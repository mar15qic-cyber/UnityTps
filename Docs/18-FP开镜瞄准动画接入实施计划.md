## 1. 执行摘要（审计结论）

**现状**：右键瞄准 = `PlayerAimState.Ads01` → `FPCameraRig` FOV 插值（60→AdsFov）+ `FPWeaponMotion.TryComputeAimPose()` 程序化平移 viewmodel 使 SightReference 对准视口中心线。**不播放任何瞄准动画**。数值侧 ADS（散布收窄 `BaseAdsSpread`、后坐倍率 `AdsRecoilMultiplier`）已完备——即"数值有开镜收益、视觉无开镜动作"。

**素材事实**：LPFP 每个武器族手臂 FBX 自带完整 ADS 动画集且**全部闲置**：

| clip 族 | 时长 | 用途 |
|---|---|---|
| `aim_in@<weapon>` | 0.30s | 开镜过渡（举枪贴腮） |
| `aim_out@<weapon>` | 0.37s | 收镜过渡 |
| `aim_fire@<weapon>` | 0.17~1.43s | ADS 状态开火（Sniper_01 为 1.43s 重后坐版） |
| `aim_fire_pose@<weapon>` | 0.03s | ADS 持枪静态姿势（保持态） |
| `aim_*_scope_01~04@<weapon>` | 同上 | 4 种瞄具变体（Docs/15 配件系统消费） |

覆盖全部 19 个武器族；手枪族仅 scope_02/03 变体。FBX 路径：`Assets/Low Poly FPS Pack/Components/Meshes/Arms/<Family>/arms_<family>.fbx`。

**缺口（3 处）**：
1. `WeaponAnimationSet` 无 aim 字段（只有 Idle/Fire/Reload×2/Draw/Holster/DryFire）；
2. `FPWeaponAnimator` 无瞄准状态机（只订阅开火/换弹/切枪事件）；
3. `WeaponDefinition` 资产未引用任何 aim clip。

## 2. 现有链路与写者边界（不可破坏的既有决策）

```
InputReader.AimHeld（-300）
  → PlayerAimState.Update（-80，Gameplay 侧唯一 ADS 真相）
      Ads01 ∈ [0,1]，0.16s MoveTowards；换弹/切枪占用动作槽时强制收镜
  → 消费者（全部只读）：
      FPCameraRig（-40）…… FOV 插值
      FPWeaponMotion（20）…… sway/bob 阻尼、后坐独立保持系数、程序化 ADS 姿态
      CrosshairPresenter …… Ads01≥0.5 隐藏准心（已存在）
      WeaponAccuracyState / WeaponRecoilState …… 数值侧（已存在，不动）
  → FPWeaponAnimator（view prefab 根，Animancer）…… 【本轮新增】aim clip 播放
```

**关键既有决策（Docs/13 §5.3-6）**：ADS 状态属于玩家而非武器，`PlayerAimState` 是全工程唯一混合状态源，切枪不重建。本轮**不改**该权威，动画层只读 `Ads01` 与 `AimHeld` 意图。

**写者分层（本轮继承）**：
- `FPWeaponMotion` 写 viewmodel 根 Transform 本地位置/旋转（viewmodel 之外不碰）；
- aim 动画驱动 Armature 内部 30 骨骼 + weapon/mag/slider/knife 节点（FBX 曲线固有）；
- 两者叠加正交——**动画接管 ADS 姿态时，FPWeaponMotion 的程序化 ADS 平移必须让位**（否则双重位移，枪飞出屏幕）。这是本轮唯一的架构级改点。

## 4. 目标架构（本轮定稿）

### 4.1 数据层：WeaponAnimationSet 扩展

```csharp
public struct WeaponAnimationSet
{
    // 既有 7 字段不动 …
    public AnimationClip AimIn;      // 开镜过渡（一次性）
    public AnimationClip AimOut;     // 收镜过渡（一次性）
    public AnimationClip AimFire;    // ADS 开火（一次性）
    public AnimationClip AimIdle;    // ADS 保持姿势（循环/定格）
}
```

`HasAimClips()` 判定 = `AimIn != null && AimOut != null`（AimFire/AimIdle 缺省时回退：AimFire→AimIn 末帧姿态、AimIdle→AimIn 末帧定格，见 §4.2）。**未配置 aim clip 的武器（LPW 量产枪、其余 Day3 枪）自动保持现有程序化 ADS——零回归风险是本设计的核心约束。**

### 4.2 表现层：FPAimAnimStateMachine（纯 C#，可 EditMode 测试）

状态机是"决策"，FPWeaponAnimator 是"执行"。决策纯逻辑与 Unity 对象解耦，EditMode 直接锁定语义。

**状态**：`Hip`（腰射基线）/ `AimIn`（开镜过渡中）/ `Aim`（保持）/ `AimFire`（ADS 开火中）/ `AimOut`（收镜过渡中）。

**输入**（每帧由 FPWeaponAnimator 采样）：
- `AimHeld`（InputReader 意图）
- `Ads01`（PlayerAimState 混合值）
- `ActionBusy`（ActionSystem.IsBusy——换弹/切枪互斥）
- `ShotFiredThisFrame` / `DryFiredThisFrame`（WeaponController 事件）
- `HolsterRequested`（切枪收枪）

**输出指令**（FPWeaponAnimator 映射到 Animancer）：

| 指令 | 动作 |
|---|---|
| `PlayAimIn` | `Play(AimIn, fade≈0.08, FromStart)`，播速适配 adsTransitionSeconds |
| `PlayAimOut` | `Play(AimOut, fade≈0.08)` 从当前姿态淡出 |
| `PlayAimIdle` | `Play(AimIdle, fade≈0.05)` 循环保持 |
| `PlayAimFire` | `Play(AimFire, fireFade, FromStart)`，OnEnd→回 AimIdle |
| `None` | 无操作 |

**转移规则**（语义由 EditMode 测试锁死）：
1. `Hip + AimHeld + !Busy` → `PlayAimIn` →（AimIn 播完 或 Ads01≥0.95）→ `PlayAimIdle`；
2. `Aim/AimIn/AimFire + !AimHeld` → `PlayAimOut`；`AimOut` 播完 → 回 Hip（Idle）；
3. `Aim/AimFire` 状态开火 → `PlayAimFire`；腰射开火走既有 Fire 通道（Hip 态不受影响）；
4. `任何 Aim 态 + ActionBusy` → 立即让位：停 aim 播放、回到 Hip（换弹/切枪动画接管姿态）；
5. 快速点按 RMB（AimIn 未完就松开）→ 直接 `PlayAimOut`（AimOut 起始姿态≈AimIn 末帧，Animancer 淡入衔接，不跳变）；
6. `AimIn` 中开火 → Ads01<0.5 视同腰射（播 Fire），≥0.5 播 `PlayAimFire`（半开镜射击合法）。

**过渡时长对齐**：`aim_in` clip 0.30s vs `PlayerAimState.adsTransitionSeconds=0.16s`。采用**播速适配**（复用既有 `ReloadAnimationTiming.GetPlaybackSpeed` 模式）：`speed = clip.length / adsTransitionSeconds`，FOV 收敛与举枪动作同窗完成，无"镜头先到、枪慢半拍"的割裂。`aim_out`（0.37s）同理适配收镜窗。

### 4.3 表现层：FPWeaponMotion 双轨切换

- 激活武器 `HasAimClips()==true` → 程序化 ADS 平移禁用（`basePos = Vector3.zero`），动画 owns 姿态；
- `HasAimClips()==false` → 现有 `TryComputeAimPose()` 行为不变（LPW 测试枪、未接入的 Day3 枪零回归）；
- sway/bob 阻尼（adsMotionDamping）与后坐独立保持（adsRecoilRetention）**两轨通用**——它们写在 viewmodel 根上，与动画叠加正交，手感参数不受双轨影响。

### 4.4 消费端（本轮不动，但接口预留）

- **准心**：`CrosshairPresenter` 已有 `Ads01<0.5` 隐藏逻辑——动画开镜后准心在贴腮过程中淡出，行为正确无需改。
- **scope 变体**：`FPWeaponAttachmentView` 已有 opticId（attachment.optic.rifle.01 → scope_01 等）。**Phase 3** 再按 opticId 选播 `aim_in_scope_XX` 变体；本轮 base clip 直通。
- **狙击镜 UI overlay**：Phase 3（满 Ads01 切镜内贴图，需 muzzle/镜筒遮蔽策略），属 Docs/15 范畴。
- **TP 侧**：TPAimDriver 程序化 spine 俯仰已存在；TP aim 姿态动画（远端玩家）属 Phase 4 联网范畴。

## 7. 实机验收清单（用户执行）

场景 `Arena.unity`，切到槽位 3（Day 3 Rifle 02）：

1. **开镜过渡**：按住右键——枪举到眼前（aim_in 0.30s 适配 0.16s 窗）、贴腮姿势、FOV 同步收窄；准心在 Ads01≥0.5 时消失；
2. **机瞄对位**：满 ADS 时枪身竖直居中，机械瞄具（准星/照门）对准屏幕中心，无左右偏移；
3. **ADS 射击**：开火播放 aim_fire（非腰射 Fire），连射时枪口不飘出机瞄线；命中弹着点与机瞄指向一致（散布=BaseAdsSpread）；
4. **收镜**：松开右键 aim_out 平滑回落腰射姿态；
5. **互斥**：ADS 中按 R 换弹——强制收镜、换弹动画接管；换弹完成按住右键重新开镜；
6. **互斥**：ADS 中切枪——收枪动画接管，无姿势残留；
7. **快速点按**：连点右键无姿势跳变、无卡死在贴腮态；
8. **零回归**：切到其他武器（ServicePistol/AssaultRifle 等）右键——行为与旧版完全一致（程序化平移开镜），sway/bob/后坐手感不变。

## 8. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 动画 ADS 与程序化 ADS 双重应用（枪飞出屏幕） | 高 | §4.3 双轨互斥开关 + T8 回退测试；实机清单 #2 直接暴露 |
| aim_in 播速适配后动画快放不自然（0.30→0.16s 即 1.9x） | 中 | 保留每武器可调 `adsTransitionSeconds` 上调空间（PlayerAimState 字段已存在，实机手感差时调 0.2~0.24s 再适配） |
| 腰射 Idle 与 aim 动画的根位姿差异造成淡入跳变 | 中 | Animancer fade 0.08s 覆盖；实机清单 #7 专项验收 |
| aim_fire 后坐方向与 CmFPCameraRecoil 双轨叠加过猛 | 中 | 数值侧 AdsRecoilMultiplier 已有钳制；实机清单 #3 观察，过猛只调数值不动架构 |
| LPW 枪瞄准线错位（Phase 2 已知问题） | 已知 | 不在本轮范围；Docs/15 CalibrationKey 机制处理 |
| scope_01 网格默认 inactive 但 aim 动画含 scope 骨骼曲线 | 低 | 曲线作用于既有节点，节点 inactive 只影响渲染；Phase 3 选播变体时才需关注 |

## 12. 实机审计修复：ADS 照门不在屏幕中心（2026-08-29 21:26 用户视频）

**用户实测反馈**：开镜时枪的准心/照门不在摄像机中间，体验仍是腰射感。

**根因定位（三步探针，全部引擎内实测）**：

1. **AnimationMode 采样探针**：aim 姿态下 SightReference 在 view-camera 系 (0.033, −0.054, 0.643)——照门停在中心下方 ~10%、偏右 ~6%；
2. **LPFP 原版 FPSController 解析**：`Gun Camera` 挂在 arms 根局部 **(0, 0.09, −0.18)**，与动画后 `Armature/camera` 节点位置 (0, 0.086, −0.179) 精确重合——该节点即**作者相机标记**（每族 FBX 内置、全 clip 恒定）；
3. **BakeMesh 烘焙探针**（决定性）：aim 姿态下铁瞄 mesh 前后瞄尖 root 局部 rear (0.010, **0.092**, 0.085) / front (−0.004, **0.092**, 0.507)——**恰在作者相机高度 ±7mm 且两点同高（瞄准线水平）**；idle 姿态瞄尖在 (0.11, 0.074)（腰射位）。

**结论**：LPFP aim 动画把铁瞄精确对中到 `Armature/camera` 节点。我们的 FP View Camera 在 root 局部 (−0.05, 0.08, −0.30)——**z 差 12cm、x 差 5cm**，视角未落在作者相机位，照门因此停在中心下方。另发现两个存量问题：
- **旧程序化 ADS 符号错误**：`TryComputeAimPose` 取 `+偏差` 而非 `−偏差`，武器向远离中线方向平移——Day4 以来"ADS 只是变焦"的另一半根因（该路径从未被视觉验证过）；
- **SightReference 标记偏低 6.6cm**（Day4.4 标定在膛线附近而非真实瞄准线高度 0.092）——按它对中也会偏，故本修复不依赖它。

**修复（FPWeaponMotion）**：`ComputeAimAlignmentOffset()` 每帧重算（blend>0 时）：
- **动画 ADS 武器**：root 偏移 = `相机父系位置 − Armature/camera 节点 root 局部位置`（**全 3D**，含 z）——把相机精确送到作者相机位，铁瞄按原作者设计对中、瞄具画面尺寸=设计值。测量经 `InverseTransformPoint` 抵消 root 自身变换——与本组件写入**无反馈回路**，recoil/sway 旋转效果保留（root 旋转近似恒等，误差 mm 级）；
- **程序化武器**（无 aim clip，LPW 等）：SightReference/Muzzle x/y 对中，z 不动，**符号已修正**；
- 节点缺失的动画武器回退标记对中路径。
