## 1. 执行摘要

### 1.1 可直接复用的系统（质量良好）
- **事件驱动骨架**：`WeaponController`（Gameplay 唯一写者）→ `OnShotFired/OnDryFire/OnReloadStarted/OnReloadCompleted/OnReloadInterrupted/OnWeaponEquipped/OnAmmoChanged` 事件链清晰，`WeaponRuntime`（纯 C# 弹药状态）、`ActionSystem`（动作槽计时真相）、`Arsenal`（切枪交换点）分层正确，且有 EditMode 测试覆盖（`WeaponRuntimeTests/ArsenalTests/ReloadAnimationTimingTests`）。
- **双相机结构**：Main Camera（FOV 60，cullingMask=0xFFFFFDFF，CinemachineBrain）+ FP View Camera（URP Overlay，FOV 40/prefab、Arena 场景 override 45，cullingMask=512=Layer 9，far 5/prefab、10/场景）无需改动。
- **Day4.7 Tracer 层修复（代码级，全武器生效）**：`WeaponView.BuildEffects()` 已显式把 `Runtime_Tracer` 与 `Runtime_MuzzleFlash` 灯光设为 `FirstPersonView` 层（WeaponView.cs `BuildEffects`，`LayerMask.NameToLayer("FirstPersonView")`），公共链路问题在代码侧已解决。
- **步枪（Day3_AssaultRifle / FP_Rifle_View）膛口基准**：Day4.4/4.5 已用 LPFP 原厂权威参考（Bullet Spawn Point/Muzzleflash Particles/Components 节点）完成 Muzzle 位置+膛线方向校准（静态前向 = (0,0,1)），并唯一配置了 `SightReference`。这是其余 9 把枪应复制的"标准作业程序"。
- **Animancer 动画管线**：`FPWeaponAnimator` 数据驱动播 clip，`state.Events(this)` Animancer 事件 API 可用，为换弹分阶段音效提供现成挂点（无需改 FBX）。

### 1.2 必须重构/修复的系统
- **非步枪武器 Muzzle 旋转全部错误（最严重）**：用 AssetDatabase 权威解析，10 把在役武器中 9 把的 Muzzle 静态前向偏离膛线 12.8°~82°（详见 §4 矩阵）——枪口火光粒子沿 Muzzle 本地 +Z 喷射（Day4.5 已验证此行为），即 SMG/霰弹/狙击/手枪的火光向上/向后喷。根因与 Day4.5 复盘一致：Day4.3 的"渲染掩膜极值像素法"只校准了位置、旋转未按原厂参考校准（该方法在步枪上已被证明会定错点）。
- **步枪 Muzzle 层级错误**：FP_Rifle_View 的 Muzzle/ShellPort/SightReference 及全部骨骼为 Layer 0（仅网格在 Layer 9）。`WeaponView.SpawnMuzzleFlash` 用 `SetLayerRecursive(flash, muzzle.gameObject.layer)` → 步枪火光粒子落在 Layer 0，被主相机（FOV 60）渲染：与武器（overlay FOV 40）投影错位 + 被武器遮挡，正是 Day4.7 已定性并修复于 Tracer 的同类问题。
- **后坐力双轨硬编码**：`FPWeaponMotion`（Player prefab 上单组件，全武器共用 recoilBackDistance=0.045/recoilPitchDegrees=4/f=11/ζ=0.6）与 `CmFPCameraRecoil`（Arena 场景 CM_FP_Camera 上，kickPitch=1.1/kickYaw=0.3/f=9/ζ=0.75）各自独立订阅 OnShotFired，两套互不关联的序列化参数，无每武器差异、无 ADS 倍率（相机侧完全不吃 ADS）、无累计/恢复/第一枪冲量。
- **准心/命中标记/弹药 HUD 全部挤在 `WeaponView.OnGUI()`**：OnGUI 每帧分配、无散布反馈、与武器表现组件耦合，违背目标 MVC。
- **散布静态**：`WeaponController.ApplySpread()` 只用固定 `Stat.Spread`（`UnityEngine.Random.insideUnitCircle` 均匀圆），无移动/冲刺/连射 Bloom/ADS 区分；腰射与 ADS 弹道角完全相同（AdsFov 只改 FOV）。
- **Shotgun 无多 Pellet**：`TryFire()` 单次 `combatResolver.ResolveHitscan`，shotgun.01 的 spread=3.5° 只作用于 1 条射线。
- **音频系统缺失**：无 AudioManager/AudioMixer/WeaponAudioProfile；WeaponDefinition 无音频字段；11 个 FP 视图 prefab 无 AudioSource；LPFP FBX 动画无内嵌 Animation Event（二进制扫描 9 把武器 FBX，零 EVT_/PlaySound 字符串）；`AnimEventReceiver` 白名单已定义（含 EVT_Reload_MagOut/MagIn）但无任何订阅者，也无发射源。当前唯一武器相关音频 = LPFP Impact prefab 自带命中音（ConcreteImpact/BloodImpact 内嵌 AudioSource+ImpactScript）。
- **弹壳 Prefab 与文档不符**：11 个视图 `shellCasingPrefab` 全部指向 `Small_Casing_Prefab`（guid b1995a53），而 Day4 文档 §5 声称"Shotgun=Shotgun_Shell、Sniper=Big_Casing"（实际 guid 58ad7033/7be59128 未被任何视图引用）。
- **FP_Handgun_View 为孤儿 Prefab**：无任何 WeaponDefinition 引用它（Arsenal 10 槽 = ServicePistol/AssaultRifle/Handgun02/Rifle02/Rifle03/Shotgun01/SMG01/SMG02/Sniper01/Sniper02）；且其根与 Muzzle 为 Layer 0，若被启用武器网格将不被 overlay 相机渲染。

### 1.3 最大的三个风险
1. **Muzzle 旋转校准方法论风险**：Day4.3 掩膜法已在步枪上翻车一次（定到照门线，差 76px），其余 9 把枪的位置与旋转均出自该方法。若继续用逐枪"手工补偿"而不统一改用 LPFP 原厂 FPSController 权威参考（每把枪的 Example_Prefab 均含 Bullet Spawn Point + Muzzleflash Particles + Components 节点，已逐一确认存在），修复会再次反复。
2. **后坐力改造的 Gameplay/表现边界**：当前相机后坐直接改变下一发弹道（射线取自被 CM 修正的相机中心，文档已声明为单人 V1 取舍）。重构时若把 Recoil 真相留在 Cinemachine 扩展里，将无法做 Modifier 管线与未来服务器权威；必须先把"每发后坐结果"上收到 Gameplay 层，表现层只消费。
3. **OnGUI→uGUI 迁移与音频接线的工作面**：两者都要动 11 个武器视图的公共路径与 Player prefab；若不先建立数值/事件模型（检查点 3）就开写 UI/音频，会重演"每把武器一套重复配置"的债务。

## 2. 当前事件与数据流（实测链路）

```
InputReader.Update（键盘/鼠标直采；FireHeld/FirePressed/AimHeld/ReloadPressed/SlotPressed）
  → WeaponController.Update（轮询开火意图，Runtime.Tick 冷却/换弹计时）
    → TryFire()
        ├─ WeaponRuntime.TryConsumeRound（弹药真相；空仓→OnDryFire）
        ├─ ApplySpread(ray.direction, Stat.Spread)   ←【静态散布，唯一随机点】
        ├─ CombatResolver.ResolveHitscan（相机中心射线，单发单 ray）
        └─ OnShotFired(WeaponShot{Origin,Direction,Result}) ──┬─→ WeaponView：Tracer 起点(LateUpdate 贴枪口)/火光/弹壳/命中特效/OnGUI 命中标记
                                                              ├─→ FPWeaponAnimator：播 Fire clip（Animancer）
                                                              ├─→ FPWeaponMotion：Viewmodel 后坐冲量（硬编码参数）
                                                              ├─→ CmFPCameraRecoil：相机 Pitch/Yaw 弹簧（硬编码参数，改变下一发弹道）
                                                              ├─→ TPWeaponFX：TP 枪口火光+点光（与 FP 同事件源）
                                                              └─→ TPAnimDriver：TP 上半身 Fire 动画
  Reload: InputReader.ReloadPressed → TryReload → ActionSystem.TryStart(Reload, Stat.ReloadTime)（计时真相）
        → WeaponRuntime.BeginReload → OnReloadStarted → FPWeaponAnimator（clip 播速适配 ReloadAnimationTiming，OnEnd→Idle）
        → 计时完成 OnReloadCompleted / 打断 OnReloadInterrupted（切枪可打断）
  ADS: InputReader.AimHeld + ActionSystem.IsBusy → FPCameraRig.AdsBlend(0..1, 0.16s)（唯一混合状态源）
        → 主相机 FOV 60→Stat.AdsFov（Lerp）；FPWeaponMotion 用 AdsBlend 程序化把 SightReference/Muzzle 平移到视口中心
  切枪: InputReader.SlotPressed → Arsenal.TrySelectSlot → ActionSystem(SwitchWeapon) → 交换点 EquipDefinition
        → WeaponController 重建 Runtime（弹药/冷却重置）→ OnWeaponEquipped → FPWeaponRig 切视图实例 + PlayDraw
        （注意：FPWeaponMotion/CmFPCameraRecoil 的弹簧状态不随切枪重置）
```

数据真相归属现状：弹药/冷却=WeaponRuntime✓；动作时长=ActionSystem✓；ADS 混合=FPCameraRig（表现层，合理）；**散布=静态常量✗；后坐=两套表现层组件各持参数✗（其中相机侧影响弹道却无 Gameplay 数据源）**。

## 5. 目标架构

### 5.1 分层总图（v2：新增瞄准权威层）
```
┌─ 数据层 ─────────────────────────────────────────────────┐
│ WeaponStat（扩展，IBalanceConfig/DemoBalanceConfig 链路）   │
│   = 每武器基础数值，分组嵌套（Recoil/Accuracy/Ballistic）   │
│ WeaponDefinition（表现资源身份）                            │
│   += WeaponAudioProfile 引用（按武器族共享 + 单武器覆盖）    │
└──────────────────────────────────────────────────────────┘
┌─ Modifier 层（Game.Core，新）─────────────────────────────┐

### 5.3 关键架构决策（v3）

**1. 瞄准权威与恒等约束（本架构最高规则，不可破坏）**
> 只要屏幕中心、机械瞄具或 Scope 中心代表瞄准点，最终相机的中心射线就必须与 Gameplay 权威 FireRay 是**同一条线**——方向一致 + 原点一致（v3 由"仅方向一致"升级，v2 版本只保证了方向，相机位置 Bob/Breathing 曾使两射线平行不同线）。

```
AuthoritativeAimDirection = CameraPivot.rotation × WeaponRecoilState.CurrentOffset
FireRay.Origin            = CameraPivot.position（AimOrigin，头部权威挂点 y=1.62）
FireRay.Direction         = AuthoritativeAimDirection
相机最终 Aim Rotation     = AuthoritativeAimDirection（CmFPCameraRecoil 回声同一 Offset）
```
- 不允许任何"准心与射线 ≤2.2° 偏差"类取舍（v1 曾提议，已被评审否决——腰射准心显示在中心而子弹不飞向中心、ADS 瞄具中心与弹道错位，等于把"拖尾起点错位"换成"弹着错位"）。
- 射线不再读 Main Camera 最终 Transform：`aimCamera.ViewportPointToRay` 废弃。附带修复现存缺陷——`CmFPCameraSway` 的 ±2.2° 旋转滞后今天就在污染弹道（SMG 基础 Spread 才 1.8°），以及 `CmFPCameraRecoil` `deltaTime<0` 清零会 snap 弹道。
- 相机**零位置修正**（v3：Bob/Breathing 位置通道全部迁 Viewmodel）；运行时 Main Camera 由 CinemachineBrain 硬锁至 Pivot 头位（prefab 序列化的 -0.33m 偏移被 Brain 每帧覆盖，Docs/12 §2 已确认），相机中心射线与 FireRay 同方向同原点——近墙/门框/掩体边缘专项测试见 §8。
- 恒等断言双重校验（防"方向对了、线不同"）：① `Camera.main.forward` 与 `AimDirection` 夹角 < 0.1°；② 相机位置与 `AimOrigin` 垂直于前向的偏差 < 0.01m。采样必须在 CinemachineBrain 完成本帧求值之后。

**2. 相机修正通道规则（保证恒等约束成立，v3）**
| 通道 | 内容 | 是否影响中心射线 |
|---|---|---|
| RecoilOffset 回声 | CmFPCameraRecoil 每帧读 `CurrentOffset` 写 OrientationCorrection | 是——但该值同时进 FireRay，恒等成立 |
| ~~Bob 位置~~ | 组件删除，手感迁 Viewmodel（v3） | 不再存在（位置修正曾使两射线平行不同线——近墙错位根因） |
| ~~Breathing 位置~~ | 迁 Viewmodel，组件仅剩 Roll（v3） | 不再存在 |
| Breathing Roll | Roll 旋转 | 否（绕前向轴，不改 Forward/原点） |
| ~~Sway Pitch/Yaw~~ | 组件删除，手感迁 Viewmodel | 不再存在 |
| Shake（未来） | **仅允许位置/Roll**；Pitch/Yaw Shake 要么进 Gameplay AimDirection，要么射击/ADS 期间禁用 | 按此规则保证 |

**3. 后坐力唯一真相**
- 弹簧**只存在于** `WeaponRecoilState`（Gameplay）；`CurrentOffset` 一份数据两个消费者（FireRay + 相机回声）。
- 每发只调用一次 `OnShot`，产出**一份** `ShotRecoilResult`：瞄准后坐冲量（进弹簧）、Viewmodel kick（纯视觉）、Shake 位置幅度（纯手感）三通道同源分流，结构上不可能重复计算。
- **倍率规则（v3 阻断修正 2）**：`AimRecoil`（原 CameraKick 更名）在进入弹簧前作用于冲量，**同源影响 FireRay 与相机**；相机不允许任何独立 Pitch/Yaw 后坐倍率（否则相机所见后坐 ≠ 弹道后坐，破坏恒等）。仅 ViewModelKick 与位置 Shake 允许独立表现倍率。
- `CmFPCameraRecoil` 无状态、无随机、无清理逻辑——删除后"表现层一次复位 snap 弹道"整类问题消失。

**4. Reset 语义与恢复模型（v3：两套状态明确化，防止恢复延迟作用到错误对象）**

| 触发 | 行为 |
|---|---|
| 切枪 / 死亡 / 组件禁用 | `HardReset()`（Recoil/Accuracy 全清） |
| 停火 | **不 Reset**——两套状态各自恢复（见下） |
| 换弹 | **不 Reset**——自然恢复（reload 1~2s 恰好覆盖恢复窗口） |

后坐恢复的**两套独立状态**（实现不得混淆）：
- **BurstAccumulation**（连射累计，发数等效）：停火后经 `RecoveryDelay` 门控，按 `RecoverySpeed`（发/秒）衰减至 0；
- **CurrentOffset / Velocity**（瞄准偏移弹簧）：每帧按 `SpringFrequency/SpringDamping` 积分回零，持续进行、**不受 RecoveryDelay 门控**。

**首枪判定（v3 定义，消除"距上一发超过阈值"的未定义性）**：距上一发时间 > `RecoveryDelay` → 判定新 burst（firstShot=true）。Day4 复用该字段（语义＝停火超过此时间即新 burst）；未来需分离再加 `BurstResetDelay`。

Bloom 恢复独立同构：`BloomRecoveryDelay` 门控 → `BloomRecoverySpeed`（度/秒）衰减。

**5. 每发开火五步顺序（TryFire 内固定）**
```
① 用开火前状态算本发弹道：AimOrigin/AuthoritativeAimDirection + AccuracyState.CurrentSpread(ctx, stats)
② 完成本发命中结算（含 Shotgun Pellet 循环与聚合）
③ AccuracyState.OnShot（Bloom 累计——影响下一发）
④ RecoilState.OnShot（后坐冲量——影响下一发；产出本发 ShotRecoilResult 供表现）
⑤ OnShotFired 广播（含 Recoil/Spread/Pellets 载荷）→ 全部 Presentation 消费同一份结果
```

**6. ADS 属于玩家（v2 新增）**
`PlayerAimState`（Gameplay）由 `InputReader.AimHeld && !ActionSystem.IsBusy` 推导 Ads01；`FPCameraRig` 只读它驱动 FOV；`WeaponFireContext`/准心/相机读同一份——切枪不重建 ADS 状态源，且消除 v1 计划中 WeaponController 读 `FPCameraRig.AdsBlend` 的编译级反向依赖（Game.Gameplay 不引用 Game.Presentation，asmdef 已核实）。

**7. 动画事件版本号（v2 新增）**
`FPWeaponAnimator` 每次动作（Reload/Switch）分配递增 `actionVersion`；Animancer 阶段回调触发时校验版本，不匹配即丢弃——换弹/切枪被打断后，旧 clip 的 MagIn/Bolt 事件不会误触发音频。

**8. 网络/确定性边界**：随机数收敛到 WeaponController 可播种 `System.Random`；`WeaponShot` 携带 ShotIndex+Seed；RecoilState/AccuracyState 纯 C#、签名只含数值与 dt——服务器回放 ShotIndex+Seed 即可复现。

**9. 每武器差异 100% 数据驱动**：数值进 WeaponStat（Lua 热更链路），表现资源（AudioProfile/SightRef/Prefab）进 WeaponDefinition；不新增"每武器一个脚本"。

**10. Shotgun Pellet 聚合（v2 新增）**：一次扣弹/一次火光/一次音效/一次后坐；一次生成全部 Pellet 方向（主方向=当前散布锥心，每 Pellet 独立 PelletSpread 锥）；命中结果聚合后**只广播一次** OnShotFired；`HitscanResult[]` 每次开火独立分配（上限 16，霰弹射速低，GC 可忽略；不做池化——readonly struct 内复用数组会造成订阅者读到被改写数据）。主 Result 语义：首个 Damaged 命中，否则首个 Hit，否则未命中终点（供 tracer/hitmarker/UI）。

    public float BaseAdsSpread;          // ADS 基础散布（度）            Clamp [0, BaseHipSpread]
    public float MovementSpreadMax;      // 移动额外散布上限（度）        Clamp [0, 10]
    public float SprintSpreadExtra;      // 冲刺额外散布（度）            Clamp [0, 10]
    public float ShotBloomPerShot;       // 每发 Bloom（度）              Clamp [0, 5]
    public float MaxBloom;               // Bloom 上限（度）              Clamp [0, 10]
    public float BloomRecoveryDelay;     // Bloom 恢复延迟（秒）          Clamp [0, 1]
    public float BloomRecoverySpeed;     // Bloom 衰减速率（度/秒）       Clamp [1, 60]
}
[Serializable] public struct BallisticProfileData {
    public int   PelletCount;            // 每发弹丸数（默认 1）          Clamp [1, 16]
    public float PelletSpread;           // 弹丸独立散布（度）            Clamp [0, 15]
}
```
- **迁移默认值守卫**：Unity 反序列化新增字段读到 0（而非 C# 字段初始化值）。Sanitize 将所有乘法类字段下限设为中性值 1（`FirstShotMultiplier≤1 → 1`、`AdsRecoilMultiplier≤0.1` 时若未迁移且为 0 → 0.6 默认），使旧资产零改动即得到中性/合理行为；正式迁移逐武器显式填值。
- 现有 `Spread` 字段保留兼容读入（迁移期映射到 BaseHipSpread）。
- Lua/JSON 均支持嵌套，热更链路无阻碍；分组防止未来蹲姿/空中/受伤/多 Scope 倍率字段继续平铺膨胀。

### 6.2 Modifier 合成顺序（v2：描述式，固定，写进 Resolver 并测试）
```
① 收集全部 IWeaponStatModifierSource 的 WeaponStatModifier 描述符
② 排序：(Priority, SourceId, 提交序) 稳定排序——配件(0) → 技能(10) → Buff(20)
③ 合成（对每个 StatId 独立）：
   Add 项：final = base + Σ add
   Multiply 项：final = final × Π multiply
④ 数值防护：NaN / ±Infinity → 拒绝该修饰符（日志告警）；乘法负值 → clamp 到 0
   （0 是合法值：完全消除水平后坐/散布是有效设计；防护目标是非法数与负值，不是 0）
⑤ Clamp（min/max 同 6.1）——最后一步，任何来源不得越界
```
- 移除语义：按 `SourceId` 精确剔除（卸配件 / Buff 到期 / 技能重置 → 标脏重算）。
- **重算时机**：`Initialize`/`EquipDefinition`、Modifier 集合变更（脏标记）。
- **唯一写者**：WeaponController（持有 Resolver 结果，对外只读）。

### 6.3 Spread 计算顺序（每发/每帧；输入=WeaponFireContext）
```
CurrentSpread(deg) =
    Lerp(BaseHipSpread, BaseAdsSpread, ctx.Ads01)
  + Lerp(0, MovementSpreadMax, ctx.HorizontalSpeed01)
  + (ctx.IsSprinting ? SprintSpreadExtra : 0)
  + CurrentBloom        // 连射累计（≤MaxBloom；BloomRecoveryDelay 后按 BloomRecoverySpeed 衰减）
最后 × SpreadMultiplier（Resolver 乘法项）→ Clamp [0, 45°]

单发方向：以 AuthoritativeAimDirection 为轴，可播种 Random 在锥内取点
Shotgun 多 Pellet（已拍板，随检查点 4 实现）：主方向用上式（不含 PelletSpread），
每 Pellet 再独立取 PelletSpread 锥——散布与 Pattern 互不干扰
```

### 6.4 Crosshair Gap 与真实 Spread 的映射
```
GapPx = tan(CurrentSpread) × (Screen.height / 2) / tan(主相机vFOV/2) × ConfigScale
      ≈ CurrentSpread(deg) × pxPerDeg（小角近似）；pxPerDeg = Screen.height / 主相机当前vFOV
—— 用主相机（弹着所在投影）而非 overlay 相机；ADS 时准心隐藏/切换 Scope UI，不参与映射
—— Gap 由 Presenter 读 WeaponController.CurrentSpreadDegrees 驱动，
   保证"准心间距=真实弹着环"，绝无独立 UI 动画
—— Shotgun：Gap 映射 **CurrentSpread + PelletSpread** 的合成锥（v3 修正：CurrentSpread 已含移动/冲刺/Bloom/ADS——动态项必须全部反映到霰弹准心外沿；用 BaseHipSpread 会使移动/连射时准心骗小）
Clamp：GapPx ∈ [Config.MinGap, Config.MaxGap]（防极端分辨率/数值越界）
```

### 6.5 防重复叠加的数值保证
每发开火只调用一次 `RecoilState.OnShot`；PitchKick/YawKick 冲量只进 Gameplay 弹簧一处；相机回声与 FireRay 读的是**同一个** `CurrentOffset`（恒等约束）；Viewmodel kick 与 Shake 是 ShotRecoilResult 的独立通道字段，由独立倍率控制，不存在第二处冲量或随机源。
