# PreviewV1 r1：客户端启动修复

用户报告：在主机本机启动 UnityFpsClient.exe 或开始游戏.cmd 均没有游戏窗口。

根因：打包脚本把自包含 .NET 8 启动助手的运行库复制进 Unity EXE 根目录，其中包括另一套 mscorlib.dll、System.dll 等。用户多次启动的日志均停在 `Begin MonoManager ReloadAssembly`，游戏进程随后退出。并非本机不能同时运行 DS 与客户端，也不是 5080 端口冲突复发。

修复：把 464 个启动助手文件移入 Client/Launcher；助手从父目录读取游戏配置并启动游戏，开始游戏.cmd 改为 Launcher/StartGame.exe。更新两处发布脚本、EXE 变体包装入口，并加入禁止运行库混入 Unity 根目录的检查。Unity 客户端/服务端二进制、协议、热更地图均未改动，无需重建 Unity 或重启主机。

已修复目录：

- Builds/PrivateInvitations/PreviewV1/Client
- Builds/Distributions/PreviewV1/PreviewV1-Host-Win64/Client（用户正在使用）

验证：只启动一次修正后的客户端，PID 80760，出现 UnityFps 窗口且 Responding=true。日志记录程序集载入成功、APP_PROTOCOL fps-net-v23、客户端 buildId b43e257358cb、热更版本 16 应用成功。未自动登录、创建房间、开始比赛或进行联机回归。窗口留给用户操作。

启动记录：Logs/PreviewV1/startup-r1-process.json；运行日志位于该记录指定的用户本地目录。迁移清单：Logs/PreviewV1/launcher-relocation-r1.json。

## 本机单人客户端＋服务端

1. 保持已启动的 PreviewV1 主机与 ZeroTier 运行。
2. 打开主机目录 Client/开始游戏.cmd，登录自己的账号。
3. 创建房间、选择地图与模式，然后开始。当前 RoomService.TryStartOnceAsync 明确允许房主单人开始；无需第二个客户端，也无需运行 Unity 编辑器。

以上单人开局规则经过代码确认，本次未代用户实际开局。
