## 方法、数值及覆盖限制

单机运行独立 API、一个专用服务器、两个客户端，使用端口 5180/5181/27770 和临时数据库，与旧主机隔离。测试副本覆盖正式构建的业务程序集和资源后，额外加入本地观测程序集及加载条目。identity.json 保存正式与测试副本业务程序集身份一致的证据。

74 个命名用例均已执行：16 把枪腰射/ADS 共 32 项、13 把适用枪消音器腰射/ADS 共 26 项、16 项投掷。装备通过明确记录的夹具切换；射击走现有输入/预测/RPC，投掷走现有选中/投掷入口。

保留 7169 个渲染样本，其中 1363 个含活动曳光；271 张 PNG 包含准备阶段截图。数值检查 73/74，**不等于视觉通过**。射击阶段枪口几何最大偏差约 0.00603 mm、曳光投影最大偏差约 0.008423 px，但黄色特效截图仍不对齐，不能用这些指标替代视觉验收。投掷时隐藏枪械的几何偏差不计为射击偏差。

限制及异常：

- 14 个名为 bare 的用例实际继承外观附件：handgun02、handgun04、rifle03、smg01、smg02、smg03、smg05 各自腰射/ADS。因此不能宣称 16 把枪所有裸枪和消音器场景均已充分验收。
- sniper02-throw 未捕获 Selected/ready 阶段；前一个投掷用例发生玩家死亡，后续存在复活/状态切换影响。这是覆盖缺口，不能直接判定为新的玩法缺陷。
- 494 次预测射击、494 条确认；服务器接受 492 次，另 2 次为 InputTimeout 拒绝（shotId 65、96）。具体原因未确证。
- 驱动命令错误为 0；两客户端各有一条准备阶段自动流程失败的 runtime-error，保留完整原日志。
- 本轮属于同机双客户端测试，不代表朋友异地网络质量，也未覆盖全部地图。

## 准备与收尾

输入保护两次中止构建准备：首次 Unity 构建期间输入变化；第二次测试观测源码变化。冻结输入后最终四项构建均成功，正式双端摘要一致。早期中止诊断并非最终构建失败。

运行准备首次错误地使用 KillRace 15 分钟参数，规则校验拒绝。随后临时 API 建房未接入真实主机，加入返回 ROOM_STARTING，该未游玩房间自然过期。Windows 防火墙弹窗由用户手动放行。随后通过正常客户端 UI 创建 10 分钟、20 击杀、最多 8 人的夜战房间并开局。等待超时后仅继续未执行的检查，没有重启游戏进程或重跑已完成用例。启动脚本时间默认值现更正为 10 分钟，仅为后续复现保留，本轮没有重新执行。

74 项结束后，两个测试客户端、测试专用服务器、测试 API 均已退出，详见 stopped.json。旧 r1 主机保留运行。本轮没有 git 提交。
