# 地图热更修复与发布说明

## 原因与修复

旧客户端只有地图下载成功后才拉取 `/api/maps`，而本地包没有 `client-environment.json`，下载器直接返回失败；独立目录刷新方法没有调用方。夜战出现在兜底列表中，但建房因目录缓存为空而报版本未发布。

本轮将目录刷新与地图下载分开：大厅/房间浏览页定期拉取目录，建房前再次请求，目录失败显示连接错误；本地环境使用默认热更地址，保留 release/protocol 校验。页面销毁、账号变化和异步建房期间不得写入过期目录或启动下载。

后台刷新与建房共享同一个正在执行的目录请求，避免触发 ApiClient 的重复操作限制。自动测试驱动增加 `-itMap` 参数，等待大厅初始化与地图更新结束，并记录建房返回结果；原驱动只等到 Presenter 创建就触发请求，首轮未形成房间，该轮不能计入成功验证。

本地热更端补齐地图专用清单，沿用已验证的 v9 地图文件和 v23 协议；不修改现有 Lua、地图内容。下载验证通过正常安装事务创建地图专用缓存，保留原有 Lua 缓存。发布脚本以后自动生成普通清单与地图清单，地图清单仅收录 bundle。启动器优先读取地图专用清单并校验 DS 协议；仅旧部署缺失专用清单时回退普通清单。

## 本地发布步骤

1. 保存地图场景。Unity 菜单 `Tools/HotUpdate/Build Map Bundles` 生成 `Logs/HotUpdate/bundles/maps/*.bundle`。
2. 构建包含同一份场景的 Dedicated Server。若改变 C# / 协议，需要配套发布客户端，不能只换地图包。
3. 等受影响地图没有玩家，停止旧地图 DS。首次生成时在项目根目录执行 `./Tools/HotUpdate/Publish-HotUpdate.ps1 -Version <新整数版本> -Deploy`，脚本生成包并部署到 `fps-backend/src/UnityFps.Api/hotupdate/`。不得覆盖旧版本目录。
4. 若需要先审阅产物，可省略 `-Deploy`，检查 `Logs/HotUpdate/releases/<版本>/` 下的版本目录、`manifest.json`、`maps-manifest.json`。之后手动将版本目录完整复制到服务目录，最后提升两个清单；不要再次用同版本调用生成脚本，它会拒绝重复 staging。
5. 用配套 DS 构建运行 `./Tools/Server/Start-LocalServer.ps1 -AllMaps`。启动器验证包哈希并更新 `Tools/Server/.runtime/maps.json` 和 DS 环境变量；如果其他实例过期，应先排空对应实例后重新启动。
6. 确认两个清单 HTTP 200、`/api/maps` 哈希与 DS 一致，再在大厅等待地图更新并创建房间实测。只下载成功不代表入场链路通过。

自动版本号取两份线上清单和现有 staging 目录的最大版本加一，避免撞上已经生成但未部署的包。回滚必须把旧内容发成更高版本。

发布工具会拒绝向仍运行旧内容的本地地图 DS 直接推送不同 bundle。地图没有变化、只是修复发布元数据时，可显式传 `-BundleSourcePath` 指向已验证旧版本的 `maps` 目录。不要把遗留的构建临时目录当作当前线上地图。

私人测试主机仍使用 `PrivateMapBuild` + `Tools/PrivateTest/Publish-PrivateMap.ps1`，不要混用本地目标目录。
