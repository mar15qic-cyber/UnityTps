# 本机 ZeroTier 邀请测试

## 玩家

只发 `InvitationClient.zip`，不要发主机发布目录。解压后双击“开始游戏”。首次按提示安装 ZeroTier，允许加入网络的管理员操作，将助手显示的设备编号发给主机批准，再输入分配的游戏账号。后续正常启动不需要管理员权限；记住登录状态只保存当前 Windows 用户加密保护的令牌，过期仍需重新登录。

已配置网络 `743993800fd77ce1`，主机 `10.16.41.231`，网段 `10.16.41.0/24`。不要把阿里云 IP 填入本方案。你需要在 ZeroTier Central 确认私有网络、设备额度及成员授权；不要把管理 API 令牌发给玩家。网络规则应只允许玩家到主机 TCP 5081、UDP 7770–7775，拒绝成员相互访问和其他主机服务。

## 主机

双击 `Tools/PrivateTest/HostConsole.cmd`，点击首次配置。填写 MySQL 连接字符串及发布目录；凭据存放在主机私有 `.runtime` 目录。现有 MySQL 需已经安装并运行，本工具不会自动安装或改动已有数据库配置。

API 内部入口 `127.0.0.1:5080`，玩家入口 `10.16.41.231:5081`。两者为同一发布 API 的不同 Kestrel 监听器，玩家监听器在路由前拒绝服务器实例控制面和非游戏路径；不额外依赖 IIS。DS 仅绑定组网地址。设置防火墙按钮仅添加该接口上的限定端口规则，需要一次管理员操作。

开始测试会校验发布身份、复用属于工具的进程并启动五图。现有本机双开服务器占用端口时明确失败，不会替你强杀；先结束旧测试并通过旧入口正常停服，再启动新测试。五图容量各 8，不代表本机能同时承载 40 人，本轮总人数仍为 2–8。

停止按钮先关闭新入场。有对局或连接时保持服务运行，退出后再点击完成停止。账号停用禁止后续认证，不会立即踢出已经连接的玩家。控制台须保持打开才会监督重启；自动恢复次数有限，失败需查看日志。

## 构建与发布

首次配置生成 `Tools/PrivateTest/.runtime/client-environment.json`。Unity 菜单 `Tools/Private Test/Build Configured Pair` 构建独立 DS 和私有客户端，不覆盖现有 `Builds/Server`。

重新生成热更包后运行 `Tools/PrivateTest/Publish-PrivateRelease.ps1 -EnvironmentPath <配置> -HotUpdatePath <热更包目录>`。该工具发布自带运行库的启动助手/API、验证客户端/DS 输入摘要、封装只含客户端的 ZIP；发布目录不可覆盖。地图内容与代码发布身份分开：同一 releaseId 可以发布递增的地图内容版本，代码/RPC 改动仍需整包同批更新。

## 新增地图

场景由项目维护者制作；本轮没有制作正式第六张地图。地图需要沿用已有网络组件与预制体、PlayerSpawner 及有效出生点，出生点须支持当前按位置划分队伍的机制。

创建 JSON 请求，字段 `mapId`、`displayName`、`scenePath`、`version`；调用 Unity 编辑器 `Game.EditorTools.PrivateMapBuild.Build(请求路径)`。工具输出 `Builds/PrivateMaps/<mapId>/<version>/` 下的 Bundle 和独立 DS。版本必须高于已发布地图内容版本。新增 C#、网络资源注册或程序集变化不能当作地图资源热更，发布工具会比较 DS 游戏程序集及协议。

执行 `Publish-PrivateMap.ps1 -ConfigPath <主机配置> -MapBuildPath <上述目录>`。默认新地图 UDP 7775；工具等 DS 新鲜 Ready 后才切换地图内容指针和目录。已有地图更新要求对应对局排空，保留旧内容，不能覆盖相同版本。失败不自动宣称发布完成；现场可能留有未启用资源或新进程，须核对日志后处理。

大厅每 30 秒检查地图资源，也可手动检查。对局中不激活，下载期间不能进入房间；地图失败保留原版本。Lua 不在大厅热重载。服务器入场校验地图内容哈希；资源准备中或版本不一致会拒绝开局/入场。

## 验证边界

自动化通过和构建成功不等于外部网络已通过。仍须两名不同网络玩家验证：首次安装/UAC、设备批准、五地图进出、热更运行中生效、真实 UDP 握手和对战。记录直连或中继；无法获知时填写未知。最终分别记录接入、体验和补偿正确性，不以 HTTP 200 代替 UDP 联机证据。
