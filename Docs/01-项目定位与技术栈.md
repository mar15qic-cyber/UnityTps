## 1. 项目定位说明

**一句话定位**：一个具备商业游戏流程感的多人 FPS Vertical Slice——证明「Client/Server 架构理解 + Gameplay 系统设计 + 数据持久化 + 热更新 + 模块化架构」，而非证明画面或内容量。

- 与第一个项目（RE4 入村 Demo）的能力互补：Demo1 证明场景/动画/整合能力；Demo2 证明网络/架构/服务端能力。
- 流程闭环：登录 → 大厅 → Loadout → 技能升级 → 进入房间 → Arena 对战 → XP 结算 → 升级 → 回大厅强化。
- **明确不做**：匹配系统、排位、大厅3D场景（纯UI大厅）、载具、移动端、语音、观战、反作弊实装、Dedicated Server 实装。

## 2. 最终技术栈选择

| 层 | 选型 | 理由 | 备选与回退 |
|---|---|---|---|
| 引擎 | Unity 6000.0.76f1 | 当前工程 | — |
| 渲染 | **URP**（Day 0 从 HDRP 模板转换） | 免费FPS资产兼容最好、迭代快、面试主流 | Built-in（更稳但表现弱） |
| 网络 | **FishNet Pro（4.x）** | 开源、源码可读（面试可深挖 tick/prediction/sync 源码级讲解）；Pro 含完整 Prediction v2 + Lag Compensation/Rollback 工具链；Server-First 设计符合教学目标 | Mirror / NGO（讲解点少）；Fusion（曲线陡+授权叙事复杂，两周风险高） |
| 热更新 | **xLua**（仅数值/公式层） | 国内主流、边界清晰、演示直观 | 若 Unity6/团结编译坑 >0.5天：降级 JSON 热载，接口边界不变（见 §12） |
| 动画播放 | **Animancer Pro**（Presentation 层，仅作播放引擎） | 代码驱动替代 AnimatorController 资产图：状态→动画映射全部显式在代码（AI 友好、可单测、无黑盒参数表）；与「AnimDriver 单写者」制度完美契合 | Animancer Lite（无渐变）；保底回退手写 Mecanim，AnimDriver 接口不变 |
| 相机 | **Cinemachine 3.x**（UPM 包） | 相机基建：FP↔死亡观战切换用 priority 机制免费获得；自定义 CinemachineComponent 承载 sway/bob/recoil（效果逻辑仍自研，可讲解） | 手写相机管理器（保底回退，FPCameraRig 接口不变） |
| 角色IK | **FinalIK** | TP 远端玩家：AimIK（躯干/枪口朝向=同步的瞄准方向）+ 双手 IK 贴武器（消除穿模）；动画播完后的姿态后处理，纯表现层 | Unity 内置 TwoBoneIK（能力弱）；无 IK（观感降级） |
| 后端 | ASP.NET Core 8 WebAPI + EF Core + Pomelo.MySql + JWT + BCrypt | 与 Unity 同语言、模板成熟、AI辅助效率高 | — |
| 数据库 | MySQL 8 + Navicat | 指定 | — |
| 输入 | **Input System（新版）**，不用 PlayerInput 组件，自写 InputReader 轮询 | 工程已含 inputactions 资产；轮询模式与 FishNet OnTick 对齐更好解释 | 卡住则回退旧 Input Manager |
| UI | uGUI + TextMeshPro（Unity6 中已并入 ugui 2.0） | 熟悉、快 | 中文需配 TMP 中文字体（落地时处理） |
| 关卡 | ProBuilder 白盒 Arena | URP 兼容好、可完全自控布局 | — |
| 版本 | Git（每模块可回滚；AI 辅助开发必须小步提交） | — | — |

**Day 0 清单**：转 URP → 建 Git 仓库 → 删模板杂物 → 导入 FishNet(Pro)/xLua/Animancer/FinalIK + UPM 安装 Cinemachine，各跑通最小示例（HelloWorld / BasicSync / Play 一个 clip / CM 相机切换 / AimIK demo）→ 确认团结引擎下编译零错误。

## 14. 插件使用原则与评估

| 插件 | 结论 | 理由 |
|---|---|---|
| **FishNet Pro** | ✅ 用 | 只用其 Transport/SyncVar/RPC/Prediction/LagComp 底层；movement/weapon/combat/同步策略全自研 |
| **xLua** | ✅ 用 | 只做数值/公式热更层 |
| **Animancer Pro** | ✅ 用（仅 Presentation 播放引擎） | 不含 gameplay 逻辑、不藏同步设计——只是把「代码驱动动画」变干净（§7 详述）。注意讲解时主动展示 AnimDriver 的状态→clip 映射代码，证明逻辑自研 |
| ProBuilder | ✅ 用 | Arena 白盒搭建（URP 兼容好） |
| FPS Framework / FPS Template（各类成品 kit） | ❌ 拒绝 | 会把 movement/weapon/combat 变黑盒——面试死亡问题「讲讲你移动系统怎么实现的」将无法回答。本项目核心卖点恰是这些系统自研 |
| **FinalIK** | ✅ 用（Presentation 姿态后处理） | AimIK 让远端玩家躯干/枪口真实朝向**服务器同步的瞄准方向**（纯动画混合做不到，这是网络状态到表现的关键一环）；双手 IK 贴武器消除穿模；只读状态、只写动画姿态，不碰 gameplay |
| **Cinemachine 3.x** | ✅ 用（相机基建） | 提供 camera rig/priority 切换（FP↔死亡观战）与 pipeline 扩展点；sway/bob/breathing/recoil/ADS 以**自定义 CinemachineComponent** 自研接入——基建用插件、效果逻辑自己写 |

**总原则**：插件提供地基（网络传输、Lua VM、动画播放、相机/姿态基建），业务层（gameplay 规则/同步策略/状态机设计）必须自研且能逐行讲解。Cinemachine/FinalIK 与 FishNet/Animancer 同属「地基」类：替换它们不动摇业务架构。
