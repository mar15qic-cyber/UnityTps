# 公网邀请测试部署与验收

目标：Windows 客户端、Windows 云 DS、2–8 位受邀玩家、全部五张地图。本文是实际操作入口，不代表公网验收已经通过。

## 1. 发布包

1. 准备真实域名、公网 IPv4、HTTPS 证书，以及云机上的 MySQL 和 .NET 8 ASP.NET Core Runtime（或 Hosting Bundle）。API/数据库/五个 DS 同机。客户端电脑无需 Unity 或 .NET SDK。
2. 复制 `Tools/Cloud/client-environment.example.json` 到私有配置目录，填入真实 HTTPS 地址、环境名及新的 `releaseId`。模板故意不能作为有效发布配置。
3. Unity 菜单 `Tools/Client/Build Invitation Client` 从进程环境变量 `FPS_RELEASE_CONFIG` 读取配置路径；也可在编辑器调用 `Game.EditorTools.InvitationClientBuild.BuildFromConfig(绝对路径)`。入口会编译 `PUBLIC_INVITE_TEST`：配置缺失时明确拒绝启动，不退回玩家自己的 localhost。
4. 构建 Windows Release DS 和 Map Bundles。客户端地图列表来自现有 Build Settings；DS 包含五张战斗地图，TrainingYard 客户端通过 bundle 获取。
5. 运行现有 `Tools/HotUpdate/Publish-HotUpdate.ps1` 准备新版本，不使用 `-Deploy` 修改本机后端。热更版本必须单调递增。
6. 执行 `Tools/Cloud/Publish-InvitationRelease.ps1 -EnvironmentPath <真实配置> -HotUpdatePath <包含manifest.json和版本目录的绝对路径>`。封装器核对协议、构建输入摘要、程序集和热更内容哈希，要求包含 TrainingYard bundle；统一写入 releaseId。产物位于 `Builds/Invitations/<releaseId>`。
7. **仅将 `InvitationClient.zip` 分发给玩家**。整个 release 目录仅供云端部署；禁止分发 API、服务端配置或密钥。

开发者可先用 `Tools/Public Test/Build Local Validation Pair` 构建本机回归用的 Client/DS/bundle；本机客户端不等于邀请测试包。该入口保存并恢复构建前 ProjectSettings 文件内容。

## 2. 云主机配置

- 复制 `cloud-config.example.json` 和 `cloud-secrets.example.json` 至云机私有运维目录，分别填入路径、公告地址和随机密钥。JWT 与 DS 控制密钥各自使用至少 32 字节随机材料；密码文件仅授权部署管理员及运行服务账号读取。
- `apiListenUrl` 固定为 loopback HTTP；`dsBindAddress` 是云机监听地址，默认 `0.0.0.0`；`publicAddress` 是告知玩家连接的公网 IPv4 或 DNS，二者不能混用。
- IIS 安装 URL Rewrite 与 ARR，开启 reverse proxy，为站点绑定有效 HTTPS 证书，参考 `iis-web.config.example`。API 内部端口改动时同步修改 rewrite 地址。IIS 站点根不应指向整个 release 目录。
- 云安全组及 Windows 防火墙仅开放 TCP 443、UDP 7770–7774 给测试玩家。MySQL、API 5080 不开放公网；RDP 仅允许管理员来源。公网 `/api/server-instances` 必须返回 404，内部请求仍需服务器密钥。
- API 只信任 loopback 代理的 forwarded headers。ARR 应正确追加客户端地址，不允许用用户输入覆盖可信代理链。
- `Start-CloudServer.ps1 -ConfigPath <配置> -CheckOnly` 只验证文件、配置、哈希及端口所有权，不启动进程、不创建状态。退出成功**不代表 UDP 可达**。
- `Start-CloudServer.ps1 -ConfigPath <配置>` 启动发布版 API 和五个 DS，等待真实数据库健康与新鲜地图注册。密钥通过子进程环境传递，不写在启动参数中。失败时保留已启动进程记录，供重试或定向停止。
- `Test-CloudReadiness.ps1 -ConfigPath <配置>` 要求五个实例均 Ready；运行中的对局可用 `-AllowActive` 做运维检查。实例地址、端口、地图、协议和发布编号均需匹配。
- `Install-CloudTask.ps1` 创建专用账号运行的开机任务，安装后不会自动启动。核对目录权限后启动任务；监督器只重启丢失的托管进程，不冒用或停止外来进程。

端口与地图：Arena=7770，Stackyard=7771，Depot55=7772，Ridgeline=7773，TrainingYard=7774。单图容量 8；首轮总人数控制在 8 人以内，尚无五图同时满载的容量结论。

## 3. 账号、维护与回退

- `Set-InviteAccount.ps1 -ConfigPath <配置> -Action create -Username <账号>` 在交互输入框读取密码，离线创建账号；`-Action disable` 停用账号并使已有 JWT 失效。邀请码模式下公网注册返回 `INVITE_ONLY`。
- 停用会阻止后续登录、认证 API 与入场票据消费；已建立的 DS 连接不在此命令中强制踢除，需要结束对局或使用既有断开机制。
- 登录限流每来源地址每分钟 10 次；认证 API 每账号每分钟 1200 次，覆盖大厅轮询。可信代理配置错误会把所有玩家算成同一来源，必须在外部测试中检查。
- 升级前先停止监督任务，再运行 `Stop-CloudServer.ps1 -ConfigPath <配置>`。它仅写维护标记，拒绝新建房、加入和开局，现有对局继续。确认无人后加 `-StopProcesses` 停止记录中路径及启动时间匹配的进程。
- `Backup-CloudDatabase.ps1` 用私有 MySQL defaults 文件执行一致性备份。部署前检查备份退出状态；备份属于敏感数据，不能放到 IIS 公开目录。
- 本轮增加 `UserAccount.Disabled` 数据库列；迁移由 API 启动应用。回退程序版本时保留该兼容新增列，不自动执行破坏性 down migration。
- 回退到上一份完整 Client/DS/热更 release，更新云配置并重新运行预检查。已安装新热更的客户端拒绝降版本，因此旧内容必须以**更高热更版本**重新封装成新的 releaseId，并发放与之匹配的客户端。
- 恢复接入需要明确删除私有运行目录内 `admissions.paused` 文件，然后重新启动监督任务。启动脚本不会擅自移除维护标记。
- 每次进程启动单独生成日志目录。`Archive-CloudLogs.ps1` 只压缩不再被活进程占用的目录，保留原文件；JSONL 诊断按 64MiB 分段。运维按磁盘预算归档，删除前确认不属于当前对局。

## 4. 网络语义与取证

- 协议升级为 `fps-net-v8`：观察者位姿增加服务器时间戳/生命代际；射击携带 shotId、输入 tick、生命代际和显示时间。
- 输入仍使用可靠 RPC。服务器保存已模拟输入对应的权威瞄准射线；请求先进入最多 32 项的顺序队列，输入尚未消费时最多等待 200ms。输入过期、缺失、代际错误、未来显示时间与超窗请求均拒绝并回送弹药确认。
- 目标 hitbox 在 OnPostTick、全部移动之后采样。插值只使用同生命代际历史；不使用历史保留余量扩大补偿上限。缺历史的目标在查询期暂不参与碰撞，随后恢复；异常路径同样恢复现场。
- 观察者以统一单调服务器时间轴渲染；静止快照照常更新时间。缓冲自适应范围本轮收窄为 **50–150ms**，避免原 250ms 插值本身就超过 200ms 补偿窗口。实际 RTT、缓冲与输入等待仍可能共同超窗，届时明确拒绝，不能宣称任意高延迟下都能补偿。
- `-disableLagCompensation` 用于服务器 A/B 对比，仍保留时间及输入准入检查。默认启用补偿。
- 客户端/DS 加 `-publicTestTelemetry -testRunId <本轮编号>` 开启结构化取证；日志写在该进程 `Application.persistentDataPath/PublicTestEvidence` 下。云启动器默认开启 DS 取证。
- 记录关联键是 releaseId、matchId、connection、shotId；sessionId 区分进程，runId 标识测试轮次。server-tick-total 记录 OnPreTick 至回溯/开火处理结束耗时，不包含随后所有框架发包开销；CPU 压测还需结合 Unity Profiler。
- `Export-PlayerEvidence.ps1` 只导出固定字段 JSONL，拒绝将 Player.log、API 日志或任意文件夹打成玩家回传证据。截图/录像由测试者另行提供。
- `python Tools/Network/summarize_evidence.py <一个或多个jsonl> --output <summary.json>` 汇总位置误差、纠正分类、RTT 与服务器耗时。短于 10 分钟或样本不足只标记证据不足；指标通过也不会自动把真实公网体验标记为通过。

## 5. 公网验收

至少两名玩家位于不同外部网络、使用不同电脑。每图完成 10 次入场，以及不少于 20 分钟的完整对战；再做 8 人轮次。录下地图、账号代号、网络类型、实际 RTT、配置、build/releaseId 和开始结束时间。云上不能用“API /health 200”代替真实游戏 UDP 握手。

| 档位 | 设置与观察 |
|---|---|
| 原生公网 | 不注入，记录真实 RTT、抖动、帧耗时 |
| 正常 A | 总 RTT 约 80ms，抖动约 10ms，1% 丢包 |
| 正常 B | 总 RTT 约 150ms，抖动约 20ms，1% 丢包 |
| 压力 | 总 RTT 约 250ms、抖动约 40ms、3% 丢包；另加乱序 |
| 恢复 | 短时断流、恢复、强退后再次入场 |

`Tools/Network/netem_gateway.py` 在独立双网卡 Linux 测试网关上默认只打印命令，加 `--apply` 才修改 qdisc。参数 delay 是**每方向额外延迟**，总 RTT≈原生 RTT+两方向附加值。只匹配游戏 UDP 7770–7774；`--clear --apply` 仅删除本工具的 71: qdisc。不要把脚本运行在唯一远程管理链路上。

每轮重复横移、急停、出入掩体、移动开火、重生和贴身交错。受控命中测试关闭散布并预先定义轨迹/射击时刻，分别验证应该命中及应该未命中。关闭散布属于测试场景配置，不改正式武器默认数值。

通过线：正常档位无意外掉线、重复伤害、结算不一致；扣除首次对位和重生后，每玩家每 10 分钟异常硬纠正≤1，配对位置误差 P95≤0.10m；录像无持续回拉。窗口内命中符合历史几何，窗口外不额外补偿。压力档位队列有界、权威一致，恢复后 5 秒内恢复推进或明确退出且能重新入场。

**每轮分别填写接入、体验、补偿正确性三列；未执行就是未验证。** 配置、EditMode 单测、合成弱网及本机双开不能替代外部玩家证据。
