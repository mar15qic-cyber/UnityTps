# 05 瞄具挂载贴合与眼点校准（2026-09-21/22）

## 现象
- codex 中断的"眼点修复+LPW 瞄具移除"工作交接时：**192/192 运行时证据全 FAIL**（"FP camera/window unavailable"），文档与资产不一致，自有契约测试 2 红，另覆盖掉了本会话 4 把 TP 手枪的根姿态校准。
- 修复 harness 后首次全量捕获暴露真问题：13 把武器挂点与导轨存在间隙/嵌入——悬浮 0.8~46mm（AK 悬浮 4.1cm）、嵌入 2~243mm（KSG 整个瞄具埋进枪身 24cm，P90 埋 5.6cm）。

## 证据
- 静态探针（InstantiatePrefab + SMR.BakeMesh + socket.InverseTransformPoint）：8 个代表组合 7 个 ≤1.4mm，SCAR FP -7.1mm（镜底=挂点面 0.0000 精确，但导轨顶在 -0.007114）。
- 运行时 harness（真实 Arena 玩家 + DebugAdsOverride）：railGap=镜底-导轨顶逐项实测，与静态值逐位一致（SCAR 7.1mm / AK 41.1mm / SMG05 -242.7mm）；156 条记录带 PNG+contact sheet+manifest。

## 根因
1. **"arm" 子串误杀**：排除规则沿父链上溯，`"arms"`/`"Armature"` 节点含子串 `arm` → LPFP FP 视图的整条骨骼下（含枪体）全部被排除 → 测量恒空。codex 在 EditMode 测试和运行时 harness 两处复制了同一个 bug（修复前先修判断——这次先修 harness 才看见真数据）。
2. **挂点标定系统性偏差**：codex 的 socket 构建器宣称"挂点=导轨设计面"但仅 4/13 把枪达标；SMG 族 5 把挂点 y 全部相同（0.0883）= 用了统一值而非逐枪实测；SMG05 FP 挂点为负 y（-0.0986）深埋枪身。
3. **并行工作区覆盖**：prefab 构建工具用旧态内容回写 → 只活在脏区（未提交）的 TP 手枪校准被覆盖回 HEAD；对方的审计文档误报"无根姿态改动"（对比基线选错）。
4. **证据链方向反了**：先堆数据矩阵最后搭取证 harness，harness 一跑全 FAIL 导致运行时正确性从未被证明；文档手填表格，资产一变就过期。

## 修复
- 排除规则只按渲染器自身节点名（scope/iron/sight/bullet/silencer/knife/slider/mag/grip/bipod/arms），两处（测试+harness）同改。
- 新增一次性校准器 `OpticSocketRailContactCalibrator`：以 BakeMesh 顶点实测导轨顶在挂点局部系 Y，挂点沿自身 +Y 平移该值 → 26 个挂点（13 FP+13 TP）间隙=0。**关键性质**：挂载行 delta 与眼点行全是挂点局部系数据 → 随挂点整体平移保持有效，C2 眼点矩阵零改动。
- 用户拍板"全部按实测校准"（曾就 SCAR 7.1mm 单独征求意见——已验收锚点的姿态改动必须先给用户看）。
- 文档改由生成器从资产导出（`OpticMatrixDocGenerator`），禁止手填。

## 验证
- 156/156 PASS：满 ADS 窗口中心 (0.5000,0.5003)、高 0.1200/0.12 精确；52 组合 hipfire 最大 |railGap|=2.5μm；mountBaseGap=0。
- EditMode 1082/1082 全绿（含修复的 4 个手枪姿态旧测试——9/18 步枪基准锁被 9/21 @handgun 标定取代，旧测试前提被推翻要改锁而不是绕）。
- 后端真库：退役瞄具 0 行、瞄具兼容=四款×13=52、狙击 0；迁移 20260921090000 手工应用（dotnet-ef 设计时连接串解析失败 → 按仓库 SOP 手工 SQL+登记历史行）。
- 双端重建：protocol 不变 fps-net-v7、inputDigest 相同、5 DS 注册。

## 教训
1. **连续量测量先修排除规则**：任何"找不到顶点/找不到相机"的测量失败，先怀疑过滤条件，再怀疑被测对象。子串匹配节点名时，父链上溯是最危险的写法。
2. **局部系数据是免费保险**：挂点局部系的挂载/眼点数据让"挂点整体平移"成为零成本操作——设计数据管线时优先把组合相关量放在会动的锚点局部系。
3. **未提交的工作区不是安全区**：构建工具回写 prefab 前必须 diff 目标文件 vs HEAD 并确认归属；测试常量要保存期望值（恢复数据源在测试里）。
4. **验收过的锚点不静默重写**：SCAR 7.1mm 下沉单独问用户；全量校准也先给表格再动手。
5. **运行时证据先行**：先让 harness 端到端 PASS 一小撮（4 把代表枪），再全量；文档从资产生成。

## 面试问答（可背）
- Q：瞄具怎么贴合不同枪的导轨？A：运行时以烘焙网格顶点实测导轨顶，挂点沿自身轴平移实测偏差；组合校准数据（挂载偏移/眼点/镜窗）全部定义在挂点局部系，平移挂点不动任何数据；测试锁定逐枪导轨接触≤2mm、满开镜窗口中心 0.5±1%、屏占比=标定值。
- Q：怎么证明 52 种组合的 ADS 是对的？A：自动化证据管线——真实玩家+生产 FPWeaponMotion/WeaponAttachmentView，逐组合三状态截图+数值断言（中心/高度/挂载间隙/导轨间隙），156 条机器可读 manifest 全 PASS。
- Q：多把枪共用同一套瞄具怎么避免逐枪手调？A：瞄具元数据（镜窗包围盒/眼距）实测一次 + socket 局部系换算推导逐组合行；差异来自挂点位置本身。
