# 命中判定与表现层九项复盘（2026-09-18 实机批次 + 面试素材）

> 用途：收录"侧/背射击不掉血 + 血液弹孔浮空 + 重生陷地 + 准星缺失 + 光标管理 + 聊天交互 + TP 手枪姿态 + 弹药重置 + HUD 美化"批次。格式同 01/02：现象 → 证据 → 根因 → 修复 → 验证 → 教训 + 面试问答。

## 案例 1：正面能打死人，侧面/背面经常完全不掉血（问题 6）

**现象**：双端实机，从敌人正面射击通常有伤害，绕到侧面/背后射击经常一梭子零伤害（2026-09-18 录屏 57-65s 贴背射击段）。

**证据与推理**：
- 静态链路核查：`ServerFireRequest` → `ServerLagCompensation.TryBeginRewind` → `WeaponController.TryFire` → `CombatResolver.ResolveHitscanTwoStage`（`QueryTriggerInteraction.Collide` 显式，trigger 可中）。
- **关键发现**：`BodyHitbox`（r0.35/h1.8 胶囊，trigger）挂在 **TP_Model** 下；而 DS 上所有玩家走非 Owner 分支 → `UpdateRemoteVisualSmoothing()` 用 0.05–0.25s 缓冲插值写 TP_Model 位姿（该插值 2026-09-17 为"远端丝滑"引入）。→ **DS 上 BodyHitbox 跟随的是滞后的视觉位姿，不是权威模拟根**。
- `ServerLagCompensation.Capture` 每 tick 记录的正是这个漂移位姿 → 回滚后射线打的是"过去时刻的视觉位置+插值滞后"双重偏移。
- 量化：横移目标胶囊侧向偏移最大 ≈ 0.25s × 3.4m/s ≈ **0.8m ≫ 胶囊半径 0.35m** → 侧/背射线落空；正面射击误差沿射线轴方向，被胶囊 1.8m 纵深容忍 → 打得中。与"正面中、侧背不中"的方向性完全吻合。

**根因（一句话）**：为视觉丝滑引入的缓冲插值跑在了 Dedicated Server 上——**headless 服务器不需要视觉平滑，却让命中 hitbox 继承了视觉滞后**。

**修复**：`UpdateRemoteVisualSmoothing()` 增加 DS 早分支（`IsServerInitialized && !IsClientInitialized`）→ `PinTpModelToRootForServer()`：TP_Model 每帧直接钉到 根∘作者基准，跳过缓冲插值（Host 调试宿主与纯客户端保持插值不变）。附保险：生成/重生后 `CC.Move(1mm)` 一次，让根 CharacterController 进入物理命中集（Unity CC 必须 Move() 过才参与 Raycast——静止目标若从未 Move 根 CC 不在命中列表）。

**验证**：EditMode `RemoteVisualSmoothingTests.PinTpModelToRootForServer_AlignsModelToRootBaseline`（钉根后模型=根∘基准、缓冲清空）+ 回归 54/55→12/12 全绿；实机复测 VERIFY_PENDING（判据：正/侧/背互射均掉血、`[FireGeom]` 无 GEOMETRY/NO_TARGET）。

**教训**：①**任何"表现层"优化都要问一句：它会跑在 DS 上吗？** DS 上的玩家实例既是权威模拟体又是（无头的）表现体，视觉逻辑混入会污染判定；②方向性命中缺陷先量化"误差方向 vs 胶囊几何轴向"——正面/侧面容忍度差一个数量级时，根因几乎一定是"判定体与视觉体在水平方向解耦"。

## 案例 2：血液喷溅与弹孔浮空，尸体倒地后特效留在站立位置（问题 5）

**现象**：命中敌人时血溅/弹孔不贴人，敌人倒地死亡后特效仍悬在原站立胸口高度（录屏 57-65s、2:44 与用户图二）。

**根因（一句话）**：`WeaponView.SpawnImpact` 世界坐标 `Instantiate` 且**不 parent 到命中对象**；且命中点本身取自服务器权威射线（打在案例 1 的漂移胶囊表面），与客户端视觉模型错位。

**修复**：`HitscanResult.Target`（DamageableTarget 在 TP_Model 上）非空时，特效 `Instantiate(prefab, point, rotation, parent: Target.transform)`——世界位姿保持命中点，尸体倒地/移动时特效跟随；静态场景命中（墙/地，Target 空）保持原世界坐标行为。不动网络契约（Target 已在广播载荷内）。

**验证**：EditMode `SpawnImpact_WithTarget_ParentsEffectToTarget`（父级=目标视觉体、世界位置=命中点）/ `SpawnImpact_WithoutTarget_StaysWorldSpace` 全绿；实机复测 VERIFY_PENDING。

**教训**：命中表现两要素"位置源"与"挂载点"要分别审——位置来自权威判定（可能滞后于视觉），挂载决定跟随性；只修一个都会留半边症状。

## 案例 3：准星在对局中消失（问题 4）

**现象**：进对局后腰射状态屏幕中心无任何准星。

**根因（一句话）**：联网模式场景作者玩家被模式门整树禁用，`CrosshairPresenter` 在 Awake 一次性 `FindObjectOfType` 绑到禁用对象（`IsInitialized` 恒 false → 恒隐藏）；**同画布的 WeaponHudView 有 Owner 重绑机制所以弹药正常，CrosshairPresenter 没有**——两个 HUD 组件的"联网重绑"覆盖不对称。

**修复**：仿 `WeaponHudView.RebindToOwnerPlayer`：0.5s 重扫 `NetworkWeaponState.IsOwnerPlayerSafe` → `Rebind(controller, aimState, playerState)`（internal 测试接缝，开火事件精确迁移）。

**验证**：EditMode `CrosshairRebind_SwapsControllerAndShotSubscription`（换绑+订阅迁移+命中标记端到端）3/3 绿；实机复测 VERIFY_PENDING。

**教训**：同类组件的"联网适配"要做**覆盖清单**——同一画布 6 个 HUD 组件逐个核对重绑能力，而不是修一个算一个。

## 案例 4：重生弹药不重置（问题 8）

**现象**：死亡重生后，武器保持死亡前的残弹（弹匣+备弹）。

**根因**：`ServerRespawn` 只 ResetHealth + 位姿，从未碰弹药；切枪弹药缓存 `_ammoCacheByWeaponId` 还会把残弹恢复回来。

**修复**：`WeaponController.ServerResetAmmoToLoadoutDefault()`（弹匣补满+备弹回配装初始 `Stat.ReserveAmmo`+清切枪缓存+换弹/冷却复位+`OnAmmoChanged` 推送 SyncVar），`ServerRespawn` 对两槽调用。

**验证**：EditMode 3 例（补满+SyncVar 契约事件、缓存清空切回满弹、换弹中死亡复位）全绿。

## 案例 5：重生后敌人陷进地面直到移动（问题 1）

**现象**：敌人重生后腰部以下埋入地面，敌人移动后恢复（录屏 sweep_073/074）。

**排查路径**：出生点 Y（4 图 8 点全部 0.15，地面 y=0，无穿插）✓；`ApplyAuthoritativeSnapshot` CC 禁用直写 ✓；观察端 smoothing 死亡期停写/复活 snap 分支静态推演 ✓——**静态分析未定论**，活候选三个（服务器 CC 局部穿插 hold 语义保持 / 观察端 ResetDeathVisual 与 smoothing 脚本顺序竞态 / 死亡姿态写者还原不对称）。

**处置（先取证后修，按项目惯例）**：双端 `[RespawnTrace]` 结构化日志（服务器：spawnY/rootYAfter/CC 状态；观察端：重生后 3s 每 0.25s 记录 root.y/model.y/缓冲/死亡表现/Animator/CC）+ 无副作用兜底（`ObserversRespawned` → 观察端缓冲立即失效，下一帧必走对位；服务器 CC 注册 Move）。实机取证后按决策矩阵定修复（本案例待实机数据回填）。

**教训**：静态推演三个分支都"看起来对"时，不要猜——加一行能区分三者的日志打一局，比重构三遍便宜。

## 案例 6：TP 手枪竖直朝天（问题 7）

**现象**：玩家 A 手持手枪时，B 看到 A 的 TP 模型手枪竖直/错位（录屏 0-10s）。

**证据**：全部 TP 武器 prefab 的枪身结构同约定（Muzzle 在模型局部 +Z）；步枪类根旋转烘焙值统一（ euler (291.6, 354.7, 178)，实机正常）；手枪类 Handgun_01/02 烘焙成另一组值（≈90° 偏差）、Handgun_03/04 为 identity——**同一手骨系下旋转基准不一致**。

**修复**：4 把手枪 prefab 根局部位姿统一改写为步枪基准（pos (0.0087, 0.1524, 0.1093)、rot 同步枪），PrefabUtility.LoadPrefabContents → SaveAsPrefabAsset。校验：手骨系下枪口方向与步枪差 ≈13°（几何差异合理范围），场景 T-Pose 目检握持自然。

**教训**：同族资产（同挂点约定的武器族）的位姿基准要**成组校验**，单把枪"看着差不多"的烘焙值在别的枪上就是 90°。

## 案例 7：对局内 Windows 光标可见（问题 3）

**根因**：光标锁定只在 `GameplayMenuController.ApplyState()`（菜单状态迁移时）执行；**进对局的挂载路径从未调过它**——除非玩家开/关一次菜单，光标永不锁定。

**修复**：`EnforceCursorState()` 每帧兜底补锁，守卫三条：菜单可见不锁（归 ApplyState）、聊天聚焦不锁（归 ChatHudView）、状态机锁定不锁（SceneTransition/MatchEnded——结算页与场景切换窗口要自由光标）。

**教训**：状态机"迁移时执行"的副作用，必须配一个"条件满足时保持"的幂等执行者——否则所有"未经迁移的进入路径"都是漏的。

## 案例 8：聊天阴影常驻 + Enter/Esc 交互反主流（问题 2）

**现象**：左下 42%×34% 半透明面板无消息也常驻；Enter 呼出后要 Esc 关闭。

**修复**：①背景板收起态隐藏（只留纯文字消息行+8s 淡出+描边保可读性），Enter 呼出才显示；②OnSubmit 发送成功即关闭、空草稿 Enter 即关闭、Esc 取消保留草稿；③发送失败 `RestorePendingDraft` 自动重新打开（否则草稿沉在不可见输入行）；④玩家进出系统消息接入左下消息流（`MatchLifecycle.ServerNotifyPlayerJoined` 对局中补入触发 + `ServerRequestLeave` 唯一离开入口广播，幂等闸保证一次）。

**验证**：EditMode `ChatEnterInteractionTests` 4/4 + 生命周期回归 11/11 绿。

## 案例 9：底部 HUD 美化（问题 9）

**需求**：血量/备弹/武器 UI 美化，用户拍板"主流 FPS 简洁风"。

**实施**：运行时 restyle（一次改动全地图生效，不动 4+ 场景 YAML）：HP 从顶中黑底绿条移到**左下半透 chip 内大数字+细条+阈值变色**（>50 绿/26-50 琥珀/≤25 红，MatchHudView.Build 改造）；弹药/武器名升级为**运行时 TMP 簇**（右下：武器名小字 muted + 弹匣 46 号加粗/备弹 24 号 muted/换弹进度琥珀色，WeaponHudView.EnsureRuntimeCluster；场景内建旧版文本仅禁用可回退）；TMP 字体走 NotoSansSC（Resources 加载，Game.Presentation asmdef 补 Unity.TextMeshPro 引用）。

**验证**：编辑器目检场景截图两轮（修复了弹药行与武器名重叠的布局问题）+ 相关套件全绿；实机观感 VERIFY_PENDING。

## 面试问答

**Q：联机 FPS 里"打不中"怎么排查？**
A：先分三段取证：客户端有没有发出（提交日志/计数）→ 服务器有没有收到和处理（到达日志/冷却拒绝分类）→ 判定几何有没有中（逐段射线证据）。本项目有 `[FireTrace] submit/resolve` 双端关联和 `[FireGeom]` missReason 四分类（GEOMETRY/NO_TARGET/TARGET_DEAD/FRIENDLY）。本案（侧背不中）最终定位到**判定用 hitbox 在 DS 上继承了视觉插值滞后**——教训是命中判定体必须与权威模拟状态同源，任何表现层插值都不能污染判定路径。

**Q：Dedicated Server 上最容易踩的坑是什么？**
A：DS 也是玩家实例的宿主——客户端写的"表现层"代码默认会在 DS 上跑。本案两个根因都与此有关：视觉插值让服务器 hitbox 滞后（命中缺陷）、表现组件在服务器副本上抢权威写者（此前的 TP 俯仰瞬回）。纪律是：每个写 Transform 的组件都要显式声明"我在 DS 上跑不跑"。

**Q：HUD/聊天这类 UI 需求在联网项目里怎么做才不返工？**
A：两条：①场景内建对象要考虑"联网重绑"——离线场景的作者玩家对象在联网模式下被禁用，Awake 一次性绑定必然落空，每个 HUD 组件都要有 Owner 重绑；②交互闭环要测异步失败路径——"发送即关"看起来简单，但发送失败时草稿必须有地方还原（本案 RestorePendingDraft 自动重开）。

**Q：重生（respawn）要做好哪些事？**
A：四件套：位姿传送（含 NT Teleport 通知观察者）、状态复位（血量/弹药/换弹态/冷却）、判定连续性（生命代际+出生保护窗口，旧生命的回溯命中要拒绝）、表现收敛（死亡表现还原+远端视觉缓冲失效）。漏任何一项就是一个实机缺陷（本案弹药是状态复位漏项、陷地疑似表现收敛竞态）。
