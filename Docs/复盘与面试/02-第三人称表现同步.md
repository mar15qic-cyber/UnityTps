# 第三人称表现同步复盘（双端实机复盘 + 面试素材）

> 用途：收录"远端玩家第三人称表现（俯仰/姿态）"问题线。格式同 01：现象 → 证据 → 根因 → 修复 → 验证 → 教训 + 面试问答。

## 案例 1：远端玩家的抬头/低头不可见（2026-09-16）

**现象**：双端实机，从 A 的第一视角看 B 的第三人称模型，B 抬头/低头时模型完全没有变化（身体朝向 yaw 正常跟随）。

**证据与推理**：
- 数据链逐段核查全部成立：① Owner 客户端 `MovementCommand.PitchDelta` 上行；② 服务器消费时 `ApplyRemotePitch` 积分并写到服务器副本的 CameraPivot；③ `NetworkCombatAuthority.TrySyncAimPitch` 读 `WeaponController.aimPivot`（prefab 内已序列化指向 CameraPivot）写入 `_aimPitch` SyncVar；④ 观察者客户端 `HandleAimPitchChanged` 写本副本 pivot。TPAimDriver 的远端分支也已实现（读 `AimDirectionWorld`）。
- 全库 GUID 搜索（`9cbf0ecf…`）：**TPAimDriver 只挂在 Arena.unity / Arena_LPWTest.unity 的场景作者玩家上**；联网生成的 `Player_Day2_Rebuilt.prefab` 里没有该组件。
- 结论：**数据链 100% 接通，缺的是表现消费者**——离线作者玩家有组件所以本地看着正常，联网生成的远端玩家没有执行脚本，pitch 数据到了也没人用。

**根因（一句话）**：表现组件只存在于场景作者对象，没有随"联网生成 prefab"分发；**"场景里能看见"不等于"联网副本上有"**。

**修复**：把 `TPAimDriver` 直接加进 `Player_Day2_Rebuilt.prefab` 的 `TP_Model` 根（prefab 内 override，参数与场景作者实例对齐：spine 0.3/chest 0.4/neck 0.15/head 0.15、maxPitch 60、smooth 0.08）。不改网络契约，不递增 ProtocolId。死亡生命周期零改动接入（姿态写者名单按名字标记 "TPAim" 扫描，自动停用/还原）。

**验证**：EditMode 结构测试 `TPAimDriverPrefabTests`（prefab 有组件且启用、权重和≈1、Humanoid 四根骨可解析）3/3 + 死亡视觉回归 8/8；实机双端 A 看 B 俯仰（VERIFY_PENDING 移交用户）。

**教训**：
1. 排查"远端表现不生效"先做**分层归因**：数据链（输入→服务器→SyncVar→观察者）与表现链（组件存在性/启用状态）分开证；本例数据链全绿，缺的是"prefab 上有没有执行者"。
2. **场景作者对象 vs 联网生成 prefab 是两条资产路径**：离线能跑通的功能，必须确认组件/配置落在联网 prefab 上（本项目此前 A06 相机链、TP 武器挂点都踩过同族问题）。
3. 与"远端替身视觉分层"（Owner 层 LocalPlayerBody vs 远端整树改层）配合时，表现组件对 Owner 也保持启用是无害的（自己 TP 模型被层级隐藏）。

## 面试问答

**Q：你们怎么做远端玩家的瞄准俯仰同步？**
A：俯仰增量随移动输入命令上行（复用预测管线的输入批次，不单独开 RPC），服务器在消费输入时积分出权威 pitch 并广播 SyncVar；观察者端把 pitch 写回该玩家副本的 aim pivot，表现层用一个骨骼加权驱动（spine→chest→neck→head 按 0.3/0.4/0.15/0.15 分配）在动画求值后做世界空间叠加。要点是**数据与表现分离**：同步只传一个标量 pitch，骨骼解算在各端本地做，不需要逐骨骼网络同步。

**Q：遇到过"数据到了但表现没动"的问题吗？**
A：有——远端 TP 俯仰最初不可见，排查发现数据链（输入→服务器积分→SyncVar→观察者回写）每一环都成立，但执行骨骼解算的组件只挂在离线场景的作者玩家上，联网生成的玩家 prefab 里根本没有它。修复是把组件下沉到联网 prefab。这类问题的定位手法是**把"数据链"和"表现链"拆开分别取证**，以及用 GUID 全库检索确认组件的资产分布。

## 案例 2：远端 TP 俯仰"抬头后立即回正"（2026-09-17 双端实机）

**现象**：B 一直抬头，A 看到 B 的 TP 模型先抬头、随后迅速回正；低头同理。录像 `Desktop 2026.09.16 - 23.42.28.06.mp4`。

**证据与推理**：
- 数据链逐段核查全部成立（同案例 1 链路），且案例 1 已把 TPAimDriver 装进联网 prefab——症状从"完全不动"变成"动一下就弹回"，说明 pitch 数据到了但**保持不住**。
- 逐写者排查服务器副本：`PlayerNetworkAdapter.OnStartServer` 从不去激活 `localOnlyRoot`（CameraPivot）——**纯 Dedicated Server 上 `OnStartClient` 不会回调**，远端玩家的 `FPMouseLook` 一直激活；其 `_pitch` 恒 0（DS 无输入设备），**每帧 LateUpdate 把 `ApplyRemotePitch` 写入的权威俯仰清零**。
- 时序恰好解释症状：OnTick 消费输入 → 写 Euler(-30) → Update 里 `TrySyncAimPitch` 读到 -30（SyncVar 闪现一次）→ 同帧 LateUpdate FPMouseLook 写回 Euler(0) → 下一帧 SyncVar 回 0。**"先抬头（消费输入的瞬间）然后迅速回正（每帧清零）"**。

**根因（一句话）**：DS 没有本地观察者，但沿用客户端的组件激活策略——表现组件（FPMouseLook）在服务器副本上与权威写者（ApplyRemotePitch）**抢同一个 Transform**。

**修复**：`OnStartServer` 增加 `DeactivateLocalPresentationForServer()`（非本地客户端拥有时）：`localOnlyRoot` 整树失活 + `ownerOnlyComponents` 禁用。失活 Transform 的 `localRotation` 读写不受影响（ApplyRemotePitch/TrySyncAimPitch 继续工作）；Host 本人玩家由 OnStartClient Owner 分支重新激活不受影响。注意 FishNet weaver 禁止 OnStartServer 里用 `IsOwner`（FN0007），要用 `NetworkObject.Owner.IsLocalClient` 判定。

**验证**：EditMode 结构测试（去激活断言）+ 实机双端复测（VERIFY_PENDING）。

**教训**：①**Dedicated Server 也是"玩家实例的一种宿主"**——所有"表现组件只在客户端激活"的假设都要在 DS 上单独验证；②"数据保持不住"类问题找**第二个写者**，而不是怀疑同步链。

## 案例 3：远端玩家移动"一顿一顿"不丝滑（2026-09-17 双端实机）

**现象**：远端玩家从 A 走到 B，脚下移动明显掉帧/顿挫，不是丝滑滑过去。

**证据与推理**：方案A（2026-09-16）把远端根/CC 钉在**最新权威位姿**（NT 插值压到 1）以消除近距碰撞分歧——根于是以到达节奏（≈30Hz）阶梯瞬移；视觉平滑用的**指数追随**（τ=0.07s）在相邻两段样本之间"先快后慢"，宏观上把 30Hz 台阶摊成了一顿一顿的脉冲。这是算法选择问题，不是丢包/帧率问题。

**根因（一句话）**：用"指数追随"平滑"阶梯输入"永远得不到匀速视觉——台阶之间必然先冲后停。

**修复**：远端视觉改**快照缓冲插值**（`RemoteVisualInterpolationBuffer`）：根位姿只在变化时推入样本（避免渲染帧率污染到达间隔估计），渲染时刻 = now − 自适应延迟（EMA(到达间隔)×2.1，钳 [0.05, 0.25]s），在两样本间线性插值——远端模型以渲染帧率匀速移动，代价是固定 ~70ms 视觉延迟。碰撞根不动（方案A 语义不变）；死亡/瞬移/复活的直接对位语义保留。

**验证**：纯逻辑 7 例 + 组件级 5 例（丝滑性断言=渲染帧位移恒 ≤ 权威 tick 步长）全绿；实机复测 VERIFY_PENDING。

**教训**：①"平滑"要分清**误差吸收**（纠偏，用指数衰减）与**播放节奏**（表现，用缓冲插值）——前者可以失真，后者必须匀速；②把"只在变化时推入样本"做对，否则渲染帧率会污染到达间隔估计、把延迟压到下限让插值退化成原地踏步。

## 案例 4：腿部动画"翻小人书"——修好位置后还是顿（2026-09-17 双端实机）

**现象**：案例 3 修完位置后实机复测，远端移动仍然"类似翻小人书的低帧感"，不是离线模式那种丝滑。

**证据与推理（静态审计逐环取证，报告 `Docs/交接/2026-09-17-远端丝滑度静态审计.md`）**：
- 位置链自查全部健康：NT `_interval=1`（每 tick 发）+ 灵敏度 0.001 → **30Hz 稳定到达**；客户端 `Update()` 每渲染帧缓冲插值。位置已不是瓶颈。
- 腿部动画走**另一条链**：`TPAnimDriver` 每帧执行 `_walkMixer.NormalizedTime = SourceGaitPhase`，远端 `SourceGaitPhase` = `NetworkLocomotionState._gaitPhase` **SyncVar**；
- FishNet SyncVar 默认发送率 = `ServerManager._syncTypeRate = 0.1f`（全项目无覆盖）→ **广播被节流到 10Hz**；
- 致命一环：`BuildDirectionalMixer` 里 **`mixer.Speed = 0f`**——混合器自己完全不推进时间，动画相位 100% 由 10Hz 值逐帧覆写 → **腿每 100ms 跳一格**。位置再丝滑，腿还是顿。

**根因（一句话）**：连续量（步态相位）用"低频同步值逐帧覆写"驱动一个不自走的混合器——**同步频率就是动画帧率**。

**修复（方案B：渲染与同步解耦）**：服务器相位以固定速率 1/周期 推进（`RootMotionProfile.EvaluateDelta`：phaseAdvance=dt/duration，与输入无关）→ 远端**本地按同一周期常量连续积分相位**（`RemoteGaitPhase`），10Hz SyncVar 只做低频锚定（误差 ≥0.25 对位、小误差指数拉拢；速率一致时锚定不可见）；进入走/跑态瞬间对齐一次同步相位。纯逻辑测试证明：10Hz 锚定抖动下每帧相位位移 <0.02（直接覆写的台阶是 0.107）。

**验证**：EditMode 61/61（RemoteGaitPhase 8 例 + 回归）；客户端重建 buildId=85d96b5b9fec（协议不变 v4，DS 对该路径惰性未重建）；实机复测 VERIFY_PENDING。

**教训**：
1. **修好一条链不等于修好表现**——远端丝滑度要按"位置/旋转/步态相位/俯仰"四条独立链路逐条审计（本案：位置 30Hz 插值 ✓、相位 10Hz 覆写 ✗→本地积分、俯仰 10Hz+SmoothDamp 弱吸收 △）。
2. **连续量绝不直接用低频同步值逐帧覆写**：要么本地积分+低频锚定（推荐），要么同步提频（止血）。与网络位置插值的经典结论同构——"渲染与同步解耦"。
3. `mixer.Speed=0` 的设计意味着"相位由外部供给"——外部供给的频率就是动画帧率，改任何一侧时另一侧必须一起审。

## 案例 5：TP 手枪歪斜 + 左手不随武器变握点（2026-09-21 双端实机）

**现象**：①远端玩家持手枪时枪体明显歪斜（roll+上仰+悬浮）；②持不同步枪时左手姿势恒定（动画原姿"扶弹匣"），装了垂直握把也不握握把。

**证据与推理**：
- 手枪歪斜：TP 武器 prefab 以固定根位姿挂 `hand_R`，位姿对不对取决于**动画集摆出的手骨姿态**。长枪播 `@rifle` 动画集、其根位姿已长期校准正确；手枪播 `@handgun` 动画集，**手骨系不同**，但 4 把 `TP_Weapon_Handgun_0X` 根位姿被统一成了"步枪参考值"——EditMode 探针采样两个 idle clip 实测：手枪姿态下枪体悬浮拳头前上方 ~11cm/前移 15cm/带 roll 上仰。
- 左手不随武器：`TPLeftHandIK`（TwoBoneIK 解左臂到武器 LeftHandTarget 的完整实现，含换弹抑制/死亡闸门）**从未挂上正式玩家 prefab**——GUID 全库检索只命中已废弃的 Arena_LPWTest 场景（组件写在 8 月底、挂载工作从未落地到正式资产）；且握把配件无独立持握点数据，装配后 IK 目标也不会移动。

**根因（一句话）**：①武器挂点偏移只对"作者校准时的那个动画集"成立——手骨系随动画集变化，根位姿必须按动画集分别标定；②"实现了组件"≠"挂上了资产"——IK 组件长期只存在于废弃测试场景，与案例 1（TPAimDriver 只在场景作者对象）同族。

**修复**：
- 手枪位姿：EditMode 探针采样 `idle@rifle_tpc`/`idle@handgun_tpc` 烘焙骨架后读手骨世界位姿，以步枪集为基准做**传递标定**（旋转：`L_new = R_handR@hg⁻¹ × R_handR@rifle × L_rifle`，把枪的世界持枪朝向从步枪手骨系搬进手枪手骨系；位置：枪的 mag 节点=握把中段代理点，落位到拳头中心——步枪 case 实测手骨恰位于握把区，规则同构）。四把枪共用旋转 Euler(283.1,62.8,123.1)，逐枪位置差 = mag 节点差。测试 `TPGripIkTests` 锁死回归。
- 左手 IK：`TPLeftHandIK` 挂进 `Player_Day2_Rebuilt.prefab` 的 TP_Model；`TPWeaponMeshSwapper.CurrentLeftHandTarget` 改动态决策（纯函数 `ResolveLeftHandTarget`）：装配的配件克隆里带 `LeftHandGrip` 子标记 → 左手改握握把，否则回退武器 LeftHandTarget（护木/护圈）；握把配件 Mod_04.prefab 内烘焙 LeftHandGrip 标记（腕点=握把中段左侧 3.5cm，手旋转=武器系绕前向轴+90°，掌贴握把、拳道竖直）。

**验证**：四把手枪逐把截图目检 + 行走姿态复验；探针实测 IK 解算后手骨与标记重合误差 0.0001m；EditMode 9/9 + 回归 16/16；ReleaseClient 重建 BUILD_OK（协议 v7 未变，DS 无需重建）；实机双端 VERIFY_PENDING。

**教训**：
1. **"武器挂 hand_R + 固定偏移"的持有姿态是（动画集，武器）二元组的函数**——换动画集必须重标定，"统一参考值"只对同动画集成立。标定 SOP：采样目标动画集 idle 烘焙骨架 → 以已验证正确的枪做旋转传递 + "拳落握把区"位置锚定 → 截图目检循环。
2. 组件"存在但从未挂载"比"没实现"更隐蔽——**用 GUID/类名全库检索确认组件的资产分布**（本案第三次踩：TPAimDriver/A06 相机链/TPLeftHandIK 同族）；写了实现不等于完成了功能。
3. 握把类配件的自适应持握 = 数据驱动标记（配件 prefab 内 LeftHandGrip 子节点）+ 消费端纯函数决策，零新增同步、零协议影响。
