# 04 网络设计（原方案 §8 §9 §10）

## 8. Network Replication 设计（状态 vs 事件）

| 类别 | 用途 | 机制示例 | 原则 |
|---|---|---|---|
| **状态同步**（持续真值） | 位置/朝向、LocomotionState、HP、武器索引、弹药、**CurrentAction(枚举+tick)** | FishNet SyncVar / NetworkTransform | 丢失可自愈；新加入者能补齐（含动作状态） |
| **事件同步**（一次性） | 开火特效、**OnActionStart/Complete/Interrupt**、受击、死亡、飘字 | ObserversRpc（可靠） | 只发一次，不重放；事件仅触发表现，真相在状态 |
| **请求**（客户端→服务器） | FireRequest(dir, tick)、ReloadRequest、SwitchRequest、GrenadeRequest | ServerRpc | 服务器逐项验证（冷却/弹药/动作槽/存活） |

**铁律：网络上传输的永远是 Gameplay 语义（FSM 状态枚举 + Action 事件），从不传输 Animator 参数、动画名、归一化进度。每端用 AnimDriver 把语义各自翻译成本地动画。**

**开火全链路（一条主线讲清整个 C/S 设计）**：
```
本地客户端: 鼠标按下 → InputReader → WeaponController.TryFire
  → [客户端预测] 立即播 FP 开火动画/枪口特效/后坐力 (弹药显示-1)
  → ServerRpc(FireRequest, dir, tick)
服务器(Host): 验证(冷却/弹药/动作槽) → Raycast 命中 → Lua 公式算伤害
  → 扣弹药/扣目标血 → ObserversRpc(OnFireShot, hitInfo) 广播全员
  → 目标死亡则 OnDeath + 战绩累计
远端客户端: OnFireShot → TP 开火动画+弹道特效; OnReloadStart → TP 换弹动画
```
本机自己也收到 OnFireShot（去重：本机已预测过则跳过重复特效）——这个去重细节是很好的面试谈资（预测与权威结果合并的最小案例）。

## 9. 网络高级功能 A/B/C 评估

| 功能 | 建议 | 实现成本 | 面试价值 | 两周风险 | 结论 |
|---|---|---|---|---|---|
| Client Prediction | **A 第一版实现**（FishNet Pro 自带，不自研） | 中：学习 OnTick/InputData/Reconcile，基于官方 demo 改 | **高**（FPS 网络必聊） | 中 | Day 8–9 专窗；**回退线：Day 9 午未跑通官方 demo → 切 NetworkTransform**，面试照样能讲取舍 |
| Server Reconciliation | **A**（与 Prediction 绑定，Pro 自带） | 同上 | 高 | 同上 | 同上 |
| Lag Compensation | **A- 升级：低成本接入**（Pro 自带） | **低**：CombatResolver 中 `Physics.Raycast` → `LagCompensator.Raycast` 一处替换 + 配置历史缓冲 | 高（能讲 history buffer/回滚射线原理） | 低 | Day 9 若 Prediction 成则顺带接入（半小时级）；若 Prediction 回退则降回 B 仅讲解 |
| Rollback（物理回滚） | **C 放弃** | 高 | 中 | 高 | 不做；面试讲「Pro 有 rollback，Demo 场景无需要」 |
| Matchmaking | **C 放弃** | 高 | 低 | 高 | 房间码/直连 IP 加入，够用 |
| Dedicated Server | **C 放弃**（一句话说明可行） | 高 | 中 | 高 | 面试讲：FishNet 支持 headless build，当前用 Host 模式是 Demo 权衡 |
| Anti Cheat | **C 放弃** | 高 | 中 | 高 | 面试讲服务器权威已覆盖哪些验证点（§5 表B）即可 |
| Custom UDP Transport | **C 放弃** | 高 | 中 | 高 | 用默认 transport；能讲 transport 抽象即可 |

> **Pro 版带来的唯一变化是成本曲线**：Prediction 与 Lag Compensation 从「贵」变「便宜」，但**学习成本不变**——面试价值不在「你启用了 Pro 功能」，而在你能讲清 tick 制、输入回放、reconcile 快照、history buffer 原理，以及为什么 CombatResolver 单点化让 lag comp 只改一行。学习时间已排入 Day 9，并保留硬回退线。

## 10. 网络扩展设计（适度预留，禁止空接口）

| 概念 | V1 做法 | 未来扩展路径 |
|---|---|---|
| Tick System | 不自研，直接用 FishNet TimeManager 的 tick；Gameplay 输入采样对齐 OnTick | 天然支持 prediction |
| Input Command | 定义 `InputData` 结构体（moveDir、lookDelta、buttons 位域：fire/aim/reload/jump/sprint/switch1-3/grenade） | 这就是未来 prediction 的输入格式；V1 由 Locomotor 直接消费，无需第二套 |
| Player Snapshot | 不自研（FishNet 内部已有） | WeaponRuntime 字段化（弹药/冷却/动作进度皆为纯数据），面试可讲「若 reconcile 武器状态，这些字段进快照」 |
| Network Message Layer | **INetGateway 薄接口**：Gameplay 通过它发请求/收广播，实现类持有 FishNet | 这就是「自己的同步层设计」，一层接口而非空壳框架 |

**禁止事项**：不为 dedicated server 写任何现在不跑的代码；不造 5 个只有 1 个实现的接口。
