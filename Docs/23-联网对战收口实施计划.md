### 1.2 缺口清单（G1~G7，代码行级证据）

**G1 换弹/切枪无服务器验证**
全 Gameplay 仅 3 个 ServerRpc（`NetworkCombatAuthority.ServerFireRequest` L39 / `ServerRespawn` L124 / `PlayerNetworkAdapter.ServerSubmitCommand` L156）。纯客户端玩家的换弹/切枪只在本地执行（`WeaponController.Update` L193-196 读 `processLocalInput`，NetworkWeaponState 仅对**非 Owner** 置 false）：
- 服务器弹药只减不补——远端玩家打完一匣后服务器侧拒绝其后续 FireRequest，即使客户端已本地换弹；
- 服务器侧武器恒为初始枪——`NetworkWeaponState._weaponId` 只由服务器 `OnWeaponEquipped` 事件更新，而服务器控制器永远收不到远端玩家的切枪 → 他人看到旧枪 + 服务器用旧枪数值结算伤害。

**G2 瞄准同步缺口**
`MovementCommand`（MovementSimulationTypes.cs）只带 `YawDelta` 无 pitch；`FireRequest` 无方向快照（Docs/04 §8 原设计是 `ServerRpc(FireRequest, dir, tick)`）：
- 远端玩家垂直瞄准在服务器侧恒 0（服务器 aimPivot 俯仰不更新）——俯/仰射必偏；
- `TPAimDriver`（L59-60）读 `Camera.main` → 远端 TP 瞄准 IK 指向观察者本地相机（Docs/17 §4.1"AimIK 同步瞄准方向"未做）。

**G3 双结算分叉**
纯客户端 Owner 的 `processLocalInput` 仍为 true → 本地 TryFire 本地结算伤害（`CombatResolver.ResolveHitscan` L68 `target.ApplyDamage`）写入客户端本地 DamageableTarget，与服务器 HP 无写回同步。Docs/04 §8 设计意图 = 本地仅**预测表现**（动画/特效/后坐/弹药显示-1），伤害权威在服务器。

**G4 击杀竞赛玩法缺失**（Docs/17 §1.4/§3.3/§4.2 全项）
无 kills/deaths 统计、无比分 SyncVar、无 20 杀/10min 终局判定、无 Countdown 输入冻结、无 kill feed/比分板（Tab）；respawn 仅用 `spawns[0]`（Arena 场景 SpawnPoints 下只有 Spawn_0 一个出生点）；无死亡表现与死亡期输入冻结。

**G5 结算链路断裂**
Unity `AccountContracts.cs` L37-38 仍旧契约：请求含 `score` 缺 `durationSeconds/isWin`；响应 DTO 旧 6 字段 vs 后端 12 字段（详见 §5 契约对照表）。`LobbyPage.Results` 为 Docs/20 演示假数据。

**G6 房间码 UI 未接**
后端 `/api/rooms` 五端点（create/list/{code}/join/heartbeat/leave）+ 6 契约测试就绪（N4，提交 bb00260e）；Unity 未消费——当前 F1/F2 + LAN 直连提示语（`NetworkHud` + `LobbyPresenter.StartOnlineHost/Client`）。

**G7 Prediction / LagCompensator 未启动**（原 Day9 核心）
前置已齐：FishNet 4.7.2 **Pro**（ProjectSettings L826 `FISHNET;FISHNET_V4;FISHNET_PRO`）；`Locomotor.Simulate` 唯一移动模拟入口 + `CaptureSnapshot/ApplyAuthoritativeSnapshot` 对账钩子 + `MovementSimulationMode` 枚举（PredictedOwner/ServerAuthority/RemoteProxy 已预留）；本地 `Assets/FishNet/Demos/Prediction` + `ColliderRollback` 可作起步参考。

## 2. 目标与非目标

### 2.1 目标（按阶段，P0→P5）

1. **P0 权威战斗收口**：换弹/切枪服务器验证、瞄准（pitch）同步、纯客户端双结算清理——本地改弹药/血量作弊无效；
2. **P1 击杀竞赛**：MatchLifecycle 服务器状态机（倒计时/20 杀终局/超时判定）、击杀归因与比分、随机出生、死亡期冻结与表现、比分 HUD/kill feed；
3. **P2 结算链路**：Unity 契约对齐后端、ClientMatchId 生成与广播、终局→结算三币→回大厅刷新、失败重试；
4. **P3 Prediction 专窗**：官方 demo 起步 → Locomotor 接入 FishNet CSP（带降级阶梯）；
5. **P4 LagCompensator**：射线单点替换 + FireRequest 方向校验收口（仅 P3 成功后）；
6. **P5 房间码 UI**：大厅房间列表/创建/加入（可砍项）。

### 2.2 非目标（明确不做，本合订范围外）

- Dedicated Server（Docs/04 评级 C 放弃；Host 模式是既定 Demo 权衡）、Rollback 物理回退（C 放弃）、Matchmaking（C 放弃）、Custom UDP Transport（用默认 Tugboat）；
- 正式反作弊（服务器权威验证 + 后端数值裁剪已是最低安全线，Docs/17 §4.8）；
- 观战、>2 人 FFA **实现**（架构不写死人数上限即可，预留扩展）；
- 手雷 Throwable（UI 灰显"预留"，第一候选砍项传统沿用）；
- **断线重连续战**：首版对战中断线 = 本局作废不计奖励；仅"结算前断线 → 重连后凭 ClientMatchId 幂等补交（本地暂存待提交记录）"（Docs/17 §3.3）；
- 跨局 Player 网络持久化、赛季/排位、技能点演进冻结等 Docs/17 §1.7 全部条款沿用；
- LPW 视觉 F 线（F0/F3/F4）——独立线，与本计划互不抢文件（见 §1.4 护栏）。

### 3.3 硬约束

1. **架构铁律**（Docs/17 §2.4）：三层单向依赖（Presentation → Gameplay ← NetworkAdapter，asmdef 编译期强制）；单写者（只有 Locomotor 动 Transform / 只有 AnimDriver 播动画 / 只有服务器改比分）；状态/事件二分；权威边界（客户端不是比分、弹药、HP、奖励的权威来源）。
2. **网络只传 Gameplay 语义**（Docs/04 §8 铁律）：FSM 状态枚举 + Action 事件；禁传 Animator 参数、动画名、归一化进度。
3. `Locomotor.Simulate` 是唯一移动模拟入口；网络层不得直接写 Transform（`ApplyAuthoritativeSnapshot` 是唯一例外入口）。
4. **运行时测试授权制**（Docs/07 最高纪律）：PlayMode 注入测试必须用户亲自授权；禁止轮询；默认安全手段 = EditMode + 只读 console；PlayMode 冒烟失败先判编辑器伪影（isPaused/帧计数）即停，实机验收以用户为准。
5. 每 Job 完成立即 `git add -A && git commit`（2026-08-25 事故制度）；Unity 单编辑器实例；编辑器卡死预防协议（工具超时 → 停发 → unity_job 清点取消 → 日志诊断 → 磁盘安全检查 → 重启 → idle 验证）。
6. 凭据只走 User Secrets / 环境变量；JWT/密钥/连接串不入库、不入日志；后端契约测试打真库用随机前缀用户名。
7. **离线单人零回归**：网络未启动时所有新增组件零副作用（沿用 N1 门控惯例）。
8. FishNet **4.7.2 锁定**；升级 FishNet 版本属范围外。
9. LPW 基线测试与实施会话严格串行（§1.4 护栏④）；基线收口前开工必须先过护栏②开工基线门槛。

## 4. 分阶段实施（合订两天 ≈24h 含缓冲）

### P0 权威战斗收口（Day8 前段，≈5h）——G1+G2+G3

1. **G1 换弹/切枪服务器验证**
   - `NetworkCombatAuthority` 增 `ServerReloadRequest`（ServerRpc，RequireOwnership=true）→ 服务器 `WeaponController.TryReload()`（ActionSystem 服务器侧闸：忙碌/弹满拒绝）；
   - 增 `ServerSwitchRequest(slot)` → 服务器 Arsenal 换装 → 既有 `NetworkWeaponState._weaponId` 广播链自动生效；
   - 弹药权威：`NetworkWeaponState` 增 SyncVar（currentAmmo/reserveAmmo），服务器 Runtime 变化广播；Owner 本地弹药 -1 仅作预测显示，HUD 读 SyncVar 权威值。
2. **G2 瞄准同步**
   - `MovementCommand` 增 `PitchDelta`（随既有 `ServerSubmitCommand` 上行）；
   - 服务器侧 NetworkAimState：pitch 累加写入服务器侧 aimPivot（disabled GameObject 的 Transform 写入安全）→ 服务器 FireContext 射线恢复正确俯仰；
   - `FireRequest` 增 aimDir 快照参数（对齐 Docs/04 §8 原设计）。**设计决策（v1）**：服务器以请求内 dir 为准（LAN 1v1 信任边界内），防滥用校验收口留给 P4（方向与历史位姿偏差超限拒绝）；
   - 远端 TP 瞄准：pitch → SyncVar → RemotePlayerStateView 增量 → `TPAimDriver` 瞄准源从 Camera.main 切到远端同步瞄准方向（Owner/本地路径不变）。
3. **G3 双结算清理**
   - `DamageableTarget.ApplyDamage` 权威门：网络已启动且本端非服务器 → 不结算生命值（预测射线仅表现）；网络未启动（离线）→ 本地结算照旧；
   - Owner 本地开火保留完整预测表现（Docs/04 §8：立即播动画/特效/后坐）；HP HUD 读 `NetworkCombatAuthority.Health`（SyncVar）。
4. **EditMode**：换弹/切枪请求状态机用例（含忙碌/弹满拒绝分支）、弹药 SyncVar 语义（服务器写/Owner 读）、DamageableTarget 权威门用例（离线开/联网客户端关/联网服务器开）。
5. 顺手项（**后置至 LPW 基线收口后**）：`processLocalInput` 由反射写改为 internal 公共 setter——基线活跃期内维持反射惯例，不动该字段定义。

**退出条件**：编译 0 错 + EditMode 全绿；联网行为验收移交用户（或授权 PlayMode Host 单实例冒烟）。

### P1 击杀竞赛玩法（Day8 后段，≈6h）——G4

1. `MatchLifecycle : NetworkBehaviour`（Arena 增 MatchSystems 挂载，场景级单例）：
   `WaitingPlayers → Countdown(3s, 服务器广播输入冻结) → InProgress → Ended`
   - 终局判定（服务器唯一权威）：任一玩家 kills ≥ 20 立即结束；10 分钟超时按击杀数判、击杀相同按死亡少者、再相同判 DRAW；
   - ClientMatchId 于 Countdown 开始生成（见 P2）。
2. **击杀归因**：服务器从 `WeaponShot.Result.Target`（DamageableTarget）→ 归属对方 NetworkCombatAuthority → kills/deaths SyncVar（每玩家）；kill feed 由服务器 ObserversRpc 广播（击杀者/被杀者/武器）。
3. **重生完整版**：Arena SpawnPoints 补 Spawn_1~3；服务器随机选点，排除与对手当前位置距离 < 8m 的点（无可选则全集随机）；死亡期输入冻结（复用 dead SyncVar → 本地输入消费门控）+ TP 倒地简式表现（禁用碰撞/模型倒置）。
4. **HUD**：Arena 内比分常驻条（我方击杀/目标 20/对方击杀）+ Tab 比分板（双方 K/D）+ kill feed——挂 WeaponHudCanvas 同层；HUD 只读同步状态。
5. **EditMode**：MatchLifecycle 状态机全转移用例（含 20 杀/超时/平局判定与优先级）、击杀归因、出生点选择（排除逻辑/回退逻辑）。

**退出条件**：EditMode 全绿；Host 单实例 PlayMode 冒烟（授权制）：倒计时冻结→开火击杀→比分→20 杀终局。

### P2 结算链路（Day9 前段，≈4h）——G5

1. **契约对齐**（以后端 `Contracts.cs` 为准，见 §5 对照表）：`MatchSubmissionRequest` 去 `score` 增 `durationSeconds/isWin`；`MatchResultDto` 对齐 12 字段；新增序列化快照 EditMode 用例。
2. **ClientMatchId**：Host 于 Countdown 开始生成（格式 `match-{yyyyMMddHHmmss}-{4 位随机}`，8~64 字符内），ObserversRpc 广播全员；各客户端留存；**同局重试复用**（幂等键）。
3. **终局流**：Ended → 各客户端收集结算数据（kills/deaths/duration/isWin **全取服务器权威 SyncVar/判定**，客户端不自制胜负）→ `SubmitMatchAsync`（客户端预校验 kills≤30/duration≤900s，避免 422）→ Results 页实数据（三币 + 升级进度 + 通行证升级/新配件/新成就徽标，替换 Docs/20 演示版）→ 返回大厅刷新档案/钱包/通行证。
4. **失败重试**：提交失败本地暂存待提交记录（PlayerPrefs，键含 ClientMatchId）+ Results 页重试按钮；后端 ClientMatchId 幂等保证不重复发奖；**对战中断线 = 作废不提交**（Docs/17 §3.3 首版规则）。

**退出条件**：EditMode 全绿；结算全链验收 = 用户双端实机（两账号各得奖励、重试不重复发奖）。

### P3 Prediction 专窗（Day9 午后，≈6h，硬回退线）——G7a

1. **前置**：本地跑通 FishNet `Demos/Prediction`（Tuanjie 6000.0.76f1 + FishNet 4.7.2 Pro）——**跑不通即触发降级阶梯**。

3. **降级阶梯（硬线）**：CSP 服务器权威预测（目标）→ PredictedOwner 组件（Docs/19 预留位，所有者模拟）→ 维持现状（客户端先跑 + 1x 重放 + NetworkTransform，**回退线**）。
4. **EditMode**：预测开关不影响离线模式用例；快照对账往返一致性用例。

**退出条件**：demo 跑通证据 + 双端移动手感验收（用户实机，120FPS 录屏为证）。

### P4 LagCompensator（Day9 尾段，≈1.5h，仅 P3 成功后）——G7b

**退出条件**：双端移动中对射命中一致性（用户实机）。
