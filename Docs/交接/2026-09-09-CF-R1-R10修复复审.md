## 必要问题

### F1 / P1：R1 真实 ack→断线顺序仍可能卡死，并存在过早回池路径

位置：`fps-backend/src/UnityFps.Api/Services/RoomService.cs:691,714,723,601,617,1312,1330`。

客户端 `MatchReturnSequence` 是先 AckReturn，成功后才 StopBattleConnection。后端 ReturnAsync 却把 ack 写入 ReturnedAtUtc，与 DS 真断线共用同一水位。

- 全员先 ack 时，ReturnAsync 以 `includeInstance:false` 加载房间。普通请求上下文没有加载实例导航，`ReturnToWaitingUnsafe` 先清 CurrentMatchId，再调用的 ReleaseMatchArchiveUnsafe 因 instance=null 直接返回。随后真实断线上报比较 ticket.MatchId 与已清空的 CurrentMatchId，不会进入释放分支，而返回 Waiting 房间的成员数和 Draining 状态。房间回了 Waiting，DS 却没有拿到 Ready/0 重臂信号。
- 即使补上 Include，也不能解决协议问题：归档释放直接写实例 Ready、CurrentPlayers=0，而 ack 不等于断线。维护超时路径同样无真实断线证明就释放；混合 ack/断线上报也会把仍在线者视作已退场。这会让分配器在旧连接清理及 DS 重臂前租用实例。

现有 R1 测试先直接提交两个 DS disconnect，没有覆盖真实客户端 ack→disconnect 顺序，也没有证明 DS 已重臂。应分离房间归档和实例可租状态；以独立战斗连接退场事实、比赛身份和重臂确认闭环，不能仅靠 ReturnedAtUtc 或返房超时把实例变 Ready。可沿既有 Draining 与重臂握手实现，不要求新架构。

最小回归：全员 ack 后再逐个 disconnect；一人 ack 未断、另一人 disconnect；Returning 超时但 DS 尚有连接。分别断言成员保留、真实清理前不可租、清理与重臂后能同房开第二局。

### F2 / P1：R8 首次出生改位晚于 Spawn 序列化

位置：`Assets/_Project/Scripts/Gameplay/Network/TeamFirstSpawnDirector.cs:92`。

本地 FishNet 源码顺序为 PlayerSpawner.cs:108 `ServerManager.Spawn` → ServerObjects.cs:680 `RebuildObservers` → ServerObjects.Observers.cs:464 `WriteSpawn`，返回后才在 PlayerSpawner.cs:114 调用 OnSpawned。

因此“下一 tick 才序列化，同帧修改即首个同步姿态”的注释和报告不成立：网络发送可以缓冲，但 Spawn 内容已经写入。OnSpawned 中只改 transform 无法更改已写的初始包，至少会使客户端收到旧的轮转出生点，而不是队伍点；是否后续纠正及纠正幅度取决于同步链，不能用纯槽位测试证明首帧正确。

应在调用 ServerManager.Spawn 之前选好并设置位置/朝向，或采用项目拥有的生成入口，避免修改 FishNet 原厂。最小验证覆盖实际生成入口与初始同步姿态，而非只调用 PickTeamSlot。16 连接压力验证仍可留在集中实机批次。

### F3 / P1：R5 守卫外层正确，但生产 Ack 委托仍提前污染新会话

位置：`Assets/_Project/Scripts/UI/MatchSettlementFlow.cs:192–197`；`Assets/_Project/Scripts/Account/AccountSession.cs:70`。

AckReturn 委托 await HTTP 返回后，未经身份检查就执行 `session.RefreshRoomSnapshot(ack.Data)`，然后外层 MatchReturnSequence 才检查代际。若请求在途玩家已换房，RefreshRoomSnapshot 会退化为 ApplyRoomSnapshot，把新房间覆盖成旧房间；即便连接代际检查随后阻止断线，污染也已发生。若只换房而未推进连接代际，旧响应还会把房间码恢复为捕获值，使外层检查再次通过。

应让 ack 委托只返回数据，在验证捕获身份后统一应用，或在委托内任何会话写入之前检查 room/连接代际及适用的比赛身份。现有纯编排 TCS 用例没有执行这段生产委托，不能证明生产接线无副作用。

最小回归：真实装配语义下延迟 ack 响应，切到另一房间（含连接代际不变），再完成旧响应；断言 Room、MatchId、新启动上下文、连接与导航全部不受旧响应影响。
