## 2. 审计发现与已完成修复

1. `PlayerNetworkAdapter` 原先向 `TargetRpc` 传入 `null`，Owner 实际收不到权威校正；已改为传入真实 `owner`。
2. 联网启动后 `Locomotor` 原先仍可能保持 `OfflineLocal`，造成离线 Update 与预测/服务器 tick 双重模拟；现按角色设置为 `ServerAuthority`、`PredictedOwner` 或 `RemoteProxy`，停止网络后恢复 `OfflineLocal`。
3. ACK 处理原先先剪枝再读取对应预测快照，正常确认会退化为硬校正；现使用“先读取、后剪枝”的原子入口。
4. 服务器输入队列首包原先可注入异常巨大 tick；现首包同样受未来 tick 窗口限制。
5. 服务器原先单个真实 tick 最多推进三次移动；现每个服务器 tick 恰好只执行一次 `Locomotor.Simulate`，积压输入分摊到后续 tick。
6. Lobby 已创建/加入房间后若取消、连接 DTO 无效或配装准入失败，原先可能残留后端成员资格；现执行 best-effort `LeaveRoomAsync` 并清除本地上下文和票据。
7. 新计分板原先虚构蓝红队并动态奇偶分队，与服务器“个人击杀竞赛、个人 20 杀终局”规则冲突；现改为 FFA/KILL RACE 单榜。

## 4. 最后一步边界

只做一轮短时真实验收：登录 → 建房/按码加入 → 两端进入 Arena → 同时移动并观察校正 → 移动目标互射并观察有限回溯 → 主动退出并确认房间成员清理。发现阻断项才定向修复，不扩展为全量回归。
