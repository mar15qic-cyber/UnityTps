## 2. 必改项（按优先级）

### 2.1 "基于 FishNet 构建…本地预测" 的歧义（最高优先）
你的移动预测/对账是**自研**的（MovementPredictionCore + PlayerNetworkAdapter 接线），FishNet 承担的是传输/RPC/SyncVar/NetworkTransform。FishNet Pro 自带 Prediction API（Replicate/Reconcile），你**没有用**。现写法会让面试官以为你用的是 FishNet 内建预测，一旦追问"FishNet 的 Reconcile 怎么配的/StateOrder 管理器"，答不上就整段崩塌。
二选一：
- 改写法（推荐）："基于 FishNet 传输层**自研** Tick 制客户端预测与服务器对账（输入缓冲/快照对账/误差分级校正）"；
- 或保留现写法但准备好标准答案："FishNet 提供了内建 Prediction，我评估后选择自研轻量版，因为 XX"——这个答案本身极好，前提是你真讲得出为什么（理由现成：需要与既有 Locomotor.Simulate 唯一模拟入口/快照钩子贴合、可控的对账语义、EditMode 纯逻辑可测）。

### 2.2 数字与参数务必背熟（已核实，可直接引用）
- Tick：服务器固定 tick（FishNet TimeManager，默认 30Hz 档），客户端模拟步与渲染帧解耦，单帧最多追 5 步；
- 预测历史 128 tick；输入每 2 模拟 tick 批量上行、丢包冗余重传上限 12 条；
- 对账阈值：误差 ≤0.03m 忽略、0.03–0.75m 指数平滑、≥0.75m 硬对位+从确认 tick+1 重放；yaw/速度/落地分支分叉有滞回确认（连续 2–3 快照）才升级硬校正；
- 延迟补偿窗口 200ms，越窗裁剪到最老快照；射手自身不回溯；
- 后坐确定性：seed = weaponId + ownerClientId + 生命代际 同源派生；
- 输入代际协议（协议 v6）拒收旧生命输入。

### 2.3 建议增写的亮点（现简历没写、代码里真实存在）
1. **shot 级确认/拒绝闭环**：每发本地预测携带请求 id 上行，服务器权威确认/拒绝，拒绝时撤销预测表现（弹孔/反馈）并回写权威弹药快照——"预测与权威结果合并"的完整案例，比"客户端提交开火请求"高一个档次。
2. **结算补偿队列**：DS 与后端断连时本地持久化待结算记录、恢复后重放、幂等键保证恰一次——分布式系统味道的谈资。
3. **工程纪律数字**：千级 EditMode 测试（本审计实测 1030 全绿）+ 后端 189 用例 + 协议版本号（v6）+ 构建身份门禁（源码摘要判新旧）。"问题分析与调试"那条泛泛的技能描述可以整体替换成这个。
4. 复合受击体（躯干+头部双胶囊，四向几何取证）——一句话即可，体现"用数据反推"。

1. **"问题分析与调试：能够通过日志、断点、调用链和状态检查定位程序问题"**——这是应届生模板句，和上面 FPS 项目已经展示的能力重复且更弱。整条删掉，换 §2.3-3 的测试/工程纪律内容。

## 4. 面试风险点（提前备好口径）

1. **反作弊边界**：服务器权威验证点清单要能脱口而出——死亡闸、shotId 重放去重、冷却/弹药/动作槽校验、输入生命代际、方向快照；同时别把话说满：已知残余包括后坐随机流在接受发次分叉时仍会错位（代码注释自认待 wire 方案）、后端旧路径自报结算存在（如果你主动说"结算完全防作弊"就过头了）。"我知道它防到哪、没防到哪"恰恰是加分答案。
2. **AI 协作的"独立开发"表述**：仓库史显示多代理（Codex/Codely/zcode 等）深度参与实施。建议主动把工作流讲成"我是架构与验收的 owner：写审计票据、定红线、验收修复；AI 做批量实施；每轮修复都有 EditMode 回归与 commit 证据"。2026 年这是工程成熟度的正面信号，但被动被发现就是诚信风险。简历措辞你自己定，口径必须先备好。
3. **数字一致性**：若写"1030 个测试"，要和 GitHub 上的实际数字同步（它会增长）；稳妥写法"千余条 EditMode + 189 条后端用例"。
4. **RE4 项目**：不在本仓库，本次未核实。所有 bullet 按"能讲出实现细节才算数"自检一遍。

## 5. 改写示例（FPS 项目"网络移动"条）

改前：
> 基于 FishNet 构建服务器权威的玩家移动同步，客户端进行本地预测并缓存输入，服务器按固定 Tick 模拟并返回权威状态，根据误差进行平滑校正或状态重同步，降低网络延迟带来的操作滞后与位置偏差。

改后（供参考，参数都是真的）：
> 基于 FishNet 传输自研 Tick 制客户端预测与对账：客户端固定步模拟并缓存输入/预测快照（128 tick 环形缓冲，批量上行+丢包冗余重传），服务器逐 tick 消费输入并回传权威快照；对账按误差分级——亚厘米忽略、小幅指数平滑、0.75m 以上硬对位并从未确认 tick 重放，速度/朝向/落地分支分叉经滞回确认后升级，避免瞬态误差反复回滚；移动手感经 0/50/150ms 延迟矩阵实测调参。
