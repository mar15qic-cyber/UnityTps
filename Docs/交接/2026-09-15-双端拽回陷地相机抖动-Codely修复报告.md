## 1. 修改文件与原因

### 1.1 纠偏台账：在途量只剪枝、不清账（审计 §2）

文件：`Assets/_Project/Scripts/Gameplay/Movement/MovementPredictionCore.cs`

* `SmoothCorrectionLedger.ConsumeInFlightAfter(ackedTick)` 旧实现"求和 tick>ACK 后整体 `_entries.Clear()`"。ACK 配对是**逐张增量**语义：同一条在途步进会被连续多张早于它的 ACK 快照重复看见，因此必须保留到 ACK 追过它为止。
  * 现实现：求和 `tick > ackedTick` 的步进，**只删除 `tick ≤ ackedTick`**（这些已进入配对快照，误差天然已扣除）的条目。
  * 直接后果（审计最小反例）：tick12 施加 +0.1m；ACK10 与 ACK11 的配对快照都早于 tick12、原始误差都是 +0.1m——旧实现第二次查账返回 0 → 又施加 +0.1m（实机"前进被拽回"）。
* 新增**粘滞** `Overflowed` 标记：`Record` 超限即整体作废并置位；只有 `Invalidate()`（硬重基）才清除。旧实现只停用一次平滑，后续 ACK 会把它重新启用——审计明确指出这"不等于已经要求硬重基"。
* `TickAccumulator.Remainder`（只读）：供渲染位置插值换算本帧在两步之间的比例。
* `ServerInputQueue` 新增累计口径 `ReceivedTotal` / `ConsumedTotal`（诊断用，不参与判定）。
* `MovementPredictionConfig` 新增渲染插值开关/上限与诊断周期常量。

### 1.2 校正决策统一重算 + 溢出硬重基（审计 §2）

文件：`Assets/_Project/Scripts/Gameplay/Network/PlayerNetworkAdapter.cs`

* `None` 与 `Smooth` 分支统一为同一条重算路径：`corrected = (服务器配对快照 − 客户端配对快照) − 台账在途量`；`|corrected| ≤ 0.03m` 则取消旧纠偏，否则以 `corrected` 作为新的平滑偏移。
  * 修掉审计点名的第二个缺陷：`None` 分支过去什么都不做，于是"误差已进噪声带、旧 `remaining` 仍在继续消费"（超调无法收回）。现在会给出反向偏移把它收回来。
* 台账溢出 → 走 `HardSnapTo`（硬重基），日志 `LEDGER_OVERFLOW_REBASE`。
* 硬对位/死亡/重生/冻结/接管均调用 `ResetOwnerVisualInterpolation()`（见 1.4）。
* 删除旧的两秒 `[Day3][Reconcile] summary`（其证据字段已并入 §1.3 的 `[MoveDiag]` 行，避免双份输出）。

### 1.3 有限诊断汇总（审计 §2 第 2 项）

文件：`Assets/_Project/Scripts/Gameplay/Movement/MovementDiagnostics.cs`（新）、`PlayerNetworkAdapter.cs`

* 每 `2s` 每玩家实例输出一行（owner 与服务端各一行，字段一致、顺序稳定，便于 shell 按 `key=value` 对账）：

```
[MoveDiag] role=owner pid=… conn=… obj=… match=… t=… tickRate=30 gen=… sub=…/… recv=… cons=… empty=… local=… ack=… stTick=… qdepth=… dropSteps=… dropStale=… dropBacklog=… dropFuture=… rtt=…ms dt=min/avg/max long=… bg=0/1 focus=0/1 snaps=… smooth=… applied=…m pend=…m err=…m visOff=…m
```

* 口径（写进代码注释，防止后续误读）：
  * `gen` 本地生成模拟 tick；`sub` 上行批次/命令数；`recv`/`cons` 服务端累计收到/消费；`empty` 服务端空步（无输入仍模拟默认命令）；
  * `dropStale` 含**冗余重传去重**，不是丢包证据；`dropBacklog` 队列上限丢最旧；`dropFuture` tick 失控；`dropSteps` 客户端追帧上限丢步；
  * `dt` 区间帧时长 min/avg/max + `long`（>2×固定步长）计数；`bg`/`focus` 前后台状态。
* 独立日志入口**未重复实现**：核对确认 `启动客户端.cmd → Tools/Client/Start-LocalClient.ps1`（每次启动生成 `Tools/Client/Logs/client-<stamp>-<rand>.log` 并在启动时打印 `buildId`/`protocolId`）。DS/后端日志沿用既有 `Tools/Server` 入口。
* 诊断只做输出、绝不反作用于玩法：`TimeManager` 经 `NetworkObject` 短路访问，脱离网络生命周期调用也安全（有定向用例）。

### 1.4 死亡倒地表现：贴地 + 完整还原 + 权威收敛（审计 §3）

文件：`Assets/_Project/Scripts/Gameplay/Network/NetworkCombatAuthority.cs`

* 倒地姿态贴地（新）：前倾 85° 后按**实测地面**把姿态包围盒下沿抬到地面之上（`DeathGroundClearance = 2cm`）。
  * 地面探测：姿态包围盒中心 + 四向前后左右共 5 条探针垂直向下，取**最高**落脚面；忽略 trigger（`BodyHitbox` 是 trigger）与自身层级（根 `CharacterController` / TP 网格碰撞体）；探测不到地面 → **保持原姿态**（不猜测、不整体抬高活人、不硬编码地图高度）。
  * 包围盒用 `Renderer.localBounds` 8 角点经各自世界矩阵变换合成，**不读 `Renderer.bounds`**（同帧改过旋转时该缓存可能仍是旧值）。
* 完整还原：新增保存 `TP_Model.localPosition`；复活时位置 + 旋转 + 被禁用的动画写入者 + 被禁用的受击碰撞体全部还原，重复死亡广播幂等。
* 权威收敛：`Update` 新增 `SyncDeathVisualWithState()`——表现以 `_dead` SyncVar 为准收敛，`ObserversDied/Respawned` RPC 只作为即时通路。修掉两个缺口：(a) 迟到观察者收不到播发给当时观察者的 RPC（模型不倒地）；(b) 丢失 RPC 时永久停在倒地姿态（`_dead` 复位可自愈）。用 `_deadStateSeen` 锁存避免"RPC 先到（`_dead` 仍 false）→ 立即复位"的每局来回翻转。
* `FindTpModel()` 查找失败改为 1s 节流 + 只告警一次（新收敛路径每帧调用，不能每帧遍历层级/刷屏）。

### 1.5 Owner 模拟与渲染位置分离（审计 §4）

文件：`Assets/_Project/Scripts/Gameplay/Network/PlayerNetworkAdapter.cs`、`MovementPredictionCore.cs`

* 事实核对（决定了实现方式）：`CM_FP_Camera` 的 `TrackingTarget = CameraPivot` + `CinemachineHardLockToTarget` → **相机渲染位姿只由 `CameraPivot` 世界位姿决定**（`Main Camera` 由 Brain 驱动，写它无效）。
* 因此新增**专用视觉偏移节点** `ViewSmoothingRoot`（纯客户端 Owner 在 `OnStartClient/OnOwnershipClient` 运行时创建，把 `CameraPivot` 重挂其下、保持世界位姿；零 prefab/场景改动、节点缺失时自动跳过）：
  * 写者唯一性：模拟根（本对象，唯一服务器权威对位对象）由预测/校正写；`CameraPivot.localPosition` 仍由 `FPCameraRig` 独占（本人倒地视角）；**渲染位置偏移只写 `ViewSmoothingRoot`**。三者互不覆盖。
  * 渲染帧插值：`RunOwnerPrediction` 记录"本帧步进前 → 步进后"根位置，`UpdateOwnerVisualPosition` 用累积器余量做 `Lerp`，得到连续的相机/第一人称位姿；单帧偏移超 `0.6m`（卡顿/瞬移残余）直接归零重记基准。
  * 旋转不插值：鼠标朝向即时响应（审计要求"保持鼠标旋转响应"）。
  * 硬对位/死亡/重生/冻结/接管：`ResetOwnerVisualInterpolation()` 作废基准并归零，**不做穿场插值**。
  * 语义边界：视觉偏移只作用于表现；服务器瞄准/枪口判定基准（服务器自算）与玩家碰撞根（模拟根）不受影响；纯客户端本地表现（枪口特效/弹道起点）最多差一个 tick 位移。
* 代价（有意为之、如实记录）：相机位置滞后至多一个模拟 tick（≈33ms @30Hz）。这是"固定 tick 模拟 + 高渲染帧率"的固有取舍——不加插值就是阶梯位移，加插值就必然引入这一档延迟。可用运行时开关 `MovementPredictionConfig.RenderPositionInterpolationEnabled` 做 A/B 手感对比；若用户实机认为延迟更难受，置 false 即回退到旧行为（纠偏修复仍然生效）。

### 1.6 近距阻挡一致性：核实结论 + 未实施的权衡（审计 §5）

按审计要求"先核实、给出明确定义路径、若无法在不破坏玩法下修复则报告权衡，禁止默认改成玩家互穿"，本轮**未改玩法**。核实证据：

1. `Locomotor.SetSimulationMode(RemoteProxy)` 只改枚举；`Simulate` 对 RemoteProxy 提前返回，但**根 `CharacterController` 保持启用**（全仓无任何位置禁用它；仅 `ApplySmoothCorrection`/`ApplyAuthoritativeSnapshot` 会瞬时禁用后直写 Transform）。
2. 远端玩家位置由服务器权威 `NetworkTransform` **插值**呈现，缓冲按 RTT 抖动自适应钳制在 **2–8 tick**（`PlayerNetworkAdapter.UpdateRemoteInterpolation`）。
3. 因此 Owner 预测碰撞的是"插值后（滞后 2–8 tick ≈ 67–267ms）的远端胶囊"，而服务器模拟 Owner 时碰撞的是远端**权威**位置：走速 1.58 m/s 对应 10–42cm 误差、冲刺 3.44 m/s 对应 23–92cm——与用户"越靠近越明显"吻合。
4. 现有日志无法定量证明强度（审计已指出客户端日志混写、无移动 batch 收发关联），本轮新增的 `[MoveDiag]`（`rtt` + `empty` + `smooth/applied/err`）首次提供了可对账口径。

**建议的后续票据设计（需用户/Codex 拍板，本轮不动）**：给远端玩家引入"预测碰撞代理"——碰撞胶囊跟随**最新收到的权威位姿**（不插值），视觉模型保持插值。数据前提是拿到 `NetworkTransform` 的"本帧最新收到的目标位姿"（当前未暴露），因此需要一条不依赖 NetworkTransform 插值的远端位姿通路（自定义同步或 FishNet 侧取原始 replicate 数据）。替代方案：对"与 Owner 距离 < N 米"的远端临时压低插值 tick（换取碰撞一致性、牺牲其视觉平滑）——同样属于玩法/表现权衡，需用户选择。**两者都不采用"玩家互穿"。**

## 3. 未验证项（不得当作已通过）

1. **手感**：拽回是否消失、相机是否"够平滑"、渲染插值带来的 ≤1 tick 视觉延迟是否可接受——**只能实机**。若延迟更难受，用 §1.5 的开关对比后决定保留哪一种。
2. **倒地表现的实机画面**：贴地修正的抬升量取决于模型 `localBounds` 与地面探测，实机需要目视确认（尤其斜坡/台阶/高台边沿、以及"上半身直立/下半身埋地"是否完全消失）。录像中"持续到重生后的埋地"本轮按"位置未还原 + SyncVar 未收敛"两个确定性缺口修复并加了回归；若实机仍有残留，请交回死亡前/死亡/重生后三张帧与两份客户端日志（审计 §3 要求的分段坐标口径已具备：根 vs `TP_Model` 局部 vs 骨骼）。
3. **近距阻挡一致性**（§1.6）：只完成核实与方案，未实施。
4. **多玩家/长时**：`[MoveDiag]` 的双端对账（gen↔recv 是否闭合、empty/dropX 是否异常）本轮未采集——**这正是需要用户交回日志的部分**。
5. **构建后的运行期行为**：双端已重建（§5），但"构建成功 + 标记命中"不等于运行期正确——`ViewSmoothingRoot` 的创建/重挂、`[MoveDiag]` 输出、贴地修正的实机表现都只在真实对局里被验证。
6. 本机双开 CPU/GPU 竞争与失焦对阶梯感的影响未测量（`[MoveDiag]` 的 `dt`/`long`/`bg`/`focus` 字段就是为此准备）。

## 4. 3 分钟人工复测步骤

前置：使用**含本轮改动**的双端构建（见 §5），后端 + DS 按既有入口启动；两个客户端都用 `启动客户端.cmd` 启动（各自独立日志，启动行会打印 `buildId`）。

1. **拽回（60s）**：A 建房、B 加入。A 朝任意方向持续走 10s（中途冲刺 3s），再原地绕圈 10s；观察是否出现"前进被反向拖回"。→ 期望：不再有规律性反向拽回；如仍有，记录时间点。
2. **近距（40s）**：A、B 靠近到贴身（互相推挤）并绕行 10s，再贴墙走 10s（墙体阻挡不得回归）。→ 期望：贴身推挤不再放大抖动；墙体阻挡与代前一致。
3. **死亡/重生（40s）**：B 击杀 A（A 尽量在平地），观察 A 被击杀瞬间到重生后 5s；随后换位再来一次。→ 期望：倒地姿态落在地面上（脚/躯干不埋地）、3s 后正常起身回到出生点。
4. **跳跃/空中（20s）**：双方各跑跳 2 次（含一次跳跃中被击杀）。→ 期望：空中死亡不留埋地残影。
5. **交回材料**：两份 `Tools/Client/Logs/client-*.log` + DS 日志。按 `conn` 与时间对齐后看 `[MoveDiag]`：`gen↔recv` 是否大致闭合、`empty`/`dropStale` 是否异常增长、`smooth/applied/err` 是否已收敛到 0；以及 `[Day3][Reconcile] SNAP/DIVERGENCE/LEDGER_OVERFLOW_REBASE` 是否出现（出现即需要新的证据切片）。
