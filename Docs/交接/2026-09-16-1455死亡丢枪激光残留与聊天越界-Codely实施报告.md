## 1. 批次 A：FP 可见性单一写者（计划 §3）

**根因链（已用代码+测试固化）**：FPCameraRig（-40）死亡时保存"当时 enabled=true"再禁用 → FPWeaponRig（常规序）死亡时把 false 存进自己的快照 → 复活相机恢复 true → Rig 协程下一帧按自己的快照写回 false → 永久隐形。仅"死时当前枪"符合 Rig 只缓存 `_activeView` 的事实；之后持另一把枪死亡又被污染。

改动：
1. **新增 `Presentation/Animation/FPViewModelVisibility.cs`**：原因位（`Death/ScopeOverlay/RespawnPreparing`）合成，全部清空才可见；Renderer 基线在**受控注册**（视图创建/配件挂载）时捕获且**首次注册生效**——其它系统造成的临时隐藏不会被读成作者原始状态，也绝不一律 true（作者关闭的网格/附件不打开）；隐藏期间新注册立即跟随（防闪帧）；`Apply()` 顺带清理已销毁引用。
2. **`FPCameraRig`**：删除 `hiddenDeathRenderers` 的保存/恢复循环——只管位置/侧倾/FOV（计划 §3.3-1）。日志相应去掉 hiddenRenderers 字段。
3. **`FPWeaponRig`**：持 `_visibility`；`ShowView`/`ApplyPersistedAttachments` 把视图与动态配件 Renderer 注册进基线；`ApplyDeathState` = `Death=true` + 作废复活协程；`ApplyRespawnState` = 释放 `Death` + 置 `RespawnPreparing` + 代际递增后起协程，**恢复只释放自己的 RespawnPreparing**，不碰 ScopeOverlay；`OnDisable` = 代际作废 + `ResetAll()` 按基线还原（池化复用不带回上一局的隐藏原因）。
4. **`OpticAdsView`**：`SetScopedViewmodelHidden(bool)` → `SetScopeOverlayHidden(bool)`（只持 ScopeOverlay 位）；`IsScopedViewmodelHidden` 语义收窄为"镜内原因"，原 L96 的恢复探测逻辑不变。
5. **幂等**：Rig 原因位天然幂等（重复死亡广播只置一次）；死亡入口不再依赖 TP_Model 幂等闸（`ApplyOwnerFpDeathState` 本就在闸前调用，重复回调无副作用）。
6. **§3.3-6 实施核实（抓到真问题）**：`FPWeaponMotion` 挂在 **viewRoot（FP_Weapon_Root）** 而不在视图实例（`Player_Day2_Rebuilt.prefab` fileID 2554193943839985104 = FP_Weapon_Root；FP 视图 prefab 内无该 GUID）——上一批 `_activeView.TryGetComponent<FPWeaponMotion>` 永远落空、运行态缓存清理从未生效。改为 rig 侧 `GetComponentInChildren<FPWeaponMotion>(true)` 懒解析。

## 3. 批次 C：聊天真正卸载与上下文限定（计划 §5）

**旧链确认**（与计划一致）：`LeaveWaitingRoomAsync` 确实调用了 `StopAndClear`——问题不在"忘调"，而在 StopAndClear 只清数据。逐项落地：

| 计划条目 | 实现 |
|---|---|
| §5.3-1 幂等退出入口 | `TeardownView`：`_running=false` → 代际++ → `SetInteractive(false)`（关展开窗/释放焦点/IME）→ 清草稿/（按需）历史 → `UnBindView()` → `SetActive(false)` + 销毁根 → 解绑 RPC 订阅 → 清 pending 草稿计时 → `SetChatFocused(false)` → 清静态 Instance（**身份核对**）。`Instance==null` 时也 `ChatRoomSession.Reset`（旧实现直接 return）。销毁前先 SetActive(false)：帧尾 Destroy 生效前不再能被找到。 |
| §5.3-2 退出 vs 返房 | `StopAndClear()`（退房/登出/会话失效/房解散 = 清历史+游标）与 `StopKeepSession()`（留房跨页/跨场景 = 保留 ChatRoomSession）分离；`OnDestroy` 永不清房间历史（返房补水语义）。 |
| §5.3-3 统一调用点 | `LobbyPresenter.Logout` 补 `StopAndClear()`；`Navigate` 增加页面上下文兜底 `SetPageContext(canvas, chatAllowed: page==WaitingRoom)`（卸载挂在本画布的聊天、保留会话、不动 Arena HUD 画布的实例）；Gameplay 主动退出在 `GameplayMenuController.ReturnToLobbyLocally` 按既有反射惯例调 `Game.UI.Chat.ChatController.StopAndClear`（Gameplay 不引 UI）。 |
| §5.3-4 挂载限定 | `ChatHudView.TryMount` 只认**目标画布**下（含未激活）实例，删除全场 `FindFirstObjectByType`；`EnsureRunning` 检测实例画布 ≠ 目标画布 → 卸载重建；`BindViewOnce/UnBindView` 守卫保证事件只绑一份（修复"再次入房重复 += → 同一发送多请求/多 clientMessageId"）。 |
| §5.3-5 会话代际 | `_roomGeneration`（换房/退房递增）；`FetchHttpAsync/SendHttpAsync` 回包同时校验 `roomCode + generation + _running`——退出后**重进同一房间**的迟到回包也不得写入。 |
| §5.3-6 Enter 闸门 | `ChatHudView._interactive`：false 时不响应 Enter 热键、强制收起展开窗、释放 `ChatFocused`。 |

409 ROOM_STATE_CONFLICT 定性保留为转换期诊断（计划 §2.3）：正确取消后不再产生无上下文 HTTP 轮询。
