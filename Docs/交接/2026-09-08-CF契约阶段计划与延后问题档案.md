## 2. 契约必须回答的问题

### 数据与身份

- 房间：稳定房间标识/房间码、房主账号、状态、容量、地图 ID、模式、规则、roomVersion、成员快照；host 管理身份不得等同 DS 网络主机。
- 成员：服务器确定的账号、队伍、准备、加入顺序与心跳。时间和身份不能信任客户端提交值。
- 比赛：matchId、generation、冻结规则/地图/队伍、DS 租约身份；与客户端 ConnectionGeneration 分离。旧比赛离开、超时、结算回调不能修改新比赛。
- 地图：稳定 mapId、场景标识、支持模式、容量、目录版本、出生点组引用。首版 Arena；开始时校验后端、客户端、DS 支持情况。
- 明确 DTO 字段类型、枚举、可空字段、服务器时间格式、数据库字段/索引/迁移和兼容策略，不能只列字段名称。

### 接口清单

在契约中给出每个操作的实际 HTTP 路径、方法、鉴权、请求/响应例子、错误码与幂等规则：

| 操作 | 必须约束 |
|---|---|
| 列表、详情、创建、加入 | 返回等待快照；Starting 拒绝新成员；InMatch 加入按队伍容量与 Pending 占位验证并接通补人，不发无效连接信息 |
| 选边、准备、设置 | 队伍容量；换队取消本人准备；房主改设置清空全部准备；过期版本冲突响应 |
| 开始 | 双方至少一人、非房主全准备；房主点击开始视为本人准备；并发请求只分配一次 |
| 领取/消费连接票据 | 按个人、比赛、代际绑定；一次性消费；重试领取和已消费后的行为明确 |
| 成员心跳、离开房间 | 后端成员生命周期、超时清理、房主按加入顺序移交；最后成员离开关闭房间 |
| 聊天发送/拉取与局内 RPC | 统一频道/正文/去重标识及消息序号；HTTP/RPC 分别鉴权；身份与收件人由服务器决定；队聊禁止全员广播 |
| DS 启动/成员加载/终局/释放 | 服务器鉴权与比赛代际校验；本批次实现加载、终局、返房与释放完整闭环 |

### 状态、并发与失败

列出 Waiting→Starting→InMatch→Returning→Waiting 及 Closed 的转移表：触发者、前置条件、原子写入内容、副作用、失败恢复。Waiting 不持有战斗 DS；开始无可用 DS 时保留等待房间和准备状态，可安全重试。

约定 60 秒加载等待、双边已有加载玩家后 3 秒倒计时；明确这些动作分别由后端还是 DS 负责。网络调用失败不能令房间永久停在 Starting。Pending 占位、租约释放、超时回调必须有相同比赛身份守卫；重试不重复发起一局。数据库事务不跨长时外部网络等待。

区分离开战斗连接与离开房间；返房保留成员身份，清准备。AccountSession 的同房间快照刷新不推进 ConnectionGeneration；真正连接替换才推进。局中队伍/比分与聊天在本批次一并接通，协议不得预设客户端权威。

## 3. P1/P2/P3 集成验收和交付

- 并发开始只产生一个 match/租约；无 DS 时可重试且准备不丢；过期 roomVersion 拒绝。
- 房主离开正确移交；成员心跳超时清理；最后成员退出关闭；旧代际回调无副作用。
- 未准备、单边无人、队伍满、非法模式/地图/容量/目录版本均有明确拒绝结果。
- 创建/加入 Waiting 不连接 DS；当前客户端调用链与契约同步；FFA/Kill Race 回归入口可解释、可运行。
- TDM 实机覆盖 1v1、2v2、8v8（必须 16 个连接证据）、非对称补人、并发超员拒绝、友伤关闭与友军挡弹、重生、比分/时限/平局、一队清空、房主中途离开后比赛继续、奖励资格、结算返原房间及多局复用。
- 聊天覆盖等待期→局内→结算→返房；中文输入法确认候选不误发送，打开/关闭/菜单切换无误射或输入残留；全体/队伍隔离、系统频道伪造拒绝、限频与 Unicode、富文本防护、重复请求、滚动历史、草稿与换队清理均有证据。
- 报告包括接口文档、迁移、调用点变更、地图配置、UI/玩法可用入口、测试计数、Client/DS 构建与逐进程实机日志、未验收项、精确修改文件及 P4 接手边界。日志按运行 ID 保存，不覆盖上一轮。
- 开发中运行受影响测试；联测所需 Client/DS 构建属于本批次工作。0 collected 不算通过，双客户端不抵扣 8v8；未验收项必须明示，不能据此宣称本批次审计通过。不要求提前执行 P4 镜内性能验收或重跑无关 Day4 历史全量。
- Codex 只对本批次 P1/P2/P3 是否完整及其回归风险出具审计结论。§4 已归档的历史问题仍按原安排处理；与本批次验收重叠的行为必须提供本批次证据，已有充分证据可复用，不重复测试。
