# 联机第一人称相机差异链路审计

日期：2026-09-09。审计者：Codex/Astra。执行修改者：Codely。

## 结论与边界

已确认保存到磁盘的 Arena 场景 Player 与联机生成 prefab 不一致，足以解释用户看到的相机配置差异。差异同时涉及位置、FOV、相机控制组件和俯仰写入节点，不能仅修一个位置数值。

本次为静态资产/代码核验与编辑器只读查询，没有修改生产代码、场景或 prefab，没有运行测试。编辑器查询时处于 Lobby 非 Play 状态，没有捕获实际双端战斗中的相机状态；因此不能把所有实机症状都标记为已复现。未保存的 Inspector 调整不包含在本审计中。

## 已确认的问题链

1. `Assets/_Project/Scripts/UI/GameplayLoadoutBootstrap.cs:35`：联机启动路径对场景手工配置的 Player 调用 SetIsNetworked(false)，随后 SetActive(false)。
2. `Assets/_Project/Scenes/Arena.unity:2340`：PlayerSpawner 的 _playerPrefab 引用 GUID c3de1bc92f2f99c40a041a113fab97e4，即 `Assets/_Project/Prefabs/Player/Player_Day2_Rebuilt.prefab`。
3. `Assets/FishNet/Runtime/Generated/Component/Spawning/PlayerSpawner.cs:107`：GetPooledInstantiated 从该 prefab 生成网络玩家，不复制场景实例的覆盖。
4. `Assets/_Project/Scripts/Gameplay/Network/PlayerNetworkAdapter.cs:180`：Owner 启用 prefab 自带的 localOnlyRoot（CameraPivot），远端禁用。此路径没有把场景相机配置转移过来。

所以：用户调的是场景实例，联机使用的是 prefab 实例；场景覆盖没有进入联机资产。

## 更深一层：相机控制链也分叉

- 场景移除了 prefab Main Camera 上的 FPMouseLook（prefab 组件 fileID 5324377043688218091），在 CameraPivot 上添加 FPMouseLook（Arena.unity:807）。
- 场景在 CameraPivot 添加 FPCameraRig，并新增 CM_FP_Camera（Arena.unity:2645），其 TrackingTarget 是 CameraPivot；配有 HardLockToTarget、RotateWithFollowTarget、呼吸和后坐力扩展。
- 场景 Main Camera 添加 CinemachineBrain（Arena.unity:3761）。上述 Brain、CinemachineCamera、FPCameraRig 的脚本 GUID 均不存在于该网络 prefab。
- prefab 仍在 Main Camera 挂 FPMouseLook（prefab:559），FPMouseLook.cs:38 每帧写的是所在对象的 localRotation，而 WeaponController.aimPivot 仍指向 CameraPivot（prefab:155）。服务器远端俯仰也写 CameraPivot（PlayerNetworkAdapter.cs:664）。因此本地俯仰写入节点与权威瞄准节点存在结构不一致；具体命中误差仍需在 P4 实机中核验。
- FPCameraRig 驱动 Cinemachine Lens 的 ADS FOV，FPWeaponMotion 使用视图相机位置计算武器对齐。这些依赖意味着仅挪动 FP View Camera 不能保证 ADS/实体镜体验与场景一致。
