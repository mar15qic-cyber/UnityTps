## 修复交付

全链路审计先于本轮改动完成。代码、内容资产及配套构建已完成；**运行中的后端/DS 未切换，双端实机表现尚未验收**。

1. `ThrowableController` 改为左键按下记录持握、松开提交投掷。按住期间不创建弹体、不扣库存、不启动引信；菜单、失焦、死亡和切换取消持握。保留既有服务器权威库存与释放时钟。
2. `PhysicalScopeView` 不再只依赖装备 ID 缓存；相同瞄具父树被重建后重新创建镜片与准线。16 把枪分别连续重装同一瞄具三次，均验证新准线属于当前配件树。
3. 16 份正式音频配置恢复 LPFP 的 `shoot.wav` / `shoot_silencer.wav`，音量与音高倍率为 1。逐配置检查其余 AudioClip 引用全部来自 `Assets/Low Poly FPS Pack/`，未修改原厂包。
4. `MatchLoadingScreen` 提供跨场景保留的全屏过渡与底部进度条，进入/退出都走异步场景加载，热更 bundle 使用 `LoadFromFileAsync`。进度包含场景读取、认证、Owner 就绪与开局阶段；显示值平滑追随真实阶段目标，不以计时器伪造下载进度。战场完成准备前阻断输入并隐藏 HUD，大厅不再显示残留战斗 HUD。
5. 正常退场与认证失败分开处理。返房结果查询最多 3 次，每次查询及返房 ack 各有 2 秒请求取消预算；HTTP 失败或异常也会断开战斗连接、清启动上下文、导航大厅。原有 room/generation 守卫继续阻止迟到请求清理新会话。
6. 霰弹仍为原有 9 颗、3 度散射，未通过增加伤害伪造散射。表现层逐颗生成弹着点，确认时逐颗纠偏，拒绝时撤销预测；Owner/观察者曳光池分别扩大为 32/64。网络载荷新增逐弹丸法线与角色命中标记，因此协议升级为 **fps-net-v14**。
7. 霰弹换弹接入原厂 `reload_open → reload_insert × 缺弹数 → reload_close`，依据实际备弹限制插入次数，整体播放速度适配权威换弹时长，打断/完成使旧回调失效。
8. 校准 SMG03、P90（04）、MP5（05）枪口位置。五把 SMG 均与原厂动画枪骨下枪口坐标匹配，误差小于 0.1 mm；不会将眼睛位置用作缺失枪口的伪替代。
9. 投掷物持握挂点按各模型 mesh bounds 偏移到掌前，取代固定腕部位置。检查 16 套手臂 × 3 种投掷物的同一原生持握姿态截图；完整动态投掷过程仍需实测。
10. 后端允许已被 HTTP Leave 移除的成员凭本局已消费票据完成 DS 权威断开收口；空房删除并将实例置 Draining，**并不直接把数据库实例变成 Ready**。清场重臂及 Ready/0 心跳后才重新发放。懒维护同时回收旧代码遗留的“无成员且 DS 报告 0 连接”空房，仍保留旧会话/跨局拒绝条件。
11. 出生准备期水平与竖直视角统一冻结语义，准备完成再揭开加载画面，避免向用户展示只能上下转头的过渡状态。
