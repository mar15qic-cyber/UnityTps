## 接手时必须先审查的边界

1. 重生不要被重复 ACK、旧输入重放或 SyncVar/RPC 到达时序阻断。死亡之前正在移动/跳跃/开镜/换弹时仍应正确复活，连续至少三轮；复活后不瞬移回死亡点。
2. `OnStopServer` 退订后对象复用是否能重新注册生命事件；`_target` 非空时当前 Update 是否会漏注册。核对对象池/重连场景，不要只测首次生成。
3. TP 死亡表现是否幂等、复活后动画/碰撞是否恢复；纯客户端 `_target` 的缓存路径与服务器不同，要核对。视角降低后手臂、瞄具 RT、武器 Renderer 是否全部隐藏与正确恢复，是否被每帧武器逻辑重新开启。
4. 终局时正在等待的重生定时器应如何处理，不能复活后重新开放已结束对局的操作；校验当前输入门控。
5. 主动退出与 Ended 同帧、先 Ended 后退出、网络丢失、HTTP 失败/超时、2 人与多人局、房间房主是 DS 客户端与本地 Host 两种路径。现有离线/本地服 ReturnNow 路径与异步清房路径不同，须核对本地房间会话、连接与场景加载。
6. 非主动退出者的正常终局结算/奖励/返房不应被新的主动退出标记影响，下一局必须清标记。异常提前 return 的 SettlementNavigationPending 残留也需审查。
7. 房主单人开赛要验证真正进入 InProgress，不能只看 Start HTTP 200。房间成员数、参赛 roster、DS 实际连接数不同，核对 Starting 超时、心跳、容量、末位参赛者离开和未参赛成员留房时的状态收敛。
8. 测试仅包含房主一个成员的房间、三人混合准备、所有人未准备、同队成员、比赛开始后才加入。现有四组合不能替代这些验收。
9. 手动 Join 与轮询自动 EnterBattleAsync 的并发、取消/切页、失败重试、双击开始/加入、票据消费后的重连。未准备玩家不能仅靠轮询获得参赛资格；手动 Join 后需能成功消费票据并实际生成玩家。
10. 准备按钮首次渲染在首轮 detail 回来前、房主转移后的刷新也要验证。旧注释/契约如仍写全员准备，应按本次最终实现更新必要部分。
