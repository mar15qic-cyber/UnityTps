# 2026-09-17 远端"翻小人书"静态审计报告（只读，未改任何文件）

> 审计范围：回答用户三问——①快照到达是否稳定？②客户端是否每一帧在两个位置间推进插值？③还是快照更新频率低？**只读审计，未改代码/资产/配置，未构建未实机。**

## 0. 结论先行

| 链路 | 到达节奏 | 渲染帧是否插值 | 评价 |
|---|---|---|---|
| 位置/旋转（NetworkTransform） | **30Hz 稳定**（每 tick 必发） | **是**（每渲染帧缓冲插值，本轮修复部分已生效） | 位置链已丝滑 |
| **步态相位 gaitPhase（SyncVar）** | **10Hz（0.1s SendRate）** | **否——相位被 10Hz 值逐帧直接覆写，动画不自走** | **"翻小人书"主因** |
| 移动状态/输入（_state/_moveInput SyncVar） | 10Hz | 方向有本地 SmoothDamp 吸收 | 可接受（离散量） |
| 俯仰 _aimPitch（SyncVar） | 10Hz | TPAimDriver 0.08s SmoothDamp 部分吸收 | 大幅快俯仰可见阶梯 |

**一句话：位置快照 30Hz 且客户端每帧插值（这条已修好）；腿部动画相位走的是另一条 SyncVar 链，只有 10Hz，而且动画混合器 Speed=0 完全靠这个 10Hz 值逐帧覆写 NormalizedTime——腿每 100ms 跳一格，这就是"翻小人书"的直接来源。**

## 1. 取证：位置快照（NetworkTransform）到达节奏

`Player_Day2_Rebuilt.prefab` NetworkTransform 序列化块（与运行时反射翻转叠加后的有效值）：

| 字段 | 值 | 含义 |
|---|---|---|
| `_interval` | 1 | 每 1 tick 发送一次 |
| 服务器 tick | 30Hz（既有口径，MoveDiag tickRate=30） | 每 tick 检查一次 |
| `_positionSensitivity` | 0.001 | 移动时每 tick 位移（走 5.3cm/冲刺 11.5cm）必然超阈值 → **每 tick 必发** |
| `_clientAuthoritative` | 运行时翻转为 false | 服务器→观察者单向 |
| `_sendToOwner` | 运行时翻转为 false | 不向 Owner 回发 |
| `_interpolation` | 运行时 SetInterpolation(1) | 根插值压到 1（方案A） |
| `_enableTeleport` | 运行时翻转为 true | 重生/传送瞬移通知 |

→ **位置/旋转流 = 服务器 30Hz 稳定节奏**；本机 UDP 无丢包，到达稳定。

## 2. 取证：客户端是否每渲染帧推进插值

是。调用链：`PlayerNetworkAdapter.Update()`（**每渲染帧**，L538）→ 远端分支（L567-572，`RemoteAuthoritativeCollisionEnabled=true`）→ `UpdateRemoteVisualSmoothing()` → `RemoteVisualInterpolationBuffer.Evaluate(now)`。缓冲在**每次渲染帧调用都求值**（120Hz），样本按 NT 到达节奏（30Hz）推入，任意两样本间线性插值 → 位置/旋转视觉以渲染帧率匀速滑动。**该链本轮修复已生效（EditMode 断言：渲染帧位移恒 ≤ 权威 tick 步长）。**

## 3. 取证："翻小人书"的真正来源——步态相位链只有 10Hz

链路（逐环代码证据）：

1. 服务器 `NetworkLocomotionState.Update()` 每帧写 `_state/_moveInput/_gaitPhase`（NetworkLocomotionState.cs:27-34）。
2. 三个 SyncVar 全部 `new SyncVar<T>()` **默认 SyncType**；FishNet 默认发送率 = `ServerManager._syncTypeRate = 0.1f`（ServerManager.cs，"Default send rate for SyncTypes"，序列化默认 0.1f）；`SyncBase.UpdateSettings` 取 `max(_syncTypeRate, TickDelta)` = **0.1s**。全项目场景/prefab 搜索 `_syncTypeRate` **无任何覆盖**（仅 FishNet demo 场景有）。→ **广播节奏被节流到 10Hz**（30Hz tick 下 = 每 3 tick 发一次）。
3. 远端 `RemotePlayerStateView.GaitPhase` → `NetworkLocomotionState.GaitPhase` → `_gaitPhase.Value`（10Hz 更新）。
4. `TPAnimDriver.UpdateMixerParametersAndPhase()` **每帧**执行 `_walkMixer.NormalizedTime = SourceGaitPhase` / `_runMixer.NormalizedTime = SourceGaitPhase`（TPAnimDriver.cs UpdateMixerParametersAndPhase）。
5. 致命一环：`BuildDirectionalMixer` 里 **`mixer.Speed = 0f`**——混合器**自己完全不推进时间**，动画相位 100% 由这个 10Hz 同步值逐帧覆写。

→ 动画相位每秒只变化 10 次、每次跳 0.1s×步速相位 ≈ 0.16 相位（走）/0.23 相位（跑）→ **腿部动画以 10Hz 跳变 = 用户看到的"翻小人书"**。位置再丝滑，腿还是顿——两条链互不相干。

旁证：`TPAimDriver` 的俯仰平滑只包 `_pitch` 的 SmoothDamp，`_aimPitch` SyncVar 同为 10Hz——快速大幅俯仰也会有轻微阶梯（次要）。

## 4. 修复方向（建议，未实施）

| 方案 | 改动 | 效果 | 代价 |
|---|---|---|---|
| A. 提频（止血） | `NetworkLocomotionState` 三 SyncVar（及 `_aimPitch`）SendRate=0（每 tick 30Hz）：`new SyncVar<T>(new SyncTypeSettings(0f))` 或 NetworkManager 全局 `_syncTypeRate=0` | 相位 30Hz 到达，搭配现有逐帧覆写即大幅改善 | 带宽小幅上升（每玩家每 tick 数个小包广播） |
| B. 本地连续积分（推荐） | 远端相位渲染与同步解耦：用 `MoveInput`×走/跑周期（Walk 0.933s/Sprint 0.667s 或 RootMotionProfile）**本地推进相位**，SyncVar 仅作低频锚定/纠偏 | 完全丝滑、带宽最低，与位置缓冲插值同哲学 | 需处理走↔跑切换与状态切换的相位对齐 |
| C. 混合器自走 | 远端把 `mixer.Speed` 置 1（动画按渲染帧自走），`_gaitPhase` 只在状态切换/纠偏时写 NormalizedTime | 改动小 | 相位会随两端周期差漂移，需周期对齐；与"相位外部供给"的现设计分歧 |

方案 B 与 C 可合并（本地自走+低频锚定）。另：`_aimPitch` 若同步提频，TP 俯仰也会更跟手。
