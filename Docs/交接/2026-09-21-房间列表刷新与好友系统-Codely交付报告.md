## 1. 三个问题的根因与修复

### 1.1 房间按钮"黑着"（等待房间页）
**根因两层（均已修复）：**
1. **黑块本体**：`UIComponents.Button` 返回的是 **Face 子物体**上的 Button，按钮根节点 `Btn_N` 下还有一层 Depth 阴影 Image（`ButtonShadow = #0D1117` 近黑）。`LobbyPresenter.WaitingRoom.cs` 对 `button.gameObject`（=Face）做 `SetActive(false)`，Face 隐藏后**根节点的近黑阴影层残留**——房主看到"准备"位置一块黑、非房主看到"开始比赛"位置一块黑。
   修复：`UIComponents.SetVisible(Button, bool)` 助手（切换 `transform.parent` 根节点），替换 WaitingRoom 全部 4 处。
2. **附带挖出真 bug**：`UpdateWaitingUi` 里按钮隐藏后紧跟 `GetComponentInChildren<TMP_Text>().text = ...`——默认搜索**不含 inactive** → 返回 null → NRE → **房主的等待房间轮询循环在首个快照后静默死亡**（火并吞异常的 fire-and-forget Task），房主的"开始比赛"按钮因此永远无法点亮。修复：`GetComponentInChildren<TMP_Text>(true)` + null 守卫。

修复后行为：房主只见可用的「开始比赛」；非房主只见可用的「准备」；Starting/InMatch 时操作按钮变「进入比赛」；无任何黑块。

### 1.2 房间列表不实时（B 看不到 A 的新房）
**根因**：`RenderOnlineJoin` 只在进页时调用一次 `ListRoomsAsync`，无轮询无刷新（后端 `GET /api/rooms` 本身没问题）。
修复（纯客户端）：
- joinCard 内独立容器 `RoomListContent` + 「刷新」按钮（立即拉取）+ 「已刷新 HH:mm:ss」时间戳。
- 轮询循环：停留页面每 **3s** 自动重拉，行数 4→6；renderId 守卫防地图目录回包重渲染后的双循环；`pageCts` 随页面取消。
- 手动刷新与轮询并发由 ApiClient 现有 operationKey 去重兜底（`CLIENT_DUPLICATE_REQUEST` 静默跳过）。

### 1.3 大厅主页重排（含好友卡片入口）
- 左区：联机对战大卡（放大）、离线演练卡。
- 右区三卡：ProfileCard（用户名显示为 **用户名#编码**；旧缓存无编码时保持纯用户名兼容）→ **FriendsCard**（好友数·在线数 + 最多 3 行好友名与状态色 + 「打开好友页」）→ LoadoutCard。

## 2. 好友系统（新功能）

### 契约与模型
- **查找**：`用户名#4位编码` 双约束（名字大小写不敏感精确 + 编码精确 4 位含前导零）。编码注册时随机生成（`Random.Shared.Next(0,10000).ToString("D4")`），不可修改；用户名全局唯一 ⇒ 组合唯一，编码本身不要求全局唯一。
- **关系**：`FriendRequest`（一方一行，唯一索引 (From,To)）+ `Friendship`（对称两行，复合主键）。请求-同意制；accept=删申请+建双向行（单次 SaveChanges 原子）；拒绝/撤销共用删除；删除好友删双向两行。
- **在线状态**（优先级从高到低）：房间 InMatch=「对局中」→ 房间 Waiting/Starting/Returning=「房间中」→ `LastSeenUtc` 120s 内=「在线」→ 否则「离线」。
- **在场信号**：`GET /api/friends` 与 `POST /api/rooms/heartbeat` 均节流（30s）刷新本人 `LastSeenUtc`（单条原子 UPDATE）。Unity 侧壳页在场循环：导航可见时每 30s 拉一次好友列表（兼作心跳+主页好友卡缓存），等待房间由房间心跳承担。

### 后端（fps-backend）
- 实体：`UserAccount.IdentityTag/LastSeenUtc`、`FriendRequest`、`Friendship`；AppDbContext 配置+唯一索引。
- 手写迁移 `20260920000000_AddFriendsAndIdentityTag`（`[DbContext]+[Migration]` 成对标注）+ **AppDbContextModelSnapshot 已同步**；存量账号 `LPAD(FLOOR(RAND()*10000),4,'0')` 回填。
  - **踩坑修复**：CreateTable 的 `MySql:ValueGenerationStrategy` 注解值必须是**枚举**（`Microsoft.EntityFrameworkCore.Metadata.MySqlValueGenerationStrategy.IdentityColumn`），写成字符串 `"IdentityColumn"` 会让 Pomelo 生成 SQL 时抛 `ArgumentException`（Enum.ToObject 失败），后端启动即炸——首轮启动已实测炸出并修复。
- `FriendsService` + `FriendsController`（`/api/friends`）：GET 列表（friends/incoming/outgoing）、POST requests（发申请）、POST requests/{id}/accept、DELETE requests/{id}（拒/撤）、DELETE {friendUserId}；错误码 FRIEND_QUERY_INVALID/FRIEND_NOT_FOUND/FRIEND_SELF/FRIEND_ALREADY_FRIENDS/FRIEND_REQUEST_EXISTS/FRIEND_REQUEST_NOT_FOUND。
- `PlayerProfileDto` += IdentityTag（`Mapping.ToDto` 签名改收 `UserAccount`，4 个调用点同步）。

### Unity（客户端）
- 契约：`PlayerProfileDto.identityTag` + FriendEntryDto/FriendRequestEntryDto/FriendListDto/FriendSendRequest（小驼峰对齐后端）。
- `IApiClient/ApiClient`：GetFriendsAsync / SendFriendRequestAsync / AcceptFriendRequestAsync / RemoveFriendRequestAsync / RemoveFriendAsync。
- `LobbyPage.Friends` + 保护页/导航可见性不变量 + 新 `Pages/LobbyPresenter.Friends.cs`（搜索卡/收件箱/发件箱/好友列表，5s 轮询，操作后立即刷新）。
- 主页 FriendsCard 消费 `cachedFriends`（在场循环缓存，摘要变化才重渲染主页）。
