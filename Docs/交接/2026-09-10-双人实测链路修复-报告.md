## 2. 远端玩家互相看不到（审计 §2，确定缺陷）

根因（确定）：主相机 cullingMask 是进程级按层位判定；全项目玩家身体/TP 武器共用 LocalPlayerBody(8)，本地主相机剔除层 8 → 远端实例同样被剔除。`PlayerNetworkAdapter.OnStartClient` 远端分支的旧注释（"层 8 对其相机可见"）与本缺陷相互矛盾，已改。

修改（`PlayerNetworkAdapter.cs`）：

- 新增 `ApplyRemoteVisualLayers()` 每实例分层不变量：Owner 保持 TP_Model 整树 LocalPlayerBody（自隐藏防挡镜）；远端实例整树改到玩家根层（Default）→ 主相机与实体镜 RT 相机（其剔除表只减 FirstPersonView/LocalPlayerBody）均可见。
- `OnStartClient` 两个分支末尾统一调用；新增 `OnOwnershipClient` 覆盖 → 接管/池化复用（Owner 得失）恢复正确层；曾被打到根层的节点在 Owner 侧恢复 LocalPlayerBody，其余节点不动。
- 跳过 `BodyHitbox`：hitbox 恒在玩家根层（武器 hitMask 依赖），不随视觉递归变化——未触碰移动碰撞体与命中掩码。
- 后续换枪/配件实例无需补丁：`TPWeaponMeshSwapper` 拷贝 weaponBone 当前层，自动跟随本分层。

未做粗暴修复：未把主相机层 8 打开、未改 prefab/场景。

## 3. 贴身碰撞抖动（审计 §3，机制确定/占比待实机）

修改：

- `PlayerNetworkAdapter.EnsureBodyHitbox`：BodyHitbox 置 `isTrigger = true`。原先它与根 CharacterController 胶囊几乎重合，是"额外刚性阻挡源"，双胶囊双重解算即审计指出的确定性冲突机制。
- `CombatResolver.ResolveGeometry`：`QueryTriggerInteraction.Ignore → Collide`。已核实全场景/预制体无其他 trigger（仅 FishNet/FinalIK demo 场景有），Collide 不会误吸环境触发体；激光指示器（LaserSightBeam 走全局 queriesHitTriggers=1）语义不变；两段权威命中（R10）共用 ResolveGeometry，自动生效。
- `Locomotor` 新增 `ApplySmoothCorrection(Vector3)`：与 `ApplyAuthoritativeSnapshot` 同一写入模式（CC 短暂禁用后直写 Transform）；`PlayerNetworkAdapter` 的平滑收敛从裸 `transform.position += step` 切入该统一入口。未用 CC.Move 承载校正步：亚厘米位移会被皮肤宽度吞掉导致校正永久滞留。

玩家间阻挡策略（明确报告，未暗改玩法）：**玩家间仍互相阻挡，唯一移动阻挡 = 玩家根 CharacterController 胶囊，客户端预测与服务器权威使用同一阻挡来源**；BodyHitbox 只承担射线受击判定。墙/地面碰撞与有效受击检测全部保留，未关任何 Collider、未改层碰撞矩阵、未增大 SNAP 阈值。

尚待实机确认：贴身抖动的实际占比需修复后实机评估；远端 CC 胶囊按插值位置阻挡（滞后 2-8 tick），双方高速贴身对冲时仍可能有小幅平滑收敛——属该架构下的固有量，若实机仍不可接受，后续票据再议"模拟根/视觉根职责分离"重构。

## 4. 等待房间全体消息对方收不到（审计 §4，确定契约错误）

- `AccountContracts.cs`：`RoomChatMessageDto.senderUserId` `long → long?`（后端 `Features/Contracts.cs` 本就是 `long?`；ApiClient 实际用 Newtonsoft，不可空 long 遇 null 炸整批 feed——旧注释"JsonUtility 归 0"与现实不符，已改）。
- `ChatController.cs`：
  - 两处映射 `dto.senderUserId ?? 0L`（系统消息无发送者=正常语义；展示层 `ChatHudView.Format` 对空 username 已显示"系统"，未伪造账号 ID，未删系统消息）。
  - `FetchHttpAsync` 失败不再全静默：节流 15s 的 `Debug.LogWarning`（房间/游标/状态码/错误码/消息，不含 token）；`CHAT_CURSOR_INVALID`（后端重启 seq 清零）一次性把会话游标复位重拉——游标状态本就持久在 `ChatRoomSession`（房间作用域），复位仅作用于当前房间，身份隔离成立。
  - 旧房间响应隔离：Fetch/Send 在 await 后校验 `ChatRoomSession.IsRoom(roomCode)`，迟到响应不写入已切换的新会话。
  - `Update()` 不再因 `GameplayInputGate.MenuOpen` 整体 return——菜单只让出聊天输入焦点（视图侧既有逻辑），HTTP 拉取照常推进，战斗菜单跨场景残留状态不再无限阻断等待房间拉取。
