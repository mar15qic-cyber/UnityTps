## 1. 初衷与设计取舍（给审计者的"为什么"）

1. **要解决的问题**：用户实机看到"准心没压在敌人模型上仍然掉血，并且空气里有血花/弹孔"。
   前两轮修的是**规则**（移动阻挡体不再参与受击、角色命中不再贴墙面弹孔）；本轮修的是**几何**——
   受击代理本身就不在可见身体上。两者是不同缺陷，缺一不可，这也是排查报告 §3.3 的结论。
2. **为什么只改中心、不改半径**：方案 §6.2 明确要求本轮最低交付是"经模型实测校准、与有效站立轮廓匹配的受击代理，
   校准参数显式保存"，并禁止凭画面盲缩半径。横向轮廓（持枪姿态、T-pose 包围盒失真）必须靠四向实机扫描定，
   我没有那个授权 → 所以半径保持原值，并在代码注释与本文里都写明它是**待标定项**，而不是假装它已最优。
3. **为什么不引入复合受击体（头/躯干/肢体）**：方案 §6.2 把"复合代理"列为**独立决策项**（牵动服务器姿态求值、
   回溯快照/还原、一次伤害多碰撞体、死亡启停）。单胶囊标定后仍有可测量误差，但把复合代理悄悄做进来会越出本轮授权范围。
4. **为什么不改 prefab**：`TP_Model` 的 `z=0.341` 是作者偏移，属 LPW/LPFP 资产链与玩家 prefab（工作区里还是脏文件）。
   受击体本来就是运行时创建（`EnsureBodyHitbox`），所以标定放在**运行时装配 + 显式序列化参数**，零资产改动、可回退。
5. **为什么参数是 `[SerializeField]`**：让后续实机标定轮次能在 Inspector 里直接微调并保存，不需要再动代码；
   同时代码里的默认值就是本轮实测值，可审计、可 diff。

**测量边界（必须知道，否则会误用）**：编辑器态下 `SkinnedMeshRenderer.bounds` 反映的是**当前姿态 = 绑定姿态（T-pose）**

- **z（前后）与 y（高低）** 受 T-pose 影响很小 → 用于标定中心与纵向契约，可靠；
- **x（左右）半宽 0.672m 是"双臂平举"的产物**，不代表站立持枪轮廓 → **本轮没有用它去改半径**，
  半径 0.35 维持原值并标注为四向实机待标定项。

## 8. 复核指引（给 Codex）

重点核对项：
1. **标定值的来源是否成立**：`bodyHitboxCenter.z = 0.333` 来自角色 SkinnedMeshRenderer 世界包围盒中心换算到玩家根空间。
   复现（只读）：Arena 场景里选中 `Player`，读取 `TP_Model` 下 `third_person_character` 的 `renderer.bounds.center`，
   用 `playerRoot.InverseTransformPoint(center)` 看 z。与 prefab 作者偏移 `0.341` 应吻合（差 ~8mm）。
2. **T-pose 陷阱**：确认我没有用 x 半宽 0.672 去改半径（本轮半径未动）。若你认为 0.35 也偏大，
   那是 §6.1 四向扫描的结论项，不是本轮该拍的板。
3. **坐标系**：`center` 表达在 hitbox/TP_Model 朝向系 → 模型旋转时受击体跟身体。核对
   `Hitbox_Offset_FollowsModelRotation_AndStillOnBody` 是否真的锁住了这条。
4. **Day4 P0-1 未被推翻**：纵向"半身高只算一次、下端=脚底、上端=头顶"三条断言仍在（用例 ③⑤）。
5. **DS/Host 一致性**：受击体是 TP_Model 子节点；DS 的 `PinTpModelToRootForServer` 把 TP_Model 钉回 `根 ∘ 作者基准`，
   因此服务器与客户端的标定胶囊一致。Host 分支不钉根，但同样跟随模型节点 → 需要实机双端各验一次。
6. **仍未闭合的验收面**：四向轮廓扫描、连续站桩复活、DS 与 Host 双覆盖、症状一的重建复测。
