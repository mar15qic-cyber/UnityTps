## 结论

F1–F3 已完成代码级修复与直接受影响的后端回归。后端状态、会话写入守卫和首次出生入口均已按复审要求收紧；Unity Editor/FishNet 真实连接与首包姿态尚未在本轮实机验证，不能将其写为 PASS。

## F1：ack / 真实断线 / 重臂分离

- `RoomMatchRoster.ReturnedAtUtc` 仅记录客户端返房 ack；`LeftAtUtc` 仅由 DS 断线事实（或明确从未消费票据的无连接收口）写入。
- 全员 ack 不再把房间提前切到 Waiting；Returning 超时对已消费会话保持 Returning，实例保持 Draining。
- 全员真实连接退场后房间才归档到 Waiting；实例继续 Draining。disconnect 的 Ready/0 只作为 DS 重臂许可，数据库只有收到 DS Ready+0 心跳后才回池。
- 绑定 Returning 时的 Ready+0 心跳被后端拒绝；从未消费票据的名单在超时/真实退场汇总时安全收口，避免永远等待不存在的 disconnect。
- DS tracker 在释放许可后等待 MatchLifecycle 的统一安全门（Idle、无资格旧对象、无 AcceptedUsers、无延迟移除）才允许发送 Ready 心跳；周期/即时心跳不能抢先清绑定。

## F2：首个出生姿态

- `TeamFirstSpawnDirector` 不再订阅 `PlayerSpawner.OnSpawned` 后改 Transform。
- 项目侧接管 `SceneManager.OnClientLoadedStartScenes`：按队伍槽位先选 position/rotation，再调用 `GetPooledInstantiated` 与 `ServerManager.Spawn`；初始 Spawn 序列化读取的就是队伍位置。
- 未修改 FishNet 原厂。原 PlayerSpawner 的私有回调仍订阅着事件，但其 prefab 被公开 setter 置空以阻止双生成；组件禁用时恢复原 prefab。由于原厂回调会看到空 prefab，真实 DS 日志可能出现原生“prefab empty”警告，需实机确认是否可接受。
- `TeamFirstSpawnDirector.PlanTeamSpawn` 与 EditMode 用例锁定“先生成队伍姿态计划、再把该姿态交给 spawn action”；新增 `Assets/link.xml` 保留 `FishNet.Runtime` 的 `PlayerSpawner` 类型，降低 Release/Managed Stripping 下私有反射字段消失风险。

## F3：生产返房 ack 身份守卫

- `MatchReturnSequence` 增加只返回 ack 数据的生产 seam，快照只有在捕获 roomCode + ConnectionGeneration 仍有效时才应用。
- `MatchSettlementFlow` 的生产 `AckReturn` 不再在 HTTP await 委托内写 `AccountSession`；应用前后均有同步身份复核，`Changed` 回调重入导致会话接管时也不会断开新连接。
