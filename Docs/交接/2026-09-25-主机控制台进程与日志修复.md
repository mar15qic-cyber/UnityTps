# 主机控制台进程与日志修复

当前完整 02 发布目录中的 maps-manifest.json 存在。控制台在 API 失败时重复展示旧 console.log.error，使历史路径错误看起来仍在发生。实际现场为 API 离线、六个 DS 仍占端口，而 processes.json 保存另一轮启动的已退出 PID；两轮启动日志时间仅相隔两秒。

## 修改

- 每次操作使用带时间戳和 GUID 的独立日志；显示操作名、时间、运行状态及退出码，不读取上一会话错误充当当前错误。
- 异步状态报告独立于 API 健康：目录、清单存在性、配置/运行版本、TCP/UDP 端口、PID、程序路径、托管归属、退出记录及未被记录管理的发布进程。
- 新增刷新进程/端口、打开本次日志、服务日志目录、恢复遗留进程记录按钮。
- 去掉旧界面根据 API 请求失败反复自动开服的逻辑；开关服加入跨进程互斥，进程记录采用原子替换。
- 恢复记录要求唯一候选，核对完整可执行路径、实例 ID、端口、地图、发布版本、后端/组网地址及本状态目录下确实存在的日志；备份旧记录，不结束进程。发现歧义不写入。
- 关服先 DS 后 API，逐项报告停止结果，验证退出并检查端口残留；已退出但句柄短暂存在不再视为活进程。
- 修复 Windows PowerShell 5.1 将 File.Replace 的 null 备份路径绑定为空字符串的问题，使用 NullString.Value。

## 实际验证

恢复现场六个 DS 的管理记录，恢复 API。随后通过正常关服流程停止全部托管 DS 与 API，返回 configured ports are free；再次开服返回 PRIVATE_HOST_READY。没有修改玩家账号、地图资源或客户端包。

Windows PowerShell 下私有工具、关服范围回归、云脚本测试通过；HostConsole -ValidateUi 创建 12 个控件成功，未进行截图布局验收。状态工具实际输出 API 离线时仍可见端口及遗留 PID。

用户需关闭旧版控制台窗口后重新双击根目录“开始邀请测试.cmd”，才能载入新界面。关闭控制台窗口本身不等于关服，需使用关服按钮。客户端继续使用 02 版。
