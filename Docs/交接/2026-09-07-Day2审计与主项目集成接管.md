## 1. 双方必须遵守的统一状态契约

### 1.1 房间与实例权威

- 后端数据库是房间绑定和实例状态的唯一权威。
- 合法主链：`Ready -> Reserved -> InMatch`；释放后回到 `Ready`。
- Unity Dedicated Server 不得仅因本地玩家数为零就自行宣称 `Ready`。
- `TryEnterMatch()` 只允许在比赛真实进入 `InProgress` 且本地已经持有非空权威 `roomCode` 时执行。

### 1.2 Ended 到下一局的租约代际

旧局结束后，Unity 只有获得以下任一权威证据才可重臂 `Ended -> Idle`：

1. register ack 明确返回 `Ready`/`Offline`，并使 tracker 清除旧 `roomCode`；或
2. 新票据 consume 返回与旧局 `endedRoomCode` 不同的非空 `roomCode`，明确证明进入了新租约代际。

单独收到 `Reserved` 或 `InMatch` 的 register ack **不能**证明旧房已经释放，因为当前 `ServerInstanceRegisterResponse` 不携带 `roomCode`。不得把“任意注册成功”直接等价为 `BackendReadyForNextMatch=true`。

重臂还必须同时满足：旧局有效玩家为零、`AcceptedUsers` 为空、延迟离场已收口。复位必须清理 Phase、输入冻结、matchId、Ended 幂等闸、离开闸、命中登记、中继宿主、计时与旧比分来源。

### 1.3 重连与房主身份

- 同一用户重新加入同一房间只补发新票据，不删除/重建成员行。
- 必须保留 `HostUserId`、`HostUsername`、原 `JoinedAtUtc`、成员数与管理员身份。
- 加入其他房间时才执行“一人一房”清理。
- 旧连接迟到的 disconnect report 不得删除已重连的新会话成员。

### 1.4 联网成绩资格

- 正式比赛玩家资格统一为：NetworkObject 已生成、Owner 有效、连接已认证。
- authored/server-owned/未认证对象可以保留受击、死亡和重生表现，但不得增加正式 kills/deaths、不得广播正式 Kill、不得触发 20 杀终局或进入结算载荷。
