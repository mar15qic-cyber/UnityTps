## 2. 总体架构评价

**做得好的（应保持，也是简历/面试素材）**：
1. 自研移动预测对账体系（MovementPredictionCore.cs，770 行纯逻辑）：TickAccumulator 有限追帧（max 5 步）、PredictionBuffer 128 tick 输入+预测快照环形缓冲、ServerInputQueue 每玩家独立队列（乱序/重复/失控 tick/冻结/旧代际五类拒收计数）、Reconciler 位置双阈值（0.03m 平滑 / 0.75m 硬校正）+ 速度/朝向/落地分支软分叉滞回闸 + SmoothCorrectionLedger 在途量台账。纯逻辑与 MonoBehaviour 分离，可离线测试——这是全库架构质量最高的部分。
2. 延迟补偿（ServerLagCompensation.cs）：200ms 窗口、按 tick 快照循环复用零稳态分配、两遍回溯（先全量保存再统一回写，避免父子污染）、射手排除、快照携带生命代际与出生保护、越窗裁剪策略（LagCompensationPolicy 纯函数）。
3. 开火权威闭环：Owner 本地预测成功才上行（FirePressed/FireHeld 按模式区分，PlayerNetworkAdapter.cs:878-880，F19 已修）→ ServerFireRequest 死亡闸 + shotRequestId 64 位环形重放去重 + 廉价准入预检（避免无谓回溯）→ TryFire 权威结算 → ObserversShot 全量表现载荷 + TargetShotConfirmed/Rejected 定向闭环，拒绝时携带权威弹药快照回写（RejectShot → ApplyAuthoritativeAmmoSnapshot）。
4. 一次性入场 Ticket（后端）：SHA-256 存储、90s TTL、ConsumedAtUtc 消费标记 + Version 乐观并发 + Serializable 事务，防重放成立。
5. 确定性努力：F13 确定性后坐种子（weaponId+ownerClientId+生命代际同源键）、F14 输入生命代际（协议 v6）、F01 击杀归因下沉到伤害结算点。注释里保留了完整的决策与残余风险记录（如 ApplyDeterministicRecoilSeed 自认"接受发次分叉时 stream 仍会错位"）。

**核心问题一句话**：文档承诺的架构（三层单向依赖、编译期强制、单写者）与实际代码（FishNet 进 Gameplay、反射桥向上、静态跨端状态）已经分叉，且分叉是系统性的、有注释辩护的（"反射惯例"），但没有任何文档正式修订过 Docs/02 的铁律——**架构契约失去了唯一事实源**。
