# 私有 HTTP 热更启动修复

## 原因与改动

用户截图的“热更新未就绪: error”对应 Player.log 的 `Insecure connection not allowed`。Unity 正式客户端构建时 PlayerSettings.insecureHttpOption 为 NotAllowed，UnityWebRequest 在发出 HTTP 请求前就拒绝连接，并非资源未打包。

InvitationClientBuild 在已校验的 private-overlay 构建期间设置 AlwaysAllowed，公网邀请构建显式设置 NotAllowed，并在 finally 恢复编辑器原值。应用层继续校验私有服务地址和热更发布身份。保留自行注册策略。

## 验证

- 完整 DS、客户端与地图 Bundle 构建成功。
- Test-PrivateHttpPlayer.ps1 实际启动未封存修复客户端（后台、不登录、不入房），临时使用当前运行主机的 releaseId 进行资源下载；退出后恢复原配置字节，仅结束测试自身启动的进程。
- 日志：`Logs/PrivateHttpSmoke-7eac3e1944984ba097ddbab3bdfe8aa8.log`。
- 实测 `[HotUpdate] kind=applied version=7 downloaded=4`，证实构建后的 UnityWebRequest 已能下载并安装 HTTP 热更，不仅是 PowerShell 健康检查通过。
- 此测试针对当时运行的旧主机资源，不代表新配套服务已部署或多人验收通过。

## 后续 release-mismatch 修复与实际切换

随后用户再次遇到 release-mismatch。确认两个主机脚本缺陷：停止判断包含了其他历史测试实例的忙碌记录；Windows PowerShell 5.1 的 ConvertFrom-Json 数组在 @() 中未展开，使进程身份检查接收到数组整体，出现“停止成功”却未停止进程的情况。

已将关服判断限定到当前主机记录中的 DS 实例（自身过期但忙碌记录仍阻止关服），并在各进程状态读取位置显式枚举 JSON 数组。Windows PowerShell 回归覆盖数组展开、忽略其他历史实例以及保护自身过期忙碌实例，全部通过。

本次在确认托管实例空闲后，实际停止旧私有测试进程并启动 02；未停止其他进程或清空数据库。API /api/test-status 返回 private-selfregister-20260924-02、ready=true；热更清单返回同一 releaseId、内容版本 12。真实测试客户端日志为 `[HotUpdate] kind=applied version=12 downloaded=2`，证据 `Logs/PrivateHttpSmoke-07e19236fc0141c9a097240a3010e9a9.log`。用户可以直接重试 02 客户端，不需重新下载包。
