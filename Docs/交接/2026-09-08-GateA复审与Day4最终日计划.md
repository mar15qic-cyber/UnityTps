### 2.2 Day4 开头必须修复的两项

#### [P1] P30 的 Catalog 预览仍引用旧 fileID

`Day3_Handgun04.asset` 已改为 wrapper 根 `fileID: 6574827882670645563`，但 `WeaponAssetCatalog.asset` 的 `weapon.handgun04.previewPrefab` 仍为旧 `fileID: 6573219461991808529`。现有 `P30Handgun04AssetTests` 只通过 `TryResolveDefinition` 检查 Definition，**没有断言 `entry.previewPrefab` 本身**，因此报告所说“定义与目录均指向同一 wrapper”并未被测试证明。

编辑器下 `FindPreviewPrefab` 还能凭 `previewPrefabPath` 用 AssetDatabase 降级加载，Player Build 中该路径不是合法 Resources key，P30 商城/仓库 3D 预览可能为空。修复：用 Unity SerializedObject 把 Catalog 条目的 `previewPrefab` 重写为同一 wrapper 根，并扩充测试直接断言 `entry.previewPrefab != null`、AssetDatabase 路径一致；保存、重新导入后再测。

#### [P1] “新会话不被旧退出事务清除”只保护了一半

`LeaveTransactionCoordinator` 在房间引用改变时跳过 `ClearRoom`，但仍无条件调用 `complete()`；生产 `CompleteLeaveTransaction` 随后无条件停止所有连接、清 `NetworkLaunchContext` 并导航 Lobby。若退出等待期间新会话/重连代际替换了旧会话，新的 Room 虽保住，连接和启动上下文仍会被旧事务销毁。

修复：给退出事务绑定房间码/会话 generation；只有代际仍匹配时才能执行 Room 清理、StopConnection、NetworkLaunchContext.Clear 与导航。代际已变化时旧事务标记 superseded 并结束，不得触碰新连接。测试不能只断言 `ClearRoomCalls=0`，还要断言 `Complete/Stop/ClearLaunch/Navigate=0`。

### 2.3 Day4 正式回归必须收掉的玩家可见缺口

Unity 全量仍有 4 项失败，其中不能全部视为“无关基线”：

- `weapon.handgun03/smg03/smg04/smg05/sniper03` 均在后端正式商品种子和 Resources Catalog 中，可购买、可装备，但其 Definition 的 TP prefab 引用实际为 null。多人中使用这些枪时远端无枪，是玩家可见问题。五个 TP prefab/meta 已在磁盘，应参照 P30 方法修正 Definition 与 Catalog 的根 local fileID，并扩成参数化资产测试。
- `LobbySubPageTests.Catalog_RendersOwnedAndLockedCards` 的夹具仍使用无 Definition 引用的 `CreateRuntime()`，与当前 `IsLpfpWeaponItem` 契约不一致；应改夹具使用可解析 LPFP Definition，确认真实商城卡片逻辑，而不是删断言。
- `LPWProductionAssetTests` 的 39 条固定计数已经落后于当前 45 条目录；主线测试应按 LPFP/LPW 来源分别断言，不再依赖脆弱总数。
- `FPWeaponAdsFireRoutingTests` 属 LPW 历史范围；只允许把断言作用域收紧到正式 LPFP，不允许为让测试变绿而修改 LPW 资产或正式 ADS 路由。

目标是 Day4 结束时 Unity 主线门禁 0 失败；不得通过 Ignore 或删除断言“绿化”。
