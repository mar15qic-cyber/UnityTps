1. **本轮视频跑的是旧构建，不含前两轮的 P1/P2/P3 修复**（构建产物 06:37/06:38，源码改动 18:08–21:10）。

2. **症状一（AK 玩家开枪/换弹动画停播、弹药仍在掉）**：根因是旧构建里"停用 Animancer 组件即 `Graph.Stop + Animator.Rebind + PauseGraph`，

   已排除：AK 缺动画、`WeaponController` 订阅失效、Animator 留在停用态。
3. **症状二（不打在模型上仍掉血 + 浮空血花/弹孔）**：除旧构建的两条已修规则外，还存在一个**前两轮都未处理的独立缺陷**——
   受击胶囊按"逻辑根"对齐，而可见 TP 模型被作者偏移了 `z=0.341m`，再叠加 `radius=0.35m`（比肩宽胖）
   → **身体后方约 0.49m 的空气可被打中，胸口最前段反而打不中**。这不是延迟补偿造成的（证据见 §3.3）。
4. 修这个几何问题必须改动一条既有契约：`BodyHitboxAlignmentTests` 4 例**刻意**断言"胶囊世界中心 = 根 + (0,0.9,0)"。
   即"对齐逻辑根、不对齐可见模型"是 Day4 P0-1 的有意决定，不是遗漏。

## 2. 症状一：TP 开火/换弹动画停播（弹药仍消耗）

### 2.1 根因链（旧构建代码可证）
1. 死亡 → `NetworkCombatAuthority.ApplyDeathVisual` 停用 TP 子树内的姿态写者（含 `AnimancerComponent`）。
2. `Player_Day2_Rebuilt.prefab:1299` 的 `_ActionOnDisable: 3` = `DisableAction.Reset` →
   包内 `AnimancerComponent.OnDisable` 执行 `_Graph.Stop(); _Animator.Rebind(); _Graph.PauseGraph();`。
3. 复活 → `ResetDeathVisual` 只把 `enabled` 还原 → `AnimancerComponent.OnEnable` 的**全部**行为是
   `if (IsGraphInitialized) _Graph.UnpauseGraph();`（本轮已核对包源码）——图被 Stop 过、里面没有状态，解冻也放不出动画。
4. `TPAnimDriver.Update` 旧实现只在 `SourceLocomotionState != _currentState` 时 `ApplyState`，缓存值仍是 Idle → Layer0 永不重播。
5. 开火/换弹走 Layer1 `Play()`，但图处于 Stop+Rebind 后果 → 视觉上看不到动作；
   而弹药消耗发生在 `WeaponController`/服务器侧，与 Animator 无关 → 用户看到的"**左键仍在掉弹、动作不播**"。

### 2.2 已排除的替代解释（逐条查证）
| 假设 | 结论 | 证据 |
|---|---|---|
| AK 的 TP 动作/移动 clip 没配 | **排除** | 46 个武器定义（含 `lpw.rifle.01..06`）逐个解析：`thirdPersonLocomotion` 20 个引用、`thirdPersonActions` 3 个引用，无一为空 |
| `WeaponController` 随切枪/复活重建导致订阅失效 | **排除** | `NetworkCombatAuthority:27 _controller = GetComponent<WeaponController>()`（挂在玩家根）；运行时被 `Instantiate` 的只有 TP 枪模视图（`TPWeaponMeshSwapper:76`），控制器本体不重建 |
| 复活后 Animator 仍被禁用 | **排除** | 三客户端 `[RespawnTrace]` 采样：`animEnabled=True` 110/120、113/124、88/96 |
| 远端根本没有开火动画链路 | **排除** | `NetworkWeaponState:286` → `WeaponController.InvokeRemoteFireForPresentation()` → `OnShotFired?.Invoke(default)` → `TPAnimDriver.HandleShot`，远端 TP 动作层有通路 |

### 2.3 一个必须点名的假指标
`[RespawnTrace]` 的 `animEnabled` 读的是 `animator.enabled`（`PlayerNetworkAdapter:1661`）。
**它为 True 不能证明图里有状态在播**——正是方案 §7 结尾警告的"验收不能只检查 `rootY` 或 `Animator.enabled`"。
本轮日志因此只能证伪"Animator 没恢复"，不能证明动画正常。真实判据应是 Layer0/Layer1 的在播状态与权重
（工作区里已把它做成 `TPAnimDriver.LocomotionPlaying`，并要求图初始化 + 层权重>0 + 当前状态 `IsPlaying`）。

### 2.4 定案条件
工作区 P1 改动（暂停图冻结 + 复活显式重播 + `Evaluate(0f)` + `OnEnable` 强制重播）针对的正是 §2.1 全链，
且已有 EditMode 真实 Animancer 图回归（`TpAnimDriverRespawnTests` 5 例，含一条 legacy 停用路径的反例锚点）。
**但视频里没有这段代码** → 症状一必须"重建客户端 + 重建 DS 后复录"才能定案；在那之前不得声称已解决。

## 3. 症状二：不打在模型上仍掉血，且浮空血花/弹孔

### 3.1 几何事实（本轮实测/实读，非推测）
| 量 | 值 | 来源 |
|---|---|---|
| `TP_Model` 作者局部位置 | `(0, 0, 0.341)` | `Player_Day2_Rebuilt.prefab:1192/1196/1200` |
| `TP_Model` 作者局部旋转 | identity（`w=1`，xyz=0） | 同 prefab `:1204-1216` |
| 受击体落位规则 | `hitboxTransform.localPosition = model.InverseTransformPoint(transform.position)` → 受击体世界位置 **= 玩家逻辑根** | `PlayerNetworkAdapter.EnsureBodyHitbox` 末行 |
| 胶囊参数 | `center=(0,0.9,0)`、`radius=0.35`、`height=1.8`、轴向 Y | 同方法 |
| 佐证 | 死亡日志 `grounded=(0.00, 0.00, 0.34)` 即保存的 TP_Model 局部位置 | DS/客户端 `[DeathVisual]` |

推导（沿模型前向轴，单位米，原点在逻辑根）：
- 胶囊占据 `-0.35 … +0.35`；可见身体中心在 `+0.341`，躯干半厚按 ~0.2 估 → 身体占据约 `+0.14 … +0.54`。
- **身体背后 `-0.35 … +0.14` 这段约 0.49m 的空气属于"可被命中"区**；
- **胸口最前面 `+0.35 … +0.54` 反而不在胶囊内**（打在最前面可能不掉血）。
- 另外 `radius=0.35`（直径 0.7m）大于士兵肩宽（约 0.5m）→ 侧向擦边也命中。
- 编辑器截图所见"绿色圆柱与 TP 模型不切合、模型在后方"与上述符号一致。

### 3.2 旧构建里叠加放大该症状的两条规则（工作区已修，构建里没有）
1. 命中玩家根 `CharacterController` 外壳时，`CombatResolver.ResolveDescendantTarget` 会"在该对象子树里猜一个 `DamageableTarget`"
   并沿用 CC 命中点 → 模型外空处掉血 + 落点在空气里。
2. `WeaponView.SpawnImpact` 按 `Damaged ? damagedImpactPrefab : impactPrefab` 选特效 →
   命中角色但零伤害（出生无敌/友军/已死）时把**墙面弹孔**贴到玩家身上 → 用户描述的"浮空弹孔"。

### 3.3 延迟补偿不是本症状的原因（两条独立证据）
1. **时序**：`EnsureBodyHitbox()` 在 `OnStartNetwork`（`PlayerNetworkAdapter:195`），
   回溯注册在 `OnStartServer`（`:425 lagComp.RegisterPlayer(transform, GetComponentsInChildren<Collider>(true), …)`）。
   FishNet 顺序下 `BodyHitbox` **已经**在回溯/还原集合内，不存在"hitbox 没被回溯、CC 被回溯"的错位。
2. **DS 钉根**：`PinTpModelToRootForServer` 把 TP_Model 写回 `根 ∘ 作者基准`，
   因此服务器上的胶囊与客户端看到的胶囊几何**完全一致** → 服务器权威判定与本地预测特效会"一致地错"，
   这正解释了用户同时看到"血花 + 真实掉血"，而不是"有特效无伤害"。

结论：症状二的主因是**受击体几何与可见模型不切合**（§3.1），旧构建的两条规则（§3.2）只是叠加放大。
前两轮修复解决的是 §3.2，**没有动 §3.1**——方案 §6.1/§6.2 的几何标定一项当时明确列为"未验/未做"。

### 3.4 与既有契约的冲突（改它必须连带改测试）
`Assets/_Project/Tests/EditMode/BodyHitboxAlignmentTests.cs`（Day4 残余审计 P0-1）4 例**刻意**断言
"胶囊世界中心 = 根 + (0, 0.9, 0)"、"下端 = 脚底、上端 = 头顶"，并覆盖模型非零位置/旋转/缩放与重入场景。
即"受击体对齐逻辑根"是有意决定（当时的动机是修"腿/下躯干漏判"，把双重 0.9 偏移纠正掉）。
本轮要改为"对齐可见模型"，必须同时更新这 4 例的断言与理由，不能悄悄改几何而留一组过期绿灯。
