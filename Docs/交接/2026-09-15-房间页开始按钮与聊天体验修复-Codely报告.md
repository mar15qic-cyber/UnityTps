## 1. 根因与修复（逐条）

### ① 房主看不到"开始比赛"按钮 —— 按名字查找命中不到按钮

- **根因**：`UIComponents.Button` 返回的是按钮 **Face 子对象**，其外层容器由构建器命名为 `Btn_N`；
  `SetActionButtonVisible("Btn_StartMatch", …)` 用 `actionPanel.Find("Btn_StartMatch")` 只查**直接子级**，
  而 `Btn_StartMatch` 被挂在 `Btn_3`（容器）之下 → `Find` 恒为 null → 按钮永远不被激活。
  实机层级实证：`path=Btn_StartMatch/Btn_3/ActionPanel/WaitingRoomPage/…`（直查到 `ActionPanel/Btn_StartMatch` = False）。
  即：**房主从来点不到开始按钮**（此前会话用反射直调 `OnWaitingStartClicked` 进战，掩盖了该缺陷）。
- **修复**：`LobbyPresenter.WaitingRoom` 改为**直接引用** `waitingStartButton`（不再按名字 Find），
  删除已失效的 `SetActionButtonVisible`。
- **实机复验**：`startButtonRef=True active=True host=True status=Waiting` ✓

### ② 本机发送消息出现两条 —— 当前源码未复现；去重链路已带诊断

- **实测**：连发 3 条（HI/AB/CD）→ `sessionMessages=3`（1:1，无重复）；日志显示去重**正确工作**：
  ```
  [Chat] 入列 transport=H seq=1 ... HI      ← 发送响应（首次登记）
  [Chat] 去重过滤 key=id:abd531… HI          ← 2s 轮询把同一条又拉回来 → 被去重过滤
  ```
  （Send 响应与 Fetch 的 `seq`/`clientMessageId` 同源，键为 `id:{cid}` + `H:{seq}`，两种到达顺序都会命中。）
- **判断**：用户所见疑为**旧构建**（会话级去重 `ChatRoomSession` 是 R9 之后的实现）或"输入行不可见导致连按两次 Enter"（见 ④）。
- **本次加固**：`ChatRoomSession.TryRegister` 改为**原子判定**（先全量查重再登记，避免命中后残留前置键），
  并新增去重诊断日志（`[Chat] 入列` / `[Chat] 去重过滤`）——若再复现，玩家日志可直接判定是服务端重复投递还是客户端重复显示。
- **待用户复测**：用重建后的客户端再试；若仍出现两条，请提供该客户端 `Player.log` 中的 `[Chat]` 行。

### ③ 聊天窗口与系统消息重叠 —— 底部提示与最新消息行同带

- **根因**：收起态提示 `ENTER 聊天 · SHIFT+ENTER 队伍频道` 与"最新一条消息行"占用同一底层带
  （实测：hint `y4..32` ∩ ChatRow2 `y4..25`），提示文字压住最新消息（用户看到的"系统消息挡住聊天消息"）。
  另外房间页卡片（成员/操作面板）底边 y=0.16 与聊天 HUD 带（画布 y 0–0.34）重叠。
- **修复**：
  1. `ChatHudView.UpdateHintVisibility()`：只要有可见消息行就隐藏提示（无消息时才显示操作提示）。
  2. 等待房间页 `TeamsPanel`/`ActionPanel` 底边 0.16 → **0.36**，为聊天 HUD 让出整条底带。
- **实机复验**：`hintActive=False rowsWithText=[HI][AB][CD] (overlapFound=False)` ✓（行/提示/页面文本两两无重叠）

### ④ 无输入法候选窗 + 无光标竖杠 —— 两个独立根因

- **④-A 光标（含输入行文字）不可见**：聊天输入框的 Text/Placeholder 误用了**锚点版** `Stretch(rect, Vector2, Vector2)`，
  把像素内边距 `(6,4)/(-6,-4)` 当成锚点 → `anchorMin=(6,4) > anchorMax=(-6,-4)` → rect 退化为负宽。
  TMP 的插入符 rect 是**复制文本 rect** 得到的（`AssignPositioningIfNeeded`），因此插入符也被判成退化矩形
  （实测 `caretRect=[x2417..-2286,y139..2]`，完全在可见区外）——这正是"看不到竖杠、像盲打"的原因。
- **修复**：聊天输入框按 TMP 标准构造重建：
  `Input`（禁用 GO 延迟 Awake）→ `Viewport(RectMask2D)` + `Inset(6,4)` 像素内边距 → Text/Placeholder 铺满视口 →
  赋值 `textComponent`/`placeholder`/`textViewport` → 启用 GO；删除误用的锚点重载（改为 `Inset` 专用助手）。
- **实机复验**：`caret=[x69..454,y73..85]` ⊂ `input=[x65..457,y70..88]`（caretInsideInput=True），`textViewport=True` ✓

- **④-B 输入法候选窗/拼音预览全程不可见**：项目 **Active Input Handling = "Input System Package (New)"**
  （`ProjectSettings.activeInputHandler = 1`）。该模式下 Unity **不处理 Windows IME 消息**：
  `Input.compositionString` 恒为空（实测 `len=0`，且不抛异常所以此前无人察觉）、`Input.imeCompositionMode` 设置无效、
  候选窗不出现；而 TMP_InputField 的 IME 预览正是读 `compositionString`（新版 Input System 1.19 无 IME 组合支持）。
- **修复**：`ProjectSettings.asset` → `activeInputHandler: 2`（**Both**）。项目自身输入代码全部走新 Input System（`Keyboard.current` 等）不受影响；
  `LobbyPresenter.EnsureInputSystemEventSystem()` 已内置"销毁遗留 StandaloneInputModule"，不存在新旧模块双份处理风险。
- **生效范围**：**构建产物已生效**（本次已重建客户端）；**编辑器需重启**该设置才在 Play Mode 生效（未擅自重启用户的编辑器）。
- **实机复验限制**：候选窗需人工用中文输入法在真实窗口验证 → **待用户实机确认**；代码侧证据：模式已切换 + 光标/文本 rect 已修好。
