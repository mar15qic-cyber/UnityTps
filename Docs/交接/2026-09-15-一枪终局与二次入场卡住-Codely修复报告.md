# 一枪终局与二次入场卡住：Codely 修复交付报告

日期：2026-09-15。执行依据：`Docs/交接/2026-09-15-一枪终局与二次入场卡住-审计及Codely修复方案.md`（P0-A/P0-B/P1 全量实施）。主工作区脏区直接改，未提交（遵循"不默认 git commit"）。

## 0. 结论

审计定位的两条问题链全部落地修复并经**真实三进程实机验证**：

1. **旧 DS 进程 + 新客户端协议不匹配 → 蓝方被未知 PacketId 踢 → PlayerLeft 判红方胜**：以「应用协议代际」三层防线收口——认证前协议门（零成本拒绝旧客户端）+ 后端按房间协议筛选实例（旧 DS 对新房间不可见）+ 启动器部署门（活跃旧进程不再被当成新构建已部署）。
2. **第二次加载 Arena 时 NetworkHud.Start 永不运行（DestroyNewest 销毁新实例）→ 启动上下文无人消费 → 停在加载画面**：客户端启动入口整体迁出 NetworkHud.Start，改由常驻 `ClientMatchSessionCoordinator`（自建 DontDestroyOnLoad 宿主，不受 FishNet 持久化逻辑影响）在「Arena 场景就绪」时按**递增代际**消费票据并连接；每局连接前显式复位全部跨局残留状态；分段状态机 + 分段超时兜底（失败弹原因并自动返回等待房间页）。

实机验证中另抓出并修复两个**实施期新缺陷**（详见 §3）：
- 整体预算超时误伤 Playing 阶段（不修则任何对局 75s 必被协调器掐断）；
- SceneReady 阶段收到的上一局连接 Stopped 事件会把刚开启的新会话误判为已收场。

## 2. 协议兼容语义（三层防线）

```
第 1 层【部署门】启动器：旧进程 ≠ 已部署（APP_PROTOCOL 行 + 进程启动时间双验证）→ 旧 DS 根本不该出现在池里
第 2 层【后端筛选】房间冻结建房者协议 → 租用查询硬过滤 → 旧 DS 对新房间不可见（NO_SERVER_AVAILABLE 归因 protocol-mismatch）
第 3 层【认证前握手】JoinTicketBroadcast.ProtocolId → 新 DS 对旧客户端 PROTOCOL_MISMATCH 零成本拒绝（票据零消耗）→ 覆盖层显示"版本不匹配"并回大厅
```

旧版缺字段行为的实证依据（FishNet 源码 + 本轮实机）：
- 可靠通道所有包带长度帧（`Utility.GetPacketLength`），但广播处理 `InvokeHandlers` 按 struct 生成读取器**不做剩余字节对齐**——新客户端向旧 DS 发追加字段广播会在认证阶段即产生流错位（fail fast），不会把协议差异带进对局；
- 旧客户端（空 ProtocolId）→ 新 DS：协议门拒（本层为最终执法）；
- 未修改 FishNet 对未知 PacketId 的踢除逻辑（保留安全语义）。

## 7. 遗留观察（非阻断，供后续票据）

1. **MATCH_RESULT_CONFLICT（局 1 超时断线路径）**：客户端被预算掐断（修复前）后房间已被成员过期清理，DS 终局上报被后端 409——既有"代际证据"设计语义（契约已注明该限制），非本轮引入；预算豁免修复后该路径不应再自然出现。
2. **编辑器驱动生产退出的正确姿势**：必须走完整状态链 `PauseMenu→RequestLeave(LeaveConfirm)→RunLeaveTransaction`——直接调 RunLeaveTransaction 会被 `BeginLeaveTransaction` 的 LeaveConfirm 状态校验**静默**拒绝（产品语义正确，但自动化驱动需按链驱动；后端联测脚本注意）。
3. **启动器前台跑 ALL_OK 后的输出静默**：run_shell 前台执行会在成功后因无新输出被 5 分钟超时截断（截断不杀 DS 子进程）；编排脚本用 `Start-Process`+WaitForExit 方式无碍。
4. 池诊断 `reserved=65 inMatch=5` 为历史死行（只租 fresh Ready，不影响租用）；F-4"死房钉 InMatch"仍待专项票据（本轮验证 DS 重臂链路正常，未见复发）。
5. 旧客户端（无 clientProtocolId 字段的二进制）配新后端：join 409 PROTOCOL_MISMATCH 生效（后端测试锁定），但旧客户端 UI 只能显示原始错误码（无友好文案）——升级指引文案归旧客户端退出，不回填。

## 8. 后续协议纪律（给所有会话）

改以下任一项，必须递增 `GameProtocolIdentity.ProtocolId`（v2→v3…）并同批重建双端：
1. 任何 ServerRpc/ObserversRpc/TargetRpc 的参数或频道；
2. 任何 IBroadcast struct 字段增删/换序（追加必须在最后）；
3. 任何 NetworkBehaviour SyncVar 增删。

构建清单由 ClientBuild/DedicatedServerBuild 自动写入产物目录；启动器据此执法——**活跃旧进程不再可能被当成新构建**。
