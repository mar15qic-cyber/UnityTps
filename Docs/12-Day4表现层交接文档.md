## 2. 当前相机链路（Day4 后）

```text
InputReader（新增 AimHeld = 右键按住）
    ↓
Locomotor → Player 根节点 Yaw（不变）
FPMouseLook → CameraPivot 本地 Pitch（组件从 Main Camera 移到 CameraPivot，仍是 Pitch 唯一写者）
    ↓
CameraPivot（Follow 目标，y=1.62）
    └─ CM_FP_Camera（CinemachineCamera）
        ├─ Body: CinemachineHardLockToTarget（Damping=0，位置=头位）
        ├─ Aim:  CinemachineRotateWithFollowTarget（Damping=0，朝向=Yaw×Pitch）
        ├─ CmFPCameraSway / CmFPCameraBob / CmFPCameraBreathing / CmFPCameraRecoil（自定义扩展）
        └─ Lens: FOV 60 / Near 0.01 / Far 300（Brain 会写回 Main Camera）
    ↓
Main Camera（CinemachineBrain；自身 Transform 由 Brain 驱动，不再被业务脚本写入）
    ├─ FP_Weapon_Root（layer 9，FPWeaponMotion 唯一写者）
    └─ FP View Camera（URP overlay，只渲 layer 9，FOV 45 固定）
```

要点：

- 相机位置从「Pivot 后退 0.33m」改为「头位硬锁定」；viewmodel 是 Main Camera 子节点且由 overlay 相机渲染，屏幕构图不变，只影响世界视野向前 0.33m（更符合 FPS 眼位）。
- FPMouseLook 加 `[DefaultExecutionOrder(-20)]`，保证其 LateUpdate 早于 CinemachineBrain（默认 0）写 Pitch，不吃帧延迟。
- 自定义扩展全部走 `CinemachineExtension.PostPipelineStageCallback`（Aim 阶段），只写 `PositionCorrection` / `OrientationCorrection`（修正通道），不碰 Raw 通道，互相乘法/加法叠加、单帧可复位（deltaTime<0 时清内部状态）。
- ADS 的 FOV 由 `FPCameraRig` 写 `CinemachineCamera.Lens.FieldOfView`（60 → `WeaponStat.AdsFov`，Day2 平衡表已有逐武器值 45~50）；FP View Camera 保持 45°，viewmodel 不随变焦拉伸。

## 3. ADS 设计

- 状态源唯一：`FPCameraRig`（挂 CameraPivot，Update 里由 `InputReader.AimHeld` + `ActionSystem.IsBusy` 推导 `AdsBlend` 0→1，0.16s 过渡）。换弹/切枪时自动松镜。
- 相机侧：FOV 插值（世界相机）；sway/bob 幅度按 `AdsBlend` 收敛（各扩展 `adsDamping`）。
- 武器侧：`FPWeaponMotion`（挂 FP_Weapon_Root，本地姿态唯一写者）在换枪时**自动推导程序化瞄准姿态**——把激活视图 `WeaponView.Muzzle` 平移到 FP View Camera 视口中心线（抵消 muzzle 在 viewCam 本地空间的 x/y）。10 把枪零配置即可「枪口对准屏幕中心」，如需逐武器精调（照门对齐）后续在 WeaponDefinition 加覆盖字段。
- 准星：ADS 混合 > 0.5 时 WeaponView 的 OnGUI 程序准星隐藏。
- 输入：`InputReader.AimHeld`（右键按住）。ADS 是纯表现，不改 Gameplay 数值（spread 收敛等留给后续数值层）。

## 4. 武器 viewmodel 动效（FPWeaponMotion）

全部只写 FP_Weapon_Root 本地位置/旋转，与动画（Animator/Animancer 驱动视图骨骼）正交叠加：

- **Sway**：鼠标增量反向滞后（SmoothDamp），位置 ±0.01m / 旋转 ≤3.5°。
- **Bob**：直接复用 `PlayerStateView.GaitPhase`（Locomotor 确定性步态相位），与相机 Bob 同频同相，杜绝双频跳变；速度权重 = HorizontalSpeed/3.44，Walk/Sprint 才生效。
- **Breathing**：仅 Idle 的慢速正弦（0.28Hz）。
- **Recoil**：订阅 `WeaponController.OnShotFired`，欠阻尼弹簧（上抬 4° + 后坐 0.045m，f=11Hz ζ=0.6，带回弹）。
- ADS 期间所有动效按 `adsMotionDamping=0.85` 收敛。

## 7. 用户实机验收建议

1. 腰射开火：枪口闪光/弹壳抛射/弹道 tracer/枪口灯同时出现；打墙有火花+弹孔粒子+音效，打靶（Target）出血液反馈与 hitmarker。
2. 右键 ADS：世界视野平滑缩放到该枪 AdsFov；武器平移到枪口对准屏幕中心；准星消失；sway/bob 明显收敛；松开回腰射。
3. 换弹/切枪时 ADS 自动松镜。
4. 静止有轻微呼吸起伏；Walk/Sprint 时相机与武器同步起伏（同频）；跳跃/空中无 bob。
5. 快速甩鼠标准星有轻微反向滞后（sway），停止后回中。
6. 开火有镜头上抬 + 随机水平偏移并回弹；连发手感叠加合理。
7. 俯仰无「慢一拍」感（FPMouseLook 执行顺序验证）。
8. 切枪（0-9）后各枪 ADS 姿态自动重算。

## 8. 已知边界与后续

## 9. Day4.1 问题修复轮（2026-08-26）

用户实机验收后报告 4 个问题，先审计后修复（全程未进 Play Mode，prefab 修改走 `PrefabUtility.LoadPrefabContents` 安全路径，无卡死）。

### 9.1 手臂紫色（URP）——已修复

- 根因：项目存在两个同名 "Arms Material"——`Components/Materials/Arm_Materials/`（URP）与 `Components/Meshes/Arms/Materials/`（Standard）。Day3 迁移只给 3 个视图（ServicePistol/Handgun/Rifle）做了 URP override，其余 8 个视图的手臂 SMR 仍引用 Standard 版。
- 修复：8 个 prefab 的 arms SMR 材质统一指向 URP 版（与 3 个好视图一致）。验证：11/11 视图全 URP。

### 9.2 FP 枪带配件 vs TP 裸配——已修复（按用户拍板）

- 根因：FP 视图是模块化手臂 prefab，scope_01~04 / silencer / knife 全部默认 active 且叠在同一导轨位；TP 武器 prefab 是裸模（仅狙击枪带 scope/bipod）。
- 修复：11 个视图关闭 `scope_*` 与 `silencer`；保留 `rails`（Rifle 导轨）、`big_bullet/bullet/shellcasing_full`（换弹动画道具）、`knife`（原厂态，见 9.3）、Sniper02 的 `biped_legs/muzzle_brake`（TP 有）。已知遗留：FP Sniper01/02 无独立 scope 网格（TP 有 scope）——资产本身不含，如需一致要在 TP 侧去掉 scope 或换资产。

### 9.3 knife「悬浮」——审计结论：与原厂逐字节一致，未修改

- 审计证据链：knife 骨骼挂载（Armature 子级、localPos/rot）、SMR mesh（同 GUID）、bindposes、bones 数组引用路径、idle clip 曲线（`Armature/knife` 存在）、AnimationMode 采样后骨骼姿态——全部与 LPFP 原厂 prefab 一致。
- 原厂对照：原厂 FPSController 有两个相机（Gun Camera fov40 / Main Camera fov55），knife 在两者视野外；我们的 FP View Camera（fov45，偏移 -0.047/0.082/-0.358）下 knife 位于相机身后（z=+0.08m）——**Game 画面里 knife 不可见**，原厂同样不可见。
- 用户感知的「悬浮」来自 Scene 视图（自由视角能看到贴在 FP arms rig 左下的刀，且编辑态 view 未实例化、Play 后旧视图 SetActive(false) 保持末姿态）。这是 viewmodel rig 的固有形态，原厂 prefab 在 Scene 视图同样悬浮。
- 决定：保留 knife active（用户「可以不关」）；如仍想去掉 Scene 视图悬浮感，一行 SetActive(false) 即可，待用户指示。

### 9.4 Animancer DisableAction.Reset 断言——已修复

- 根因：Codex 为修「退出 Play 后陷地」把 TP_Model 的 AnimancerComponent `_ActionOnDisable` 改为 `Reset`（3），但 Reset 模式官方要求 **AnimancerComponent 必须排在 Animator 之上**；原顺序 [1]Animator [2]AnimancerComponent → disable 时 Animator 先失活 → `Debug.Assert(_Animator.isActiveAndEnabled)` 失败。
- 修复：Player prefab（`Player_Day2_Rebuilt.prefab`）TP_Model 组件顺序调整为 [1]AnimancerComponent [2]Animator；场景实例已同步继承。保留 Reset 语义 + `PlayerPoseRecoveryEditor` 双保险——编辑态 Scene 视图不再陷地/非 T-pose，断言不再触发。
- 附注：FP 视图 prefab（11 个）的 AnimancerComponent 均为 Stop 模式且顺序无此问题，未动。

### 9.5 射线从相机中心发出——已定方案 C，下一轮实施

- 现状链路：`WeaponController.TryFire` 用 `aimCamera.ViewportPointToRay(0.5,0.5)` 判定命中（眼睛射线），`WeaponView` tracer 从枪口画到命中点（视觉从枪口）。腰射时 viewmodel 枪口轴与相机轴不平行。
- 用户已拍板 **方案 C**：判定射线保持相机中心（所见即所得，Day8 服务器权威射线天然兼容）；表现层把 viewmodel 枪口朝向对齐相机 forward（满足「枪口方向与准心一致」的观感）。ADS 时 `FPWeaponMotion` 已对齐，腰射待做——下一轮在 `FPWeaponMotion` 中加腰射枪口朝向对齐（仅旋转 viewmodel 根或 FP_Weapon_Root 的视觉朝向，不参与判定）。

### 9.6 TP 动画复用审计结论（用户追加问题）

**LPFP 资产包只提供两族 TP 动画，无逐枪动画——当前配置正确，非 bug：**

| 动画族 | clip 来源（third_person_character_lpfp） | 使用武器 |
|---|---|---|
| handgun 族 | `*_tpc@...@handgun`（idle/walk×8/run×8/jump×3/fire/reload×2） | ServicePistol、Handgun02 |
| rifle 族 | `*_tpc@...@rifle`（同上全套） | AssaultRifle、Rifle02、Rifle03、Shotgun01、SMG01、SMG02、Sniper01、Sniper02 |

即：所有手枪共用 handgun 族、所有长枪（含霰弹/冲锋/狙击）共用 rifle 族。这是 LPFP 原厂设计（TP 角色只有两个武器姿态族）；FP 动画则是逐枪的（每枪自己的 arms fbx clip 集）。若要 TP 逐枪差异化需外购/自制动画，属资产扩展非配置修复。

## 11. Day4.3 实机反馈修复轮（2026-08-26 第三轮）

用户实测 Day4.2 后报告两问题：TP 瞄准 pitch 方向反了；火光/tracer 仍从画面中心出。

### 11.1 TP 瞄准方向反转 — 已修复（实测探针定论）

- 根因：`TPAimDriver.ApplyAim` 用 `AngleAxis(+pitch, root.right)` 叠加。Unity 约定**绕角色右轴正角=低头**（与 FPMouseLook「抬头为负欧拉 X」一致），而 pitch 以抬头为正 → 方向相反。
- 证据链：AnimationMode 探针实测（采样 idle 后对 head 骨施加 +30° 绕 root.right：head.forward.y 从 -0.210 降到 -0.671，即正角=低头）；yaw 方向经推导无误（权重默认 0 未启用）。
- 修复：delta 中 pitch 取负（`AngleAxis(-pitch * share, right)`），已编译通过。

### 11.2 火光/tracer「从中心出」— 已修复（Muzzle 精确贴合枪口尖端）

**根因复盘（比 Day4.2 认知更深一层）：**
1. FP 枪体网格是**蒙皮网格**（绑定到 weapon/slider/lid_2 骨骼）。Day4.2 的「挂到骨骼 + bindpose 数学」方向正确，但 LPFP 的 bindpose 与 prefab 序列化骨骼位姿不一致（美术摆好持枪姿势后保存 prefab，bindpose 仍是 FBX 导入值）——bindpose 推算的挂点落在枪身中后部，不是枪口尖端。
2. 编辑态 `SkinnedMeshRenderer.bounds` 返回序列化值、蒙皮公式手算因 bindpose 不一致失真、Transform.position 在 PlayableGraph 求值后存在世界矩阵假读数——三个常规手段全部不可靠，改用**渲染级验证**。

**最终方案（渲染掩膜反投影）：**
- 复刻游戏渲染链（view 实例 idle 采样 via PlayableGraph + FP View Camera 参数），枪体换红色 Unlit 材质、黑底渲染 960×540；
- 脚本内像素扫描枪体掩膜，取「质心→屏幕中心」方向的极值像素 = 枪口尖端；
- 反投影（沿用旧 Muzzle 深度）得尖端世界坐标 → 换算父骨骼局部坐标 → 写入 prefab。

**结果：11/11 把枪 Muzzle 像素级贴合枪口尖端（Δ=0px、在掩膜内）**，且挂在骨骼上随开火/换弹动画刚体跟随。手枪族挂 slider 骨（枪口端在套筒上）、狙击挂 lid_2 骨（枪口罩盖）、其余挂 weapon 骨。抛壳口统一接 `weapon/slider` 骨骼（真实抛壳位）。

### 11.3 附带发现（备忘）

- LPFP FP 手臂 rig 是「FBX 休息位=持枪姿势」设计：idle clip 只微调 weapon 骨，arm 骨不被动画驱动。
- rig 内置 `camera` 骨（(0, 0.086, -0.179)，即 FP View Camera 偏移的来源）；Unity 相机看向 +Z（本组排查中曾误用 -Z 惯例导致一轮误判）。
- 编辑态离线评估动画位姿的可靠手段：PlayableGraph.Evaluate（与 Animancer 运行时逐位一致）> AnimationMode（等价）> 手读蒙皮（bindpose 不一致时失真）。

### 11.4 修改清单（Day4.3）

- `TPAimDriver.cs`：pitch 符号修复（1 行 + 注释）。
- `FP_*_View.prefab` ×11：Muzzle localPosition/Rotation 精修到枪口尖端（修正量 8~44cm）；shellPort 引用 weapon/slider 骨。
- 验证：编译 0 错误；控制台无异常；11/11 渲染掩膜验证 Δ=0px。

### 12.5 Day4.5 膛线方向修正（火光向上喷的补丁，仅 FP_Rifle_View）
